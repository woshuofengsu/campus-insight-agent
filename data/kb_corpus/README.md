# `data/kb_corpus/` —— 社区治理公开政策语料库

本目录存放「社区先知 CommunityInsight」政策问答模块（`data/db_policy.py` + `agent/rag.py`）的
**真实公开政策语料**，用于替换/扩充早期的演示 seed 数据，提升居民口语提问的检索召回与回答可信度。

| 文件 | 说明 |
|---|---|
| `policies.jsonl` | 语料本体，一行一个 JSON（UTF-8，无 BOM），当前 **40 条**；`category` **全部为知识库 5 个合法分类之一**，另用 `topic` 保留 10 个主题标签 |
| `README.md` | 本文件：来源、收录原则、字段说明、合规声明、更新方式 |

导入脚本：`scripts/import_kb_corpus.py`（幂等，走项目既有审核流程，详见「如何更新」）。

## 二、收录原则（诚实优先，宁少勿假）

1. **只收录真实公开发布的文件**：政策名称、发布机关、文号必须能在官方来源中核实；核实不到的政策一律不收录。
2. **绝不编造**：不编造政策名称、文号、金额、比例、日期、URL。搜索/公开报道中查不到确切数字时，
   只写准确的概括性描述（例如「按对象类别确定并适时调整」），不填想当然的数字。
3. **标注来源类型**：每条 `source_type` 标注来源性质。本批全部为 `政策摘要`，
   即**依据官方发布文件与官方解读整理的摘要**，不是文件原文的照搬；正文末尾统一提示「以官方发布原文为准」。
4. **媒体口径单独标注**：少数由权威媒体报道承载的数字（如市场租房补贴分档与最高额度、
   养老助餐点数量、生育假天数变化）在正文中明确写出「据公开报道／媒体报道」，不与官方条文混同。
5. **区分法规与摘要的日期**（见「字段说明」），不使用转发页日期冒充发文日期以外的口径。
6. **不含个人信息与内部材料**：语料只包含公开发布的政策内容，不含任何居民个人信息、工单数据、
   内部会议材料、未公开的政府内部文件或联系人隐私。
7. **面向检索优化**：`keywords` 收录居民常用口语说法与同义词（如「老楼装电梯／加装电梯／老楼安电梯」、
   「高龄补贴／老人补贴」、「低保／吃低保」），以提升口语提问的召回率（见第五节实测）。

### 分类：`category` 只取知识库的 5 个合法值

`data/db_policy.py` 的 `POLICY_CATEGORIES`（第 34 行）与 `validate_knowledge_fields()` 只接受：

```python
POLICY_CATEGORIES = ["社保医保", "养老服务", "住房保障", "办事指引", "社区规定"]
```

写其它任何值，`create_knowledge()` 都会返回「请选择正确的分类」。因此本语料**每条 `category` 都直接写为
上述 5 类之一**（不是主题标签）；更细的主题归类另用可选字段 `topic` 保留，只用于人读与后续按主题扩语料，
不入库、不影响写库校验。导入脚本会同时校验两者（`db_category()`：`category` 合法则直接用，
旧格式的 `db_category` 与 `topic` 映射表仅作兜底）。

**本批 40 条的 `category` 分布（全部合法）：**

| category（入库值） | 条数 | 对应 topic 主题标签 |
|---|---|---|
| 社保医保 | 13 | 医疗保障 3、社会救助 3、生育与妇幼 3、就业社保 2、住房保障（住房公积金提取 2） |

归类口径（与项目既有习惯一致）：加装电梯／老旧小区改造／公租房／保障房／物业／维修资金 → `住房保障`；

12345 接诉即办、街道办事处、各类申请与办事流程指引 → `办事指引`。

### `effective_date` 口径（重要）

kb 表字段名为 `effective_date`，且 `_is_effective()` 用它做时效过滤（晚于今天则不进入检索）。本语料统一约定：

- **法规、规章、条例、办法、通知等有明确施行/发布日期的**：填该文件的**施行日期**（如
  《北京市接诉即办工作条例》= 2021-09-24，《北京市生活垃圾管理条例》垃圾分类新规 = 2020-05-01）。
- **摘要型/办事指南型条目**（依赖官方办事指南页或问答页，页面本身无施行日期）：填**官方来源页面的
  公开发布日期**，并在入库正文的「日期说明」行中明确标注该口径，避免被误读为发文日期。

为消除歧义，**40 条中有 21 条带可选字段 `date_note`**，逐条写明该日期的确切依据，例如：

- 《北京市公共租赁住房申请、审核及配租管理办法（摘要）》：`2019-05-22 为首都之窗政策法规页面的公开发布日期；文件为京建法〔2011〕25号，原发文日期以官方原文为准。`
- 《跨省异地就医直接结算工作的通知》：`2024-06-19 为市医保局政务公开栏目重新发布该文件的页面日期；原文件为京医保发〔2022〕41号（2022年印发），实际发文日期以官方原文为准。`
- 《困难残疾人生活补贴和重度残疾人护理补贴制度实施办法》：`2021-01-22 为海淀区人民政府网站公开该市级文件的页面日期；原文件为京民福发〔2016〕434号（2016年印发）。`

其余 19 条 `effective_date` 取的是法规/办法/通知本身的施行或印发日期（如《接诉即办工作条例》2021-09-24、
《生活垃圾管理条例》垃圾分类新规 2020-05-01、《失业保险金申领发放实施办法（试行）》2025-01-01），
入库时按通用口径说明。

## 四、与知识库的对应关系（导入实现说明）

- `knowledge_base` 表**没有** `source_url` 列，且 `create_knowledge()` 签名不含该参数。因此来源链接写入：
  - `attachment` 列 —— 居民端政策问答页会渲染为「📄 查看政策原文」按钮，可直接跳官方原文；
  - `content` 正文的「—— 来源信息 ——」块（含发布机关、文号、适用范围、日期说明、来源链接、来源类型），
    便于人工核验与全文检索。
- `publisher` 列由 `create_knowledge()` 固定写为操作人（其签名无 publisher 参数），
  因此**真实发布机关写在 `source` 列与正文来源信息块**中，`publisher` 列显示为导入操作人
  （`政策语料导入`）。这是既有业务代码的约束，语料侧未做任何代码改动。
- 导入后走项目审核流程置为 `已发布`：`create_knowledge`（草稿）→ `submit_review`（待审核，审核人
  `政策语料审核员`）→ `audit_knowledge(approve=True)`（已发布，自动留存版本快照）。
  全流程走既有函数，吃到字段校验、来源规则校验与 `log_activity` 留痕（每条 3 条留痕）。

## 六、合规声明

- 本目录只收录**公开发布**的政府政策文件及其官方解读所整理出的摘要，不含涉密信息、内部材料、
  未公开数据与任何个人信息。
- 所有条目均**标注来源机关与官方链接**，保留可追溯性；转载、引用时请同时保留 `source_url`。
- 摘要与通俗解读为便于居民理解而作的**整理与转述**，不构成法律意见；
  **具体办事以官方发布原文和经办部门口径为准**（正文中已逐条提示）。
- 如官方文件更新、废止或修订，请按第七节流程更新或下架对应条目（`take_down_knowledge` 可留痕下架）。

## 七、如何更新语料

1. 按第三节字段格式，向 `policies.jsonl` **追加**新的 JSON 行（一行一个，UTF-8）；标题 ≤50 字，
   `keywords` 3-5 个，`effective_date` 满足 `YYYY-MM-DD`，`source_url` 必须是真实可访问的官方链接。
2. 校验（不写库）：

   ```bash
   python scripts/import_kb_corpus.py --dry-run
   ```

3. 正式导入（幂等：按 `title` + `source_url` 去重，已存在则跳过）：

   ```bash
   python scripts/import_kb_corpus.py            # 全量，跳过已存在
   python scripts/import_kb_corpus.py --limit 5  # 只导入前 5 条
   python scripts/import_kb_corpus.py --update   # 已存在条目内容有变化时更新
   ```

   `--update` 行为：草稿/审核不通过 → 直接 `update_knowledge` 更新后重新发布；
   已发布 → `create_new_version` 建新版本草稿，新版本审核通过后自动下架旧版本（保留版本血缘）。
4. 测试请使用**临时库**，切勿对生产库 `data/community_insight.db` 做写入测试：

   ```bash
   python scripts/import_kb_corpus.py --db %TEMP%\kb_test.db
   ```
