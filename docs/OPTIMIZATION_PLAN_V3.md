# 社区先知 — Agent 内核重构方案（V3，真正的 Agent）

> 核心判断：当前系统是**"规则外壳 + LLM 替补"的伪 Agent**——意图路由看关键词表、规划是提示词建议、校验是正则、多 Agent 是函数聚合。
> V3 的目标：把认知决策权**整体交还给模型**，规则只做护栏（保底、安全、成本），让 Agent 真正做到**会理解、会规划、会反思、会记住、会主动**。
> 支撑项（CI/部署/产品/数据）沿用 V2，本方案聚焦 Agent 内核。

---

## 0. 现状诊断：为什么它是"伪 Agent"

| 维度 | 现状 | 病根 |
|---|---|---|
| 意图理解 | 关键词表优先，LLM 只替补 | **决策权在规则** |
| 任务编排 | 提示词写死组合模式 | **规划是文本不是执行** |
| 反思 | 正则提 `#id` + DB 查重 | **不校验语义与数值** |
| 记忆 | event_memory 只记不读 | **记忆没有反哺决策** |
| 主动 | 感知/派单是孤立函数 | **没有协作回路** |

一句话：**你的 LLM 在"念规则写的剧本"，不是在"演自己的角色"。**

---

## 1. 目标：一个"真 Agent"长什么样

### 1.1 竞争力（评委能感知）
- 一个**没写进任何规则的新说法**，Agent 能自己判断该调哪个工具、怎么调、怎么说。
- 一个**会编造数字**的幻觉，Agent 能自己发现并纠正（不是靠正则补刀）。
- 一次**复合任务**（"看看设施类积压 + 查相关提案 + 给我建议"），Agent 能自己规划步骤并执行。
- **思考过程可见**：答辩时把 Agent 的"想→调→验→改"链路展示出来。

### 1.2 聪明（能力本体）
- **意图理解**：语义理解，不是关键词。
- **工具自主**：自己决定调什么、按什么顺序、要不要追问澄清。
- **自我反思**：对工具结果做事实核查，错了重试/换路径。
- **跨会话记忆**：记得"你上次报过电梯"，主动回访。
- **主动行动**：不等用户问，观察到异常主动处置（派单/提醒/上报）。

### 1.3 实用（真实价值）
- 对居民：一句话办成一件事，闭环真的转。
- 对网格员：被派单、被升级、被提醒，不靠肉眼盯。
- 对老人：语音一句话上报 + 安全闭环，交互不断裂。

## 2. 核心架构：认知内核（取代规则外壳）

```
                ┌─────────────────────────────────────────┐
                │              Agent 认知内核              │
                │                                         │
 用户输入 ────► │  ①理解层   ②执行层    ③反思层           │
                │  LLM 意图  LLM 自主选  LLM 事实核查     │
                │  +语义路由  工具+编排    +质量自评        │
                │        ▼      ▼      ▼                  │
                │  ④记忆层（事件+画像）→ 反哺①③            │
                │  ⑤主动层（观察/派单/提醒）→ 触发②③        │
                │                                         │
                │  ⑥护栏：三层回退 + 关键词兜底（只兜底）    │
                └─────────────────────────────────────────┘
                    结果经 ⑦演示闭环（机器人）→ 居民/网格员
```

### 分层职责
| 层 | 负责 | 由谁决策 |
|---|---|---|
| ①理解层 | 意图、工具建议、是否需要追问、情绪 | **LLM**（关键词只做快路径/兜底） |
| ②执行层 | 调哪些工具、顺序、组合 | **LLM**（AgentExecutor 强化） |
| ③反思层 | 结果对不对、要不要修正/重试 | **LLM**（一次核查调用） |
| ④记忆层 | 跨会话事件/画像注入 | 规则存储 + LLM 消费 |
| ⑤主动层 | 观察→处置→提醒回路 | 规则触发 + LLM 解读 |
| ⑥护栏 | LLM 挂了/超时/不确定时保底 | 规则（不可协商） |
| ⑦闭环 | 演示模式自动"办" | 规则 + 开关 |

## 3. 各层文件级改造

### 3.1 ①理解层：`agent/router.py` 重写为 `agent/understanding.py`
- **LLM 优先**：一次调用，输出结构化 JSON：
  ```json
  {"intent": "report_issue", "tool": "report_issue", "confidence": 0.92,
   "needs_clarification": false, "suggested_question": ""}
  ```
- **快路径**：高置信关键词（"社区脉搏"）直接命中，跳过 LLM（省一次调用）。
- **兜底**：LLM 不可用/超时 → 关键词表（现有 `_TOOL_KEYWORDS` 降级为兜底）。
- **澄清机制**：低置信时 Agent 主动追问 1 个问题，而不是瞎猜。
- 删除 `prompt.py` 里的**穷举触发词映射表**，改为简短"工具使用原则"（让 LLM 靠 tool schema 判断）。

### 3.2 ②执行层：`agent/engine.py` AgentExecutor 强化
- **工具 schema 重写**（`tools/*.py` 的 docstring）：每个工具 description 写明「何时用/何时不用/常见说法/返回什么」，这是 LLM 自主选工具的"说明书"，质量决定智能。
- **动态工具集**：按角色裁剪（见 §5），减少无关工具的干扰。
- **ReAct 强化**：保留 `AgentExecutor`（LLM 自主 multi-step），`max_iterations` 提到 8（现有 6），支持多工具编排。
- **追问回合**：Agent 需要澄清时，先回复追问，收到回答再执行（现有 enforce 已有一轮，扩展为通用澄清）。

### 3.3 ③反思层：`agent/verifier.py` 升级为 `agent/reflection.py`
- **LLM 核查一次**：对草稿回复输出 `{"facts_ok": true/false, "hallucinated": [...], "quality": 0-100, "revision": "修正文本"}`。
- **核查内容**：编号存在性（保留正则兜底）+ **数值核对**（"解决率95%" vs 实际）+ **语义一致性**（回复是否匹配工具结果）。
- `enforce_tool_call` 保留为**护栏**（LLM 完全没调工具时强制），不再是唯一防线。

### 3.4 ④记忆层：`data/db_memory.py` + `agent/memory.py`
- `get_event_summary` 增强：按事件类型分组（上报/评价/用药/附议），注入系统提示词。
- **画像反哺**：老年用户 → 主动关怀话术；重复报修某类 → 主动提议升级提案。
- 新增 `memory recall`：Agent 可以"想起"上次对话结论（存 `event_memory` 的 `summary`）。

### 3.5 ⑤主动层：`agent/workers.py` 升级为协作回路
- **Observer**（感知）→ 事件写入 `perception_log` → **Dispatcher**（派单）→ `auto_dispatch` → **Auditor**（复核）→ 结论写入 `activity_log`。
- 主对话 Agent 在 `_orient` 时**读取最近事件**（`perception_log`/`activity_log`），主动引用："系统注意到 X 类问题本周上升，已自动派单"。
- 独居老人安全链（打卡/SOS/关怀）并入主动层，统一为"系统主动行为"。

### 3.6 ⑥护栏（不可协商，保留）
- 三层回退：`CommunityAgent → OfflineAgent → graceful_fallback` 不变。
- 关键词兜底（understanding 层）、`enforce_tool_call`（执行层）、正则查 id（反思层）全部降为**护栏**，不再抢主决策。

## 4. 竞争力证据（答辩可用）

### 4.1 评测 v2：`agent/eval/eval_suite.py` 升级
- **泛化场景集**：30+ 场景，其中 15 个**关键词表外**的新说法（只靠 LLM）。
- **模式**：`--mode llm`（有 key 跑真实 LLM 路由）/ `--mode offline`（关键词兜底）。
- **指标分列**：`关键词命中率 / LLM 泛化命中率 / 工具正确调用率 / 幻觉检出率 / 任务完成率 / 平均步骤`。
- 报告存 `agent/eval/report.md`，答辩直接引用"未见过表述的语义命中率 X%"。

### 4.2 思考链路可视化
- 现有 `_last_thinking` 升级为**决策卡片**（`ui/thinking.py`）：展示"理解→选择工具→结果→反思"四步，评委现场可看。
- 老年/居民界面默认折叠，评委可展开。

### 4.3 主动行为演示
- 一条"主动闭环"demo 脚本：上报一条问题 → 观察 Agent 自动派单 → 网格员端收到 → 处理 → 居民收到通知。全程可重放。

## 5. 角色化工具裁剪（让 LLM 更聪明）

| 角色 | 可用工具（裁剪后） | 理由 |
|---|---|---|
| 居民 | 全量（16 个） | 完整治理能力 |
| 网格员 | 查询/更新/提案/通知类（只读+管理，去掉上报/附议） | 工作台导向 |
| **老年** | `report_issue` / `query_my_issues` / `get_weather` / `get_community_pulse`（4 个） | 极简，LLM 不被无关工具干扰 |
| 离线 | 关键词兜底链（现有） | 保底 |

- 实现：`agent/engine.py` 构造 Agent 时按角色过滤 `tools/__init__.py` 的注册表。
- **收益**：老年角色 LLM 的选工具准确率会明显高于给 16 个工具；这也是"聪明"的可验证改进。

## 6. 实用闭环（让"办"真的转）

### 6.1 演示闭环机器人（`DEMO_AUTO_WORKER`，默认开）
- 新工单 → 自动"处理中（附备注）→ 已解决 → 通知居民"，模拟"有人办"。
- 页面标注「演示流程」徽标，可关。
- 让"上报→处理→解决→评价"整条链在评委面前自己转。

### 6.2 主动提醒（接入选工具）
- 居民端：重复报修同类 → Agent 主动提议"要不要把 X 升级为提案"。
- 网格员端：SLA 超时/升级 → 主动推送（已有）+ 工作台置顶（已有）。
- 老年端：到点用药/未打卡 → 主动通知（已有）+ TTS。

## 7. 成本与可靠性控制

| 手段 | 说明 |
|---|---|
| 快路径跳过 LLM | 高置信关键词直判，省一次调用 |
| 一次调多用 | 理解层输出复用为规划/上下文，不重复调 |
| 反思层限量 | 仅对"声称事实"的回复做核查（含数字/编号才调） |
| 工具裁剪 | 老年 4 工具，减少无效轮次 |
| 缓存 | `_llm_classify` 缓存已有；理解层加同款缓存（按文本 hash） |
| 护栏兜底 | 任何 LLM 异常自动降级，绝不白屏 |

## 9. 验收清单（对照"真 Agent"三问）

1. **会理解吗**：输入一个从未出现过的说法，Agent 自主路由到正确工具（泛化评测 ≥70%）。
2. **会思考吗**：复合任务自主规划多步执行；会主动追问澄清；思考卡片可见。
3. **会反省吗**：编造的编号/数值被自查纠正；执行失败会重试/换路径。
4. **会记住吗**：跨会话引用用户历史（"上次报的电梯"）并主动回访。
5. **会主动吗**：异常→自动派单/提醒/升级，闭环在演示中自己转。
6. **保底稳吗**：断网/无 key 时自动降级规则链，体验不崩。

---

## 10. 一句话总结

> 现在的 Agent 是"**轨道车**"——提示词是轨道，规则是道岔，LLM 是发动机。
> V3 要把它变成"**有方向盘的司机**"——LLM 把握方向（理解/规划/反思），规则只做护栏（保底/安全/成本）。
> 衡量标准不是"功能多了几个"，而是**"没教过它的场景，它能不能自己走对"**。
