## 一、上台前 30 分钟（照抄执行）

```bash
# 0）（可选但强烈建议）先清一次历史半途状态：SOS / 数据到位情况
python scripts/demo_reset.py                 # 只读体检；有问题加 --apply 收状态

# 1）起服务：必须绑 0.0.0.0，手机才连得上 ⚠️（默认 127.0.0.1 手机根本访问不到）
python -m uvicorn api_web:app --host 0.0.0.0 --port 8000

# 2）演示前自检（9 项必须全绿）
python scripts/demo_preflight.py

# 3）真移动端：手指点击级验证（22 项）⚠️ 用手机将要使用的那条 URL 跑
python scripts/mobile_flow_check.py --base http://<你的内网IP>:8000

# 4）隔离/配置两个可现场复算的探针（答辩被追问时直接跑）
python scripts/probe_tenant_isolation.py
python scripts/probe_tenant_settings.py

# 5）数字口径（评委问"你们多少测试/多少接口"时照着念）
python scripts/check_claims.py
```

**逐条看什么算过**

| 步骤 | 通过标准 |
|---|---|
| `demo_reset.py` | 5 段全 ✅（尤其「没有未结束的求助」）⚠️ |
| 服务起来 | 浏览器 `http://127.0.0.1:8000/login` 能开；手机 `http://<内网IP>:8000/login` 能开 |
| `demo_preflight` | **9/9 通过** |
| `mobile_flow_check` | **22/22 通过** |
| 两个探针 | 退出码 0，结论行是 ✓ |

### ⚠️ 手机第一次连不上 → 你要点一次"允许"

- 服务已绑 `0.0.0.0`，内网 IP 形如 `10.101.179.6`（用 `ipconfig` 看 WLAN 那行）。
- **Windows 防火墙默认没有 8000 入站规则**：手机首次访问会失败或弹窗，**必须点「允许访问」**
  （以管理员加一条入站规则更稳，但需要你自己点）。
- 手机和电脑要在**同一个 WiFi**；若会场 WiFi 隔离客户端（常见），走隧道方案：
  `python scripts/serve_public.py`（打印并复制公网 HTTPS 地址、生成扫码页）。
- 手机建议：**添加到主屏幕**（PWA `display: standalone`，打开后没有浏览器地址栏，更像一个 App）。
  注意：PWA 只能宣称"可添加到主屏幕"，**没有 service worker、不做离线**，别在台上说"离线可用"。

## 四、万一出问题（按可能性排序）

| 症状 | 原因 | 现场处理 |
|---|---|---|
| 手机打不开 | 防火墙未放行 / 不同网段 | 点「允许访问」；或换隧道 `serve_public.py`，用公网地址 |
| 对话回复很慢/失败 | 场馆网络到不了模型服务 | 说"规则优先是默认档"，功能仍可用；或提前把 `.env` 的 LLM 开关关掉走纯规则档（**改完必须重启服务**） |
| 页面是旧样式 | 改了 `web/src` 没 `npm run build` | `cd web && npm run build`（`demo_preflight` 会红字提示） |
| 老年端 SOS 点不动 | 有未结束的求助卡着 ⚠️ | `python scripts/demo_reset.py --apply` |
| 数据太好/太假被质疑 | 工单 175 条是程序生成 | 主动说："**预置数据是程序生成的**，证明的是机制与可审计性，不是治理成效" |
| 想回滚数据 | — | 备份在 `.shots/db-backup-before-purge-*.db`，直接拷回 `data/community_insight.db` |
