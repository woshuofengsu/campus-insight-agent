## 四、口径怎么讲（别被问住）

1. **"100%" 只适用于那 48 条冻结样本 + 当前知识库**，是**回归口径**，不是泛化能力。
   对抗集就是压力测试：问"公积金贷款"会被《公积金提取》答上——**这些都写在报告里，没藏**。
2. **常规跑测的"全绿"不含真实模型链路**：3 项真实 DeepSeek 兼容用例按标记 deselected、
   LLM 评分默认 skip（需 `RUN_LLM_EVAL=1`）——**这两组都已单独实测通过**（各 3/3，2026-09-29），
   讲的时候分清楚："常规套件不含它们；要验真实链路就加这两个开关，我们实测过"。
   别把它们算进常规套件的条数，也别因为没在常规套件里就说"没验证过"。
3. **多租户**：说"主业务路径 fail-closed（写入盖章 / 读取显式租户 / 按 id 闸门 / 任务按社区跑）"，
   **不要**说"全站绝对隔离"——无请求上下文的工具与全局知识库是**已登记边界**。
4. **SOS/呼叫**：网页只能打开拨号盘，**没有"已接通"这个状态**；老人 SOS 未响应升级任务本轮才发现
   因租户 fail-closed 从未跑通（已修 + 加门禁），可以主动讲这条"机制在、但没跑"的教训。
5. **幂等**：占位失败现在 **fail-closed**（不建单、如实说"状态未知，请点核对"），
   四类故障注入都有测试；门禁自检证明"换回旧行为必红"。

  以及"数字口径工具"三处**固定三位正则**（套件过 999 条时会把 1004 写成 10004，已修 + 加门禁）。
- 评审"数据都在返回体里、页面还没集中展示" → 居民端政策问答加**依据面板**（标题/版本/发布单位/文号/
  生效期/适用地区/检索来源/分数），门禁 `tests/test_qa_evidence_panel.py`。
- **全站去 emoji（557 处 → 0）**：界面图形统一改用 `EIcon` 的单色线性图标（`config/icons.js` 122 个语义图标），
  天气图标改由 `utils/weatherIcon.js` 按文字选图标。**这不是审美问题**：emoji 在各家手机上是不同厂商字形，
  而 `ui_audit` 只测对比度、`mobile_audit` 只测热区，**两个审计都测不出"字形不确定"**；
  门禁 `tests/test_no_emoji_ui.py`（含"图标名写错会静默显示成别的图标"这条静态检查）。
- **收敛方案第 3–7 阶段（老年人诉求闭环的"入口"做实）**：
  · 老年端**确认卡片**——提交后不只说"已上报"，而是回答"系统记住了什么"（位置/责任范围/紧急程度/
    所属社区/提交时间/当前状态，**每条标注来源**：您说的 / 我们按档案填的 / 系统建议）；
  · **治理情景模拟器**（网格端）——"量涨上来要多少工时、折算几个人"，公式写在页面上，
    **算不出来就明说**（未配置「人均可用工时」→ 不给人手数，绝不拿默认值硬算）；
  · **自动分类准不准**（网格端）——"系统建议分类 vs 网格员最终分类"对照清单，
    **覆盖率必须与一致率一起看**（建议写入是 2026-09-29 才补的，历史单没有建议值）。
- **顺手补上一个门禁漏洞**：`提交前清单-2026-09-29.md` 原来**不在**口径门禁的核对名单里，
  于是它长期停在旧数字（四项测试数与 schema 版本号都不是当前值）没人发现——
  **最该被核对的清单自己没人核对**。
  现已纳入 `check_claims` 与 `sync_test_count`，并加了"每份提交件都必须在门禁里"的自检。
  （写这句话时又踩了一次：引用旧版本号会把门禁自己弄红——所以这里只说"不是当前值"，不复述旧值。）
