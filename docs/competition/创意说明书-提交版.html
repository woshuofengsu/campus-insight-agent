二、项目概述（≤300 字）

基层"接诉即办"三大痛点：诉求处理不透明、时效无保障、独居老人安全真空（失联数日无人知晓）。

本项目是多智能体协同的社区治理 Agent：感知层监测工单热点、恶劣天气与老人活跃度；理解层用确定性规则识别诉求，模糊时由大模型兜底；协作层由 9 个声明式角色在黑板上多轮协商，调用 16 个工具；反馈层每轮必过 Verifier（幻觉/诊断/隐私拦截）+ Arbiter（合规·安全·专业·转人工）双层防线并全程留痕。三端差异化：居民一句话上报并追踪闭环，网格员办 SLA 工单，老人用大字版一键呼叫与 SOS。

属地化按基层刚需实现：政策本地优先、全国兜底，天气按所属社区取数；属地来自账号网格归属，不采集设备位置。

三、智能体架构与技术实现（核心）

1. 整体架构逻辑

① 架构范式：多智能体协作

主干为 OODA 自主循环（Observe→Orient→Decide→Act→Reflect），叠加角色化多智能体分工与黑板消息队列协商：角色之间通过 task_request / task_response / notify / error / handoff 五类消息在共享黑板上往返，一次用户输入可触发多轮跨角色协商，并改变后续执行链。

② 处理流程

  • 大模型选型：DeepSeek（OpenAI 兼容）。默认"规则为骨、LLM 为脑"：意图、状态机、权限、风控、脱敏全部走确定性规则；LLM 只用于模糊意图兜底、政策生成与跨角色协商。四项能力开关（LLM_ORCHESTRATION / POLICY_LLM_RAG / RECEPTION_LLM_FALLBACK / LLM_NEGOTIATION）可一键开关。

实测代价：每轮对话约 +0.9 秒 / +¥0.0002（真实调用，llm_usage 可查）。

  • 提示词工程：系统提示注入角色上下文与工具原则；LLM 输出走闭集校验（意图白名单、引用下标必须落在检索片段内、协商目标必须在 6 个可联动角色白名单内）。
  • 知识库构建：59→62 条知识条目；词法（同义词/方言扩展）+ 语义向量（text-embedding-v3, 1024 维）混合检索 + RRF 融合。
  • 检索质量：48 条口语金标 hit@1 = 100%（纯词法基线 85.7%），含 6 条属地用例（属地 Top-1 4/4）。
  • 属地化检索：applicable_area 归一（支持"北京市海淀区"这类复合串）→ 本地条目加分、全国条目始终保留（兜底）；属地只影响排序结果，不改变自动回答的阈值判定（该底线有专门测试）。
  • 工具调用：自研多智能体编排（9 个角色 + 黑板协商 + 16 个工具 + 按角色裁剪）。
  • 自动化节点：感知周期触发 → 自动派单 → SLA 升级 → 老人平安打卡检测 → 办结回访。

③ 输出形态

对话文本 / TTS 语音播报 / 工单与提案落库 / 状态流转与派单指令 / 天气与属地标签 / 治理看板与 KPI 图表 / 全链路留痕（activity_log + agent_logs）。

3. 人机协同边界设计

① 智能体自动执行环节

  • 居民诉求的意图理解、自动分类定级、工单生成
  • 主动派单（按类别 → 责任部门 → 网格员，自动写入 assignee）
  • SLA 超时/升级自动识别与预警
  • 独居老人超过 24 小时未互动 → 自动通知网格员
  • 用药提醒到点推送、"我已吃"确认记录
  • 属地自适应：政策按行政区划本地优先、全国兜底，天气按所属社区取数（属地只影响排序，不改变能否自动回答）

② 人类监督 / 审核 / 决策环节

  • 网格员确认工单处理、填写处理备注、指派处理人
  • 满意度「不满意」进入待复核状态，由网格员确认重开或驳回（防刷单）
  • SOS 紧急求助由网格员处置并标记"已处理"
  • 老人健康档案、用药提醒设置由家属/网格员协助录入
  • 系统不自动作答、一律转人工的五类情形（并生成带编号的人工处理包，居民可见 handoff_id）：

合规审计不通过 / Verifier 判定高风险 / 协商超过 2 轮 / 政策检索无任何达标材料 / Arbiter 兜底裁决

③ 安全与合规校验机制

  • 双层防线（每轮必过）：Verifier 校验（幻觉/敏感词/手机号泄露/医疗诊断句式拦截）→ Arbiter 仲裁（合规优先 → 安全 → 专业 → 费用或不可逆需人工 → 数据版本），决策落 agent_logs 留痕
  • 注入防护：提示注入规则拦截（"忽略之前所有指令"等变体）+ LLM 输出闭集校验
  • 政策回答不编造：仅基于检索片段生成，返回引用下标并校验在检索集内；无材料时转人工而非生成
  • 权限与鉴权：JWT（HS256，生产强制密钥）+ 角色权限守卫（越权 fail-closed）+ 演示登录生产模式硬关
  • 数据安全：手机号 AES-256-GCM 加密落库（g1$ 前缀），全库 8 张含手机号表明文计数为 0（含自动体检与启动自检）；属地识别不采集设备位置
  • 可观测与降级：trace_id 全链路（请求→业务留痕→Agent 留痕→异常）；LLM 不可用时自动回落规则链路，不影响业务可用性

四、产业 / 场景应用说明

1. 精准应用场景（垂直细分）

城市社区 / 街道的"接诉即办"日常治理，尤其是老龄化程度较高、网格员人手紧张的老旧小区。典型用户：① 居民（尤其不会用 App 的中老年居民）；② 网格员（一人管多网格、靠微信群和纸笔）；③ 独居/高龄老人及其家属。

2. 目标问题与现有方案痛点

现有做法痛点本项目怎么解
微信群上报 + 人工台账消息沉底、无状态、无法追责一句话自动生成工单，状态机 + 留痕 + 时限
政务 App / 小程序表单冗长、老年用户放弃；地区政策混在一起三端差异化；口语与方言归一；政策属地优先
通用大模型直接答政策幻觉、政策过期、地区不符强制引用 + Verifier/Arbiter + 弱命中转人工 + 属地优先/全国兜底
老人关怀靠定期上门空档期长、异常发现晚活跃度巡检 + 未打卡预警 + 大字 SOS + 家属绑定

3. 智能体提效 / 降本 / 提质 / 风控价值

  • 提效：诉求从"看到消息→手工登记→口头转派"变为"一句话→自动分类/派单/通知"，全流程线上留痕。
  • 降本：规则优先 + LLM 按需，日常诉求零 LLM 成本；实测单轮 LLM 成本约 ¥0.0002（2026-09-14 快照：累计 57 次调用合计 ¥0.0139，其中评测 40 题 ¥0.0109、跨角色协商 15 次 ¥0.0030）。
  • 提质：政策问答强制引用可溯源（"依据：XX 政策（V1）"），弱命中转人工而非硬答；SLA 分级与超时升级。
  • 风控：手机号等敏感字段加密落库 + 展示脱敏；医疗/法律类不自动回答；敏感词与完整手机号在输出前拦截；所有 AI 决策留痕可审计。

4. 适配区域 / 社区落地路径

  • 1. 单社区试点（最小可用闭环）：报修 + 通知 + 政策问答 + 适老 SOS 四项先跑通，用真实工单验证"平均受理时长 / 一次派单成功率 / 回访满意度"三个指标；
  • 2. 多社区接入：属地映射表（REGION_BY_COMMUNITY）从配置迁到 community_regions 表，租户维度隔离（代码已预留 tenant_id，当前仅 3 张主表预留、查询层未隔离，见 §5.5）；
  • 3. 与街道现有系统对接：12345 / 街道工单系统的字段映射（当前未对接，接口层已预留）。

移动端适配的取舍（主动放弃或降级的部分）

移动端定位为手机浏览器访问，不做原生 App，也不做桌面布局的等比缩小。以下为明确放弃或降级的部分：

#取舍原因与现状
1不做原生 App / 小程序，采用 Web + PWA（可添加到主屏幕、standalone 全屏）社区推广场景下 App 安装成本过高；无 service worker，不提供离线能力——接诉即办依赖实时数据，缓存政策/工单会产生过期信息
2治理大屏在手机上不做适配，改为提示层（<900px 显示"请在电脑/投屏查看" + 返回/仍要查看）大屏用于桌面与投屏场景；手机上挤压重排会破坏可读性
3老年端横屏不做重排，改为"请竖屏使用"提示层浏览器无法强制竖屏，横屏下排版空间不足（触发条件：横屏 + 触屏 + ≤1024px；竖屏与桌面不受影响）
4触屏热区放大，信息密度相应下降（通用 ≥44px、老年端 ≥72px）优先保证点按准确率；代价是手机单屏信息量少于桌面
5不做平板/大屏手机专属布局：断点体系为 359 / 360–427 / 428–767 / ≥768 四档以手机与桌面两端为主，中间档位仅保证不破版
6语音为增强功能（端侧 Web Speech），不作为唯一路径非 HTTPS／浏览器不支持／拒绝授权时，显式降级为打字 + 预置短语并聚焦输入框；方言、噪音、语速未做专项测试；iOS Safari 与微信内置浏览器可能不可用，服务端 ASR 列为后续工作
7手机端削减视觉动效（backdrop-filter 18px → 10px、页面不可见时暂停、prefers-reduced-motion 可关）保证低端机流畅与省电；代价是观感弱于桌面
8复杂表格/多列视图折叠为卡片与抽屉（网格端手机端为抽屉导航）窄屏横向表格可读性差
9未实现"低内存设备纯色降级"缺少可靠的浏览器能力信号（navigator.deviceMemory 仅部分 Chromium 支持）
10真机验证尚未完成21 页移动端审计基于 iPhone UA / DPR=3 / 触屏事件的浏览器仿真，非真机；iOS Safari 与微信内置浏览器待真机复验

设计优先级：可点准、看得清、不误导 > 信息密度、动效观感、原生体验。
