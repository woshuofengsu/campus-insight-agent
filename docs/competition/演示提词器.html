一、项目概述 20s

Streamlit 首页全景
各位评委好。我带来的作品是「校园先知」——一个以大学校园为原型验证环境的 智慧基层治理平台。大学是一座几万人的微型社会——有设施维护、公共卫生、民意收集、政策反馈。我们在这个边界清晰的实验场里验证了一套治理方法论。如果验证通过，同样的架构可以直接迁移到社区、养老机构、企业园区。
核心理念：把大学校园视为微型社会，用 Agent 降低学生参与治理的门槛，用数据透明建立学生对治理的信任。
四个字概括：知、报、议、督。

二、知 — 校园脉搏 30s

点击校园脉搏页面，依次展示天气、热点、事件
首先是「知」——知情权。打开应用，系统已完成环境感知。
天气数据来自和风 API 实时接口。本周校园问题上报情况和热点类别分布基于数据库实时统计。即将发生的事件来自校园知识库。
学生不需要进行任何操作即可获取这些信息。知情是参与的前提——这是治理闭环的起点。

三、报 — 随手报修 60s

切换到对话页，输入报修内容，发送
其次是「报」——参与权。当学生发现校园问题时，使用自然语言描述即可。
Agent 回复，指向工单号、分类、紧急程度
系统通过 OODA 引擎的 Orient 阶段完成意图识别——当前输入被路由到报修助手角色。Agent 调用 report_issue 工具，自动完成分类、定级、工单生成。整个过程学生无需了解任何分类标准或操作流程。
点击"推理链"展开面板，缓慢滚动展示各阶段卡片
Agent 的每一次回复背后都有一条完整的推理链。Observe 阶段感知到的环境数据、Act 阶段调用了哪个工具以及工具返回了什么、Reflect 阶段执行了哪些检查——每一步决策都可追溯、可验证。这不是一个黑盒。
快速切换到健康防护页面，滚动疾病卡片
此外，系统通过感知引擎主动推送健康风险信息。当前展示的是基于国家疾控局月度公报数据、结合季节模型和天气关联因子的疾病风险评估——甲型流感、乙型流感等疾病的全国趋势和校园风险等级。

四、议 — 有话说 55s

对话页，输入"看看大家有什么好提案"
第三个环节——「议」，表达权。
展示提案列表
系统当前存储 19 条提案，按附议数降序排列。排名第一的实验楼安全排查提案，89 人附议，状态为已采纳。延长图书馆闭馆时间提案，73 人附议，已实施。增设快递柜提案，62 人附议，已获批。
每一条提案包含完整的状态流转记录——从讨论中到已回应、已采纳、已实施。
输入创建提案
当学生提出新提案时，系统首先进行语义查重——计算标题与已有提案的字符重叠度。若相似度超过阈值，引导用户附议已有提案，避免支持力量分散。若为全新提案，自动创建并分类。
切到议题讨论区
此外，感知引擎会定期扫描工单数据——当某类别问题在短期内集中出现时，自动生成讨论议题，汇集学生意见。这一机制将分散的个人反馈转化为结构化的民意数据。

五、督 — 治理透明窗 45s

打开治理透明窗，指向健康度评分
最后是「督」——监督权。治理透明窗的核心是健康度评分系统。
这不是简单的展示统计数据——而是一个三维加权评估模型：解决率占 40% 权重，解决速度占 35%，积压趋势占 25%。评分方法参考了 ISO 37120 市政治理指标体系。
七天趋势对比图展示治理动态——新增工单与已解决工单的双线对比，直观反映治理效率的变化方向。
点击治理大屏
治理大屏是为管理层设计的全屏实时仪表盘。六个核心 KPI、趋势图、工单流转管道、类别分布和最近动态。数据每 30 秒自动刷新，CSS 动画标记异常告警。
透明是建立治理信任的基础。当学生看到自己的上报被处理、提案被采纳、数据在改善——参与意愿才能持续。

六、技术架构 30s

切换到 IDE/终端，展示项目结构或 pytest 结果
简要说明技术实现。系统基于 OODA 循环设计治理工作流引擎，每个用户请求经过五个阶段。
Observe 环境感知——预查询天气、工单热点、时间上下文。Orient 意图定位——基于 100 余个关键词和正则语义回退的 Persona Router，零延迟完成意图识别。Decide 与 Act——LangChain AgentExecutor 调用 14 个治理工具，DeepSeek 模型自主编排调用顺序。Reflect 反思——七项后处理检查，包括 Anti-Hallucination 安全网，当检测到 LLM 未实际调用工具即编造回复时，强制执行真实工具调用。
系统设计了三层容错回退链：LLM 不可用时切换至规则引擎，规则引擎不可用时降级至数据库直查，确保服务持续可用。
项目包含 309 个自动化测试，覆盖单元、集成、端到端三个层级，已配置 GitHub Actions 持续集成。
