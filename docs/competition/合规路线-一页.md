# 合规路线一页（WS10.1）—— 社区先知 CommunityInsight

> 目标：讲清"真落地要过哪些关、现在做到哪一步、差距与计划"。**严禁把预留字段/规划项说成已完成。**

## 一、等保与密评（网络安全合规）
- 目标：等保 **2.0 三级**（政务类/涉居民个人信息应用常需三级）+ 商用密码应用安全性评估（密评）。
- 现状：已具备 安全响应头（CSP/X-Frame/Referrer）、JWT 鉴权、登录防爆破、生产禁演示登录、敏感字段加密（AES-256-GCM + 密文版本前缀）、审计留痕（activity_log）。
- 差距/计划：流程性制度（定级备案、漏洞扫描、应急演练）；**私有化/数据不出域**部署是优先路径（见下）。

## 二、个人信息保护（PIPL）
- 知情同意：需在首次使用弹窗告知用途并取得同意（现状：演示版未接，规划到正式版）。
- 最小必要 + 加密存储：手机号 **AES-256-GCM** 落库、明文置空、展示脱敏（`138****8000`）、日志不含完整号码——**已实现**。
- 留存与删除：提供 PIPL 导出（`/api/web/me/export`，脱敏）与注销（`/api/web/me/delete`，匿名化+停用）——**已实现**（见 tests/test_security.py）。
- 共享台账：向第三方（如 12345 工单系统）共享数据需登记台账 + 明确授权——**规划项**。
- 争议处理：删除/更正/撤回同意等通道——**规划项**。

## 三、密钥管理
- 现状：`WEB_JWT_SECRET` / `CRYPTO_KEY`（AES 密钥）来自环境变量，生产强制；`.env` 不进 git。
- 计划：上生产接 **KMS**（云厂商/国密 KMS）管理密钥、支持轮换；AES 密文已带版本前缀（`g1$`），支持平滑算法轮换（脚本 `scripts/reencrypt_phones.py` 幂等重加密）。

## 四、行业与数据来源合规
- 真实数据来源：12345 导出 / 物业 Excel 定时导入（`perception/source_adapter.py` 目前为 mock，接真实源时需授权）。
- 医疗/法律边界：健康顾问**不诊断**、政策问答无来源**转人工**、敏感内容拦截——**已实现**（Verifier/arbiter）。

## 五、当前真实状态（不与上述混同）
- 演示阶段：`DEMO_MODE=true`、`DEMO_AUTO_WORKER` 机器人仅用于演示流程，**不代表真实治理成效**。
- 生产切换清单：`DEMO_MODE=false`、LLM 开关归 0 的可关、强密钥、CORS 白名单、演示登录 403、API 文档关闭。

> 一句话：**数据加密/脱敏/导出/注销 + 防爆破 + 审计留痕**这几条硬指标已落地并通过测试；等保定级、PIPL 同意书与共享台账、KMS、真实数据源授权是落地前要补齐的差距。
