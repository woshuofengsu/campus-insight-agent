# 〇、先搞懂评委怎么打分（对着评分点准备）

OPC 单人创新/轻量化落地，评委心里大致有一杆秤，你要让每个分点都有对应证据：

| 评分维度 | 评委在看什么 | 你的对应证据/素材 |
|---|---|---|
| 问题与价值 | 痛点真不真、人群清不清、价值大不大 | 接诉即办高频、基层减负、老人数字鸿沟（手册 2.1） |
| 方案与创新 | 是不是真智能体、和套壳/工作流的区别 | 黑板+消息+仲裁+留痕的真协作（2.5/2.6） |
| 技术与完成度 | 能不能跑、稳不稳、工程是否严谨 | 638 项测试、550 并发、v46、ruff、UI 审计（2.13） |
| 可信与合规 | 幻觉/隐私/安全怎么兜 | 强制引用、双层防线、AES 加密、转人（2.6/2.7/2.9） |
| 用户与体验 | 是不是真好用，尤其适老 | 三端、适老细节、防呆、转人不重复（2.10/2.11） |
| 落地与商业 | 谁用、谁买单、怎么复制 | 政府购买+SaaS、试点→数据→复制（B-Q19/20） |
| 个人与团队 | 单人能否驾驭、清不清醒 | 十轮迭代、取舍清晰、诚实短板、AI 副驾定位（B-Q21/22） |
| 现场表达 | 讲不讲得清、演不演得稳 | 三版陈述、Demo 动线、断网兜底（手册第三部分） |

> 结论：**评委不是找"技术最炫"的，是找"问题真、方案新、做得实、讲得清、落得了"的。** 你的牌其实很好，关键是别被带偏到拼技术名词。

# A. 你要主动问专家的问题（设议程、显专业、拿资源）

> 别问空泛的"您觉得怎么样"。一次只问一个、听完追问，临走一定加微信。

**A1 落地路径**："想先找一个社区做小试点，**学校团队进街道，第一步该找谁、用什么由头最容易成**？免费示范点还是直接走采购？" → 追问"试点先只保留哪两三个功能？"（补你最大短板，可能直接拿到资源）
**A2 需求聚焦**："报修/提案/政策/健康/天气/适老都做了，**从真实基层痛点排序，哪个最该做成不可替代的尖刀**？"（借专家之口帮你聚焦）
**A3 合规准入**："民生场景我做了规则为主、强制引用、合规否决、转人。**真进政务采购，等保/数据本地化/算法备案该在什么阶段办、先办哪个**？"（显合规意识+拿准入清单）
**A4 架构演进**："现在 SQLite+自研内核，数据层和队列接口都预留了。**从单街道扩到区级，先做多租户隔离还是先把队列/缓存独立**？"（证明你想过规模化）
**A5 真 Agent 判定**："很多'智能体'其实是固定工作流或单一大模型，我做了消息协议、黑板状态、仲裁留痕。**评审时'真多智能体'最有说服力的区分点是什么、还该补什么证据**？"（把话题引到你最强处）
**A6 路演取舍**："只有几分钟+一对一，**时间押在现场完整演一遍，还是讲架构和数据**？"
**A7 提前拆雷**："如果您是评委，看到**单人、用 AI 辅助写代码**的学生项目，最先怀疑什么？我怎么提前打消？"（直接拆"是不是 AI 写的"这颗雷）
**A8 要资源（临走）**："您接触的街道/园区/孵化器里有没有合适的试点或立项机会？方便加个微信、我把资料发您请您指点吗？"

# B. 你必须准备好被问的 34 个问题

## B1 项目价值与真实需求

**Q1 和 12345/现有社区系统啥区别，重复造轮子？**
- 潜台词：存在价值。要点：现有=被动受理+人工流转+台账；你=AI 前置分流+主动协同+适老+可审计，是**补位的智能增效层**、可对接不替代。
- 话术："12345 是诉求的入口和台账，我们做入口**之后**那段——能自动办的 AI 先办、要联动的自动协同、拿不准的带完整上下文转人，还主动做天气健康预警。我留了对接适配层，是补位不是替代。"
- 避坑：别说现有系统不行，说协同补位。

**Q2 需求是你想的还是真的？做过调研吗？**
- 要点：诚实讲来源（公开政策、接诉即办高频事项、基层减负报道、适老痛点），流程照真实链路做，试点是下一步。
- 话术："需求来自三类公开事实：接诉即办高频事项、基层事务繁杂的普遍情况、老人数字鸿沟。功能流程是照真实处置链路做的。小范围真实试点正是我下一步最想验证、今天也想请教您的。"
- 避坑：别编"访谈了多少社区"这种一戳就穿的数。

**Q3 这么多功能是不是贪多？核心是哪个？**
- 要点：主线一条=接诉即办闭环+多智能体协同，其余是入口；试点先砍到三个。
- 话术："核心就一条线：居民说事→AI 分流协同→合规把关→人工兜底。真做试点我会先只保留报修、政策问答、天气健康联动三个最刚需场景。"

**Q4（新增）政策风口在哪？为什么是现在做？**
- 要点：接诉即办、基层治理现代化、数字政府、适老化改造、AI+都是明确政策方向；现在大模型能力刚好成熟到能做"可控增强"。
- 话术："接诉即办改革、基层治理现代化和适老化都是持续推进的政策方向，而大模型这两年才成熟到能在可控前提下做辅助，时机和能力刚好对上。"

## B2 多智能体与"是不是真 AI"（主战场）⭐

**Q4 你这就是聊天机器人套壳吧？凭什么叫多智能体？**⭐
- 要点四条：角色分工与边界；5 种结构化消息+带锁版本的黑板共享状态；**真调工具改业务状态**（建工单/发通知）而非只出文字；校验仲裁留痕转人。
- 话术："聊天机器人问一句答一句、不改业务状态。我这天气 Agent 发现高温会**主动**给健康 Agent 发协作消息、再让通知 Agent 发提醒，每步黑板留痕；输出要过事实校验和合规仲裁，拿不准转人。**是能办事、会协作、可审计的团队，不是对话框。** 现场可以给您看黑板真实消息流。"

**Q5 九个 Agent 是不是过度设计？一个大模型几个 Prompt 不够吗？**
- 要点：民生要权责清晰、可测、可审计、可局部降级；专职化可单测（638）、单点故障不扩散、贴合真实组织。
- 话术："娱乐场景一个模型也许够，民生要'谁办的、依据啥、能不能追溯'。专职角色每块确定、可独立测试、出问题能隔离，还能合规一票否决，也贴合真实社区分工，老百姓一看就懂。"

**Q6 仲裁优先级凭什么这么定？真冲突管用还是写死 if-else？**
- 要点：优先级来自政务红线（合规/安全优先），裁决分类型且留痕；这里**本就该确定可解释，不该交给模型自由发挥**，规则可与业务专家共调。
- 话术："仲裁不追求聪明，追求可解释安全：合规安全是红线最先，专业问题听专业角色，判不了一律转人，每次裁决记录原因。这套顺序是可和业务专家一起调的规则，不是黑盒。"

**Q7 到底哪些是 AI、哪些是规则？会不会写了 LLM 其实都在跑规则？**⭐
- 要点：确定性核心 100% 规则；LLM 仅四处、四开关默认关、可一键开；金标证明 LLM 环节确实更优。
- 话术："我分得很清：**该确定的永远规则，该灵活的才用模型**。政策生成、意图兜底用 LLM，48 条金标证明开了检索增强命中率从 85.7% 提到 100%；派单、权限、状态流转绝不用模型赌。开关默认关是主动选择不是没接，现场可开给您对比。"

**Q8 LLM 幻觉答错怎么办？**⭐
- 要点：五道防线+零结果转人。
- 话术："强制先检索真实材料、强制标引用第几条、引用必须真实存在、输出回查数据库、合规复核，任一不过就回退规则或转人；检索不到材料**宁可转人也绝不编**。"

**Q9 断网/大模型挂了是不是就废了？**⭐
- 要点：规则主干不依赖网络/LLM，统一超时熔断回落+缓存，离线核心可办。
- 话术："不会，大模型只是增强。每次模型调用 3–10 秒超时、失败自动回规则，天气有缓存。断网照样建工单、查政策条目，只是少了自然语言润色。"

**Q10（新增）为什么不用 LangGraph/AutoGen 这些现成智能体框架？**
- 要点：现成框架抽象重、依赖多、版本变动快、现场不稳、对消息/仲裁/留痕/离线掌控弱；自研轻量内核恰好契合"OPC 轻量化落地"，且预留了队列替换接口，规模上来可演进。
- 话术："我评估过，现成框架对这种强流程、强合规、要离线稳定演示的场景偏重，黑盒也多。自研轻量内核让我对每条消息、每次仲裁、每条留痕完全可控，更符合轻量化落地；消息队列等扩展点我都留了接口，将来要换成熟框架也不返工。"

**Q11（新增）你的 Agent 会自己学习/越用越聪明吗？**
- 要点（诚实）：当前是"规则+检索+按需 LLM"，知识更新靠知识库版本与 KG，不在线乱学（政务不能让模型无人监管地自学习）；有反思/闭环模块记录人工改判，可用于后续优化规则与评测集。
- 话术："我刻意不做无人监管的在线自学习——民生场景里模型自己改行为很危险。它的'变聪明'来自知识库版本更新、知识图谱扩充，以及把人工改判沉淀成规则和评测集，是可控迭代。"

## B3 技术架构

**Q12 为什么用 SQLite，扛得住真实业务？**
- 话术："单街道读多写少，SQLite 够且零运维、演示稳；数据访问层抽象了，扩到多街道平滑切 PostgreSQL 不返工，是分阶段选择。"

**Q13 单文件后端是不是结构混乱？**
- 要点：已按业务域拆十余个路由模块，分层清晰，638 项测试让重构安全。
- 话术："早期为快跑放一起，现在已按业务域拆成独立路由模块，服务/数据/智能体分层是清楚的，而且有 638 项测试兜底，每次拆分都靠测试保证不拆坏，是可控技术债。"

**Q14 并发写黑板/数据库会不会竞争？**
- 话术："黑板写入带锁和版本，数据库开 WAL，压测 550 并发零失败（登录端点；业务混合压测服务端 5xx=0），并发安全是设计时就考虑的。"

**Q15 测试都是你自己写的能说明啥？**
- 话术："测试价值是'改不坏'：每加功能都要 638 项全绿，等于持续保险。另外还有并发压测、54 视口 UI 审计、检索金标，是多维验证不是刷数字。"

**Q16（新增）数据冷启动：知识库/工单数据从哪来？**
- 要点：知识库由社区公开政策/办事指南结构化录入并版本管理，支持文档导入；演示用脱敏样例数据；真实落地由街道提供材料、平台负责结构化。
- 话术："政策知识来自公开办事指南、可文档导入、做版本管理；工单演示用脱敏样例。落地时由街道提供权威材料，我负责结构化入库和检索调优，保证答案来源权威可溯。"

**Q17（新增）出了 bug 或 AI 判错，怎么定位、谁负责？**
- 要点：执行链+agent_logs+黑板 history+仲裁记录可完整复盘；责任上 AI 是辅助、关键动作人确认、合规可否决，最终责任在使用单位的人工岗，系统提供全程证据。
- 话术："每条诉求的完整执行链、每个 Agent 的判断、每次仲裁都留痕，能像黑匣子一样复盘。机制上关键动作必须人确认、合规可否决，AI 不替人担责，系统提供可追溯证据。"

## B4 数据安全与合规

**Q18 居民手机号等隐私怎么保护？**⭐
- 话术："入库前 AES-256-GCM 加密，界面和导出只显示打码，后端按需解密；我核验过所有手机号表没有明文残留。配合最小权限、参数化 SQL 和操作审计，符合个保法最小必要原则。"

**Q19 大模型会不会把居民数据泄露出去？**
- 话术："送模型前先脱敏、能不送不送，优先国产合规模型，敏感处理留在本地规则层；正式落地可私有化/本地化部署、数据不出域。"

**Q20 PIPL/等保/备案考虑了吗？**
- 要点：已按 PIPL 做最小必要/加密/留痕/可查；等保与算法备案是正式采购阶段办理，并现场请教（接 A3）。

**Q21（新增）权限怎么保证网格员看不到不该看的、居民改不了别人数据？**
- 话术："基于角色的最小权限，登录令牌带角色和社区，后端每个接口再校验角色与数据归属，前端隐藏只是体验、真正拦截在后端；合规审计员还会做权限校验和敏感操作留痕。"

## B5 适老化与体验

**Q22 老人端不就是字大？**
- 话术："适老不是放大字：语音报修、长按才触发的紧急求助（防误碰）、用药提醒、高对比大按钮、危险操作二次确认、路径压到最短、紧急症状一步到就医指引。"

**Q23 方言/口音/噪音/老人语速解决了吗？**
- 话术（诚实）："目前普通话和高频口语可用，方言和复杂指代是明确的下一步，会用'前端语音识别+后端方言同义词典+意图白名单兜底'逐步覆盖，不假装已全解决。"

**Q24（新增）居民凭什么愿意用、网格员凭什么愿意用？**
- 要点：居民侧=少跑腿、进度可见、被主动提醒、老人也能用；网格员侧=AI 分流减负、待办/统计/导出/驳回建议自动化，用"自解决率、平均办结时长"证明减负。
- 话术："居民图省事和被照护，网格员从事务里被解放出来。落地我会用两个指标证明价值：AI 自解决率和平均办结时长下降，让使用者直接看到减负。"

## B6 落地、商业、团队

**Q25 谁买单？商业模式？**⭐
- 要点：主=政府购买服务（街道/区县数字化、适老、接诉即办增效预算）；次=SaaS 按社区订阅、私有化部署、知识库定制与培训；先标杆后复制。
- 话术："买单方是街道/区县，走政府购买和数字化专项；形态是年费订阅+私有化+知识库定制培训。先用一个示范点跑出办结时长、自解决率的减负数据，再拿数据向其他街道复制。"

**Q26 真实落地成本、谁运维？**
- 话术："规则为主所以日常几乎没模型开销，只有少量生成按量付费，单社区月成本很低。部署容器化托管，配合日志和自动降级，一个信息员能管多个社区。"

**Q27（新增）如果给你一笔钱（比如 10 万/50 万）你怎么花？**
- 要点（显规划）：小步——试点落地与数据打磨占大头，其次合规/部署、少量模型调用与适老测试，不盲目扩张。
- 话术："最大头投在一个真实社区的试点落地和迭代上，包括数据对接和现场培训；然后是合规部署和稳定性，模型调用成本其实很低；留出适老可用性测试的预算，先把一个点做透再复制。"

**Q28（新增）半年里程碑？**
- 话术："1–2 月完成一个社区试点对接与数据初始化；3–4 月跑出自解决率/办结时长数据、补 NLU 与评测金标；5–6 月做多租户隔离和外部 12345 对接，形成可复制方案，谈第二个街道。"

**Q29（新增）项目最大的风险是什么？**
- 要点（清醒）：最大风险不是技术，是**真实落地的推进与数据对接**、以及使用习惯；对策=小试点、选尖刀场景、给网格员看得见的减负、人工兜底保平稳。
- 话术："技术风险可控，真正的风险是落地推进和使用习惯。所以我不铺大，先选一个社区、三个尖刀场景，用减负数据建立信任，全程人工兜底保证不出事。"

**Q30 你一个人做的？代码是 AI 写的吧？你真懂吗？**⭐⭐（必考）
- 要点：大方承认+讲清主导权（需求/架构/安全/测试标准/验收是自己定）+能讲模块、能现场演、能答取舍。
- 话术："对，单人参赛，AI 是我的编程助手，像工程师用脚手架，负责把我设计的东西实现。但**做什么不做什么、为什么规则优先、为什么手机号必须加密、为什么紧急通知要人确认、638 项测试的验收标准都是我定的**。您随便挑模块，我讲它的设计思路和取舍；代码可以让 AI 帮写，架构判断和产品责任是我的。"
- 避坑：①别谎称全手写；②别自我贬低说"我啥都不会"；③**对流程和数字烂熟于心就是最好反击**。

**Q31 你一个大二学生怎么保证做下去/落地？**

**Q32 和市面同类/大厂智慧社区比优势？**
- 要点：大厂重、贵、周期长、偏硬件平台；你轻、快、低成本、协同智能与适老更细，可做其前端智能补充，错位竞争。

**Q33（新增）知识产权/数据归属怎么算？**
- 要点：代码与系统设计为自有；知识库内容归属提供方（街道）并授权使用；居民数据归属居民、平台只受托处理，符合 PIPL；AI 辅助生成不影响整体著作权的人的创造性主导。
- 话术："系统和代码是我自主设计，数据归属清晰：知识材料由街道授权、居民数据归居民、平台只是受托处理，合同里会约定数据不出域和归属，符合个保法。"
