## 场景 1：知 + 报 —— 打开即感知，开口即参与（40 秒）

### Step 1.1 — 展示页面（10 秒）

**操作**：打开应用，不作任何输入。

**预期显示**：
- 侧边栏展示治理 KPI（上报数、解决数、提案数）
- 右侧显示治理大屏入口、校园脉搏、随手报修等页面

**讲解词**：
> "打开校园先知，侧边栏实时展示校园治理关键指标。不需要任何操作，也不需要去任何地方查。这就是'知'——让每个学生都知道校园在发生什么。"

### Step 1.2 — 校园脉搏（15 秒）

**操作**：点击 🌊 校园脉搏页面，或输入"校园脉搏"。

**预期显示**：
- 天气卡片（今日天气、温度、降水概率）
- 校园事件（停水检修、运动会、图书馆延长通知）
- 本周热点分布（Altair 柱状图，设施维修最热）
- 最热类别可点击跳转到报修页

**讲解词**：
> "校园脉搏告诉你这周发生了什么、下周有什么大事——停水检修、运动会、图书馆即将延长。天气感知来自真实 API。热点分布让你一眼看到校园最需要关注的问题类型。这就是'知'的全部——知情权是参与的基础。"

### Step 1.3 — 上报问题（15 秒）

**操作**：在聊天框输入：
```
教三楼二楼男厕所第三个水龙头一直在漏水，地上已经有一滩水了
```
按 Enter 发送。

**预期 Agent 行为**：
1. Persona Router 识别为报修场景
2. Agent 调用 `report_issue` 工具
3. 自动分类"设施维修"、定级"普通"
4. 返回工单号

**讲解词**：
> "我只需要用自然语言描述问题——不用选分类、不用填表单、不用找入口。Agent 自动识别这是'设施维修'、自动判断紧急程度、自动生成工单。上报→分类→追踪——这就是完整的'报'的闭环。"

## 场景 2：议 —— 从吐槽到提案，从个人到集体（1 分 20 秒）

### Step 2.1 — 查看提案（20 秒）

**操作**：输入：
```
看看大家提了什么好建议
```

**预期 Agent 行为**：
1. Persona Router 识别为议事场景
2. Agent 调用 `get_proposals` 工具
3. 展示提案列表（默认 10 条），按附议数排序

**讲解词**：
> "19 条提案，按附议数排序。最高 89 人附议的'实验楼安全排查'已被采纳。'延长图书馆闭馆时间'73 人附议，已经实施。这不是空谈——学生用附议表达诉求，学校用行动回应。系统在这里的作用是降低参与门槛：学生只需自然语言描述想法，Agent 自动查重、分类、创建。"

### Step 2.2 — 附议提案（15 秒）

**操作**：输入：
```
我支持延长图书馆那个提案
```

**预期回复**：
```
👍 你附议了提案 #2「建议图书馆延长闭馆时间到23:00」
当前附议人数：74
💡 分享给同学，让更多人支持这个提案！
```

**讲解词**：
> "一键附议。73 人附议的提案，校方已经采纳并延长了开放时间。学生看到自己的附议推动了真实改变——这就是议的力量。"

### Step 2.3 — 创建提案（20 秒）

**操作**：输入：
```
我有个提案——建议在每栋宿舍楼下增设快递柜，现在快递都堆在校门口很乱
```

**预期 Agent 行为**：
1. Agent 调用 `create_proposal` 工具
2. 工具检查是否存在相似提案 → 发现已有 #7「建议在宿舍区增设快递柜」(62人附议)
3. 提示用户已有类似提案

**讲解词**：
> "当我想创建的提案和已有提案相似时——Agent 自动查重，提醒我去附议已有的，避免力量分散。这就是智能查重——让集体声音更集中、更有力。"

### Step 2.4 — 参与议题讨论（25 秒）

**操作**：输入：
```
大家对食堂涨价怎么看
```

**预期 Agent 行为**：
1. Agent 调用 `get_topics` 工具
2. 展示系统发起的议题「食堂菜品价格最近涨了，你怎么看？」（5 人参与）

**操作**：输入：
```
我对食堂涨价有话说——一楼麻辣烫涨了2块但是分量也变多了，还可以接受
```

**预期回复**：
```
💬 你的意见已发表！
📋 议题：食堂菜品价格最近涨了，你怎么看？
👥 当前参与人数：6
💡 你的声音很重要——系统会定期汇总讨论结果，形成民意报告。
```

**讲解词**：
> "发表意见只需一句话。系统自动归类、汇总。还能根据校园热点——比如食堂涨价——自动发起议题。不需要问卷调查，学生在对话中自然表达意见。从个人吐槽到集体声音——这就是议。"

## 场景 3：督 —— 闭环反馈 + 数据透明（1 分钟）

### Step 3.1 — 展示治理透明窗（20 秒）

**操作**：点击 📊 治理透明窗页面。

**预期显示**：
- 三维加权健康度评分（解决率 40% + 速度 35% + 积压 25%）
- 7 天治理趋势图（新增 vs 已解决双线）
- 工单状态管道图 + 类别分布
- 最近动态时间线

**讲解词**：
> "治理透明窗展示治理健康度——三维加权算法综合计算解决率、解决速度和积压趋势。今天的健康度是'良'——这意味着：报修的东西会修、提的建议会回应、参与是有结果的。趋势图告诉你治理是在变好还是变差。透明本身就是最好的信任机制。"

### Step 3.2 — 展示治理大屏（15 秒）

**操作**：点击 📺 治理大屏。如果有投影仪/大屏，可全屏展示。

**预期显示**：
- 全屏实时数据仪表盘
- 6 个 KPI 卡片（健康度、累计上报、已解决、待处理、提案、参与）
- 7 天趋势图 + 工单流转管道
- 最近工单动态列表 + 类别分布
- 30 秒自动刷新

**讲解词**：
> "治理大屏——为校园管理者设计的全屏实时仪表盘。KPI 一览、趋势图、工单流转、类别分布——所有数据 30 秒自动刷新。CSS 动画让异常告警脉冲闪烁，一眼就能看到需要关注的紧急问题。"

### Step 3.3 — 展示闭环追踪（15 秒）

**操作**：回到 💬 对话页面。输入：
```
我上次报修的水龙头修好了吗
```

**预期 Agent 行为**：
1. Agent 调用 `query_issues` 查询该用户的工单
2. 返回工单 #1「教三楼二楼男厕水龙头漏水」状态：已解决
3. Agent 在回复末尾自动追加闭环追踪信息
4. 推理链面板展示关联洞察

**讲解词**：
> "我上次报修的水龙头——状态已经是'已解决'。感知引擎检测到状态变化后，会在对话中主动推送。更重要的是，Agent 的推理链面板展示了治理工作流的完整过程——从感知到推理到行动，每一步都透明可见。不是'上报就完了'，而是完整的闭环——上报→处理→解决→通知。"

### Step 3.4 — 收尾（10 秒）

**操作**：回到整个页面全景。

**讲解词**：
> "总结：校园先知，用四个字概括——**知**校园事、**报**校园修、**议**校园政、**督**校园治。从上报到追踪到解决，每一步都看得见。降低参与门槛、建立治理信任、形成闭环反馈。让每个学生都成为校园治理的参与者，而不仅仅是旁观者。谢谢评委！"

## 附录：常见问题应对

### Q1：Agent 回复不符合预期怎么办？

- 提前测试每个场景至少 3 次（推荐提前录制成功演示为备用）
- 如果 Agent 工具调用出错，刷新页面重试（种子数据幂等，不会重复插入）
- 关键场景可使用快速上报表单（💬 对话页顶部）直接写入 DB，跳过 Agent

### Q2：种子数据看起来不够"真实"怎么办？

- 强调：38 条工单覆盖了 8 个分类 + 3 种状态 + 3 种紧急程度，19 条提案含不同状态和附议量（7-89 人）
- 叙事线展示了完整使用场景（设施报修→自动分类、食堂问题→议题讨论、图书馆问题→提案被采纳、安全隐患→紧急工单优先处理）
- 真实使用时，每个学生上报的问题都会实时加入数据库

### Q3：30 秒等待感知引擎触发太久怎么办？

- 演示时通过刷新页面（F5）立即触发感知检查
- 或在 `config.py` 中将 `PERCEPTION_IDLE_SECONDS` 临时改为 5 秒

### Q4：大屏没有数据怎么办？

- 使用演示模式：URL 加 `?demo=1` 参数，自动使用足量模拟数据

### Q5：如何展示治理工作流推理过程？

- 每次 Agent 回复后，聊天消息上方会出现"推理链"面板
- 展示每个阶段（Observe → Act → Reflect）的步骤卡片
- 面板底部展示"💡 智能关联发现"——空间聚类、异常检测、相关提案
- 面板最后展示"💡 你可能还想..."——主动建议引擎
