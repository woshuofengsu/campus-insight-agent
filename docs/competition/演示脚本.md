## 场景 1：知 + 报（55 秒）

### Step 1.1 · 首页全景（10 秒）

| 操作 | 打开应用，不输入任何内容 |
|------|------------------------|
| 展示 | 侧边栏 KPI（上报数、解决数、提案数）、页面导航 |

> 🎤 "打开校园先知，侧边栏实时展示校园治理关键指标。不需要操作，不需要查——这就是知，让每个学生知道校园在发生什么。"

### Step 1.2 · 校园脉搏（15 秒）

| 操作 | 点击 🌊 校园脉搏 |
|------|-----------------|
| 展示 | 天气卡片、校园事件（停水检修、运动会、图书馆延长通知）、本周热点柱状图 |

> 🎤 "校园脉搏——这周发生什么、下周有什么大事。天气来自真实 API。热点分布一眼看到最需要关注的类型。知情权是参与的基础。"

### Step 1.3 · 上报问题（30 秒）

| 操作 | 切换到 💬 对话页，输入并发送 |
|------|-------------------------|

```
教三楼二楼男厕所第三个水龙头一直在漏水，地上已经有一滩水了
```

| 预期 | 自动分类"设施维修"、定级"普通"、生成工单号 |
|------|------------------------------------------|

| 操作 | 点击回复上方的"🧠 处理流程"面板，展示 OODA 卡片 |
|------|------------------------------------------|
| 展示 | Observe 感知数据 → Act 工具调用 → Reflect 质量检查 |

> 🎤 "自然语言描述问题——不用选分类、不用填表单。自动分到设施维修、自动判断紧急程度、自动生成工单。每次回复背后都有一条处理流程——从感知环境、调用工具、到质量检查——每一步都可追溯。上报→分类→追踪，这就是报的闭环。"

## 附录 A · 常见问题

| 问题 | 应对 |
|------|------|
| Agent 回复不符合预期 | 提前每场景测试 3 次，录屏备用；刷新页面重试 |
| 云端休眠打不开 | 立即 `start.bat` + `ngrok http 8501`，给评委公网链接 |
| 大屏没数据 | URL 加 `?demo=1` 使用演示模式 |
| 手机扫码打不开 | 给评委口述 URL，或展示 扫码体验.html 页面上的完整链接 |
| 30 秒感知引擎太久 | 刷新页面 F5 立即触发；或改 config.py 中 `PERCEPTION_IDLE_SECONDS=5` |

## 附录 B · 处理流程展示（可选，时间充裕时使用）

每次 Agent 回复上方有"处理流程"面板，展示 OODA 各阶段卡片：
- Observe — 感知到的环境数据
- Act — 调用了哪个工具、工具返回了什么
- Reflect — 执行了哪些检查

> 🎤 "这不是黑盒——每一步决策都可追溯、可验证。"
