# 真实落地路径一页（WS10.1）—— 社区先知 CommunityInsight

> 讲清"数据从哪来、谁来运营、怎么保服务、试点怎么谈"。**诚实呈现 = 评审加分项。**

## 一、数据从哪来（三个来源，逐级接入）
1. **网格员代录**：前期无系统时，网格员在走访中用本工具录入居民诉求（最低门槛，先跑起来）。
2. **居民自助**：居民端/老年端入口直接上报、提案、一键求助（主力形态）。
3. **物业/12345 导出导入**：物业 Excel 定时导入（`source_adapter.py` 已预留框架，接真实源时补授权与字段映射）。

> 现阶段为演示种子数据 + `DEMO_AUTO_WORKER` 机器人推进的示例数据，**不代表真实成效**；接入真实数据后口径才可信。

## 二、谁运营
- **运营方**：社区居委会（主导）+ 物业（工单闭环）+ 街道（监管/看板）。
- **我们的角色**：提供系统 + 培训 + 陪跑（首月每周现场）；网格员负责裁决，AI 负责预处理与减负。

## 三、SLA 与服务承诺（对街道/社区）
- 可用性：目标 99.5%（单机演示级，多副本需状态外置/PostgreSQL/Redis，见文档长远项）。
- 响应：居民诉求 AI 即时响应；转人工工单按社区值班机制 <24h 处理。
- 数据安全：PIPL 合规（同意/加密/导出/注销）、等保三级、数据不出域（私有化部署）。

## 四、试点意向（诚实呈现）
- 拟对接：**1 个社区试点** + 1 个物业试点；目标先跑通"居民上报 → AI 分类 → 人工处理 → 回访"真数据闭环。
- 当前状态：**意向/访谈阶段**（如已有接触访谈记录/意向书请在此注明；没有就写"规划中"）。

## 五、试点实施计划（90 天）
1. W1–2：私有化部署 + 真数据导入（网格员代录启动）+ **属地登记**（社区名单、行政区划、账号归属；属地来自账号而非定位，**不需要居民授权定位权限**）。
2. W3–4：网格员培训 + 运营规则（转人工阈值/停机点）+ **本地政策语料梳理**（把街道/社区现行政策摘要入库并标适用地区）。
3. W5–8：试运行 + 数据回访（满意度、自转率、超时率看板）。
4. W9–12：复盘 → 扩展 2–3 个楼栋/片区。

## 六、需要确认的边界
- **不替代政务平台**：做居民侧入口与协同，不碰城市大脑的全局治理。
- **LLM 边界**：政策/健康只做"基于已发布知识的生成/提醒"，诊断与法律结论一律转人工（合规底线）。
