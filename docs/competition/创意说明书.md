## 一、项目概述

### 1.1 项目名称

**校园先知 · CampusInsight Agent**

### 1.2 一句话描述

让每个学生都能"知校园事、报校园修、议校园政、督校园治"的 AI 微治理伙伴。

### 1.3 项目定位

面向高校校园的**基层微治理 AI 参与平台**。核心理念：把几万人的校园视为微型社会，用 AI Agent 降低学生参与治理的门槛，用数据透明建立学生对治理的信任。

不是"帮学生管日程"的个人工具，不是"帮管理者看报表"的管理后台——是一个让学生从"被管理者"变成"治理参与者"的桥梁。

## 二、核心创新点

### 2.1 四字架构：知→报→议→督

| 环节 | 板块 | 一句话 | 治理价值 |
|------|------|--------|----------|
| **知** | 🌊 校园脉搏 | 这周发生了什么？下周有什么大事？ | 知情权——不被蒙在鼓里 |
| **报** | 🔧 随手报修 | 发现问题，自然语言描述，AI自动分类上报 | 参与权——我的报修有人管 |
| **议** | 🗳️ 有话说 | 提提案、附议别人、参与AI发起的议题 | 表达权——我的声音被听见 |
| **督** | 📊 治理看板 | 工单进度、提案排行、治理健康度 | 监督权——我看到改变在发生 |

### 2.2 治理工作流引擎

本项目在 LangChain Agent 的基础上增加了预处理和后处理层，用 OODA 的阶段划分来组织这些逻辑——这是区别于普通 Chatbot 的核心差异：

- **Observe（感知）**：巡检天气变化、工单状态、议题热度——不等学生开口，系统先发现问题线索
- **Orient（定位）**：根据用户输入的关键词判断意图——报修？查询？提案？闲聊？——注入对应的角色提示
- **Decide+Act（执行）**：LangChain Agent 自主调用工具——自动分类定级、查重已有提案、检测热点发起议题
- **Reflect（反思）**：安全网检测 LLM 是否跳过了必要的工具调用；追踪工单是否过期、提案是否有进展——**治理要闭环**

### 2.3 降低参与门槛——自然语言即界面

学生不需要学任何操作。用自然语言完成一切：
- "三教二楼男厕所水龙头漏水" → AI自动识别→分类"设施维修"→定级→生成工单
- "我觉得图书馆应该延长到23点" → AI检查是否有相似提案→引导创建或附议已有提案
- "食堂涨价你怎么看" → AI发现这是热点话题→自动发起议题→汇集学生意见

### 2.4 数据驱动信任——治理透明窗

学生能看到：
- 总共上报了多少问题，解决了多少
- 自己上报的问题现在是什么状态
- 自己的提案获得了多少附议
- 校园治理健康度通过三维加权算法实时计算（解决率40% + 平均解决周期35% + 积压趋势25%）

**透明本身就是最好的信任机制。**

## 三、解决的实际痛点

| 痛点 | 严重程度 | 传统做法 | 校园先知的方案 |
|------|----------|----------|---------------|
| 发现问题不知道找谁报修 | 高 | 不知道→算了→没人管→越来越差 | 自然语言描述 → AI自动上报到正确分类 |
| 提了建议石沉大海 | 高 | 投意见箱→没回音→不再提 | 提案+附议→附议达标自动推送→校方回应→学生看到 |
| 不知道校园在发生什么 | 中 | 偶尔看通知栏 | 校园脉搏：每周简报+即将发生 |
| 感觉自己的参与没意义 | 高 | 无反馈→无所谓→不参与 | 治理看板：看到参与数据→感到改变→持续参与 |
| 民意收集靠偶遇 | 中 | 问卷调查→低回收率 | AI自动发现热点→发起议题→对话式参与 |

## 五、Demo 场景

### 场景 1：知 + 报（30 秒）

学生打开应用 → 🌊 校园脉搏显示本周简报 → 发现设施问题 → 自然语言描述 → AI自动分类定级 → 生成工单 → Agent回复："已上报，工单 #043。你的上报让校园更好了一点。"

### 场景 2：议（1.5 分钟）

学生浏览 🗳️ 有话说 → 看到AI自动发起的议题"食堂涨价你怎么看？"→ 表达意见 → 看到别人的提案"图书馆延长闭馆"→ 附议（已有42人附议，校方已回应）→ 自己创建提案"增设快递柜"→ AI检查无重复→创建成功

### 场景 3：督（1 分钟）

感知引擎检测到学生昨天报修的工单状态变为"已解决"→ Agent主动推送反馈卡片 → 学生打开📊治理看板 → 看到本周参与了2次讨论、1次上报 → 治理健康度"良"在读

## 六、竞品对比

| 维度 | 校园App/公众号 | 通用Chatbot | **校园先知** |
|------|--------------|------------|-------------|
| 交互模式 | 填表单 | 一问一答 | **自然语言+主动感知** |
| 参与门槛 | 高（找入口→选分类→填说明） | 无法处理结构化上报 | **低（说话就行）** |
| 闭环反馈 | 无/弱 | 无 | **上报→追踪→解决→通知** |
| 民意收集 | 问卷调查 | 不支持 | **AI自动发现热点+对话式参与** |
| 数据透明 | 不公开 | 无 | **治理看板实时可见** |
| 架构 | 传统MVC | LLM包装 | **OODA治理工作流** |

## 七、社会价值

1. **降低参与门槛**：自然语言上报+提案，让不擅长使用正式渠道的学生也能参与治理
2. **建立治理信任**：数据透明的治理看板让学生看到"自己的声音被听见了"
3. **可复制性**：14个工具均为独立模块，适配不同高校只需更换知识库数据
4. **OODA方法论迁移**：知→报→议→督的四字闭环可迁移至社区治理、企业园区管理等场景
