## 一、5 分钟跑起来

```bash
# 1) 依赖（后端 + 前端）
pip install -r requirements.txt
cd web && npm ci && npm run build && cd ..

# 2) 配置（.env 不进 git；演示姿态可 cp .env.demo.example .env.demo 后填 key）
cp .env.example .env      # 必配 DEEPSEEK_API_KEY；生产另配 WEB_JWT_SECRET / CRYPTO_KEY / CORS_ORIGINS

# 3) 起主服务（首次启动会自动迁移到 schema v46 并灌演示种子数据，约 15 秒）
python -m uvicorn api_web:app --host 0.0.0.0 --port 8000
```

浏览器打开 `http://127.0.0.1:8000/login`。

| 角色 | 入口 | 账号 |
|---|---|---|
| 居民端（14 页） | `/resident/home` | `demo_resident`（免密） |
| 网格员端（9 页） | `/grid/dashboard` | `demo_grid` / `demo123` |
| 老年关怀端（8 页） | `/elderly/home` | `demo_elderly`（免登录） |
| 治理大屏 | `/screen` | 需网格员身份（指标端点按角色锁定） |

> ⚠️ **数据说明**：演示库为**程序生成**的种子数据（225 工单 / 201 提案 / 59 条知识）＋ 演示闭环机器人推进，
> **不代表真实治理成效**；生产环境务必关闭 `DEMO_MODE` / `DEMO_AUTO_WORKER`。

## 三、架构一页

```
Vue3 + Vite + Naive UI 三端（居民 14 页 / 网格 9 页 / 老年 8 页）
        │  HTTP + WebSocket（JWT 鉴权、安全响应头、SPA 托管）
        ▼
FastAPI 主服务 api_web.py（:8000，130 条路由）  ── 另有 api.py 扣子插件入口（:18800，独立）
        ▼
多智能体编排 agent/orchestrator.py
  ├─ 黑板（agent/blackboard.py）：共享上下文 + 消息队列 + 锁 + 历史 → **真协商，非伪多智能体**
  ├─ 9 个声明式角色：接待员 / 报修调度 / 提案协商 / 政策专员 / 健康顾问
  │                  / 天气守护 / 通知管理 / 网格助手 / 合规审计
  ├─ Verifier（agent/verifier.py）：幻觉、敏感词、手机号泄露、医疗诊断句式拦截
  └─ Arbiter（agent/arbiter.py）：合规优先 → 安全 → 专业 → 转人工，决策落 agent_logs 留痕
        ▼
数据与检索
  ├─ SQLite（WAL，schema **v46** 版本化迁移，50 张表）：手机号 **AES-256-GCM 加密落库**
  ├─ 知识库混合检索：59 条（含 40 条公开政策摘要）× 词法(同义/方言扩展) + 语义向量 RRF
  └─ 轻量知识图谱：88 实体 / 199 关系 / 760 提及，工单覆盖率 96%
```

**关键目录**：`agent/`（多智能体）、`api_routes/`（14 路由模块）、`data/`（数据层 + 迁移）、
`web/src/views/{resident,grid,elderly}/`（三端）、`scripts/`（自检/评测/录屏/迁移）、`tests/`（577 项）。

## 四、这一版做了什么（相对早期原型的变化）

1. **架构主线迁移**：Streamlit/LangChain 原型 → **FastAPI + Vue3 三端**（`app.py` 仅存档，非主线）。
2. **多智能体从"单 Agent 反复调用"改为"9 角色 + 黑板真协商"**，并加 **Verifier + Arbiter 双层防线**与全程留痕。
3. **数据安全收口**：手机号全库加密（v46 补齐提案/两张草稿表的遗漏面），**明文计数 0**，账号注销级联清密文。
4. **检索从纯词法升级为混合检索**（语义向量 + RRF），口语金标 hit@1 从 85.7% → **100%**；知识库补 40 条可溯源政策。
5. **可观测**：知识库健康度、关怀量化（情绪/触达率）、LLM 用量记账、trace_id 全链路、轻量知识图谱。
6. **视觉系统 v2 + 无障碍**：设计令牌、三端差异化（老年端大字 ≥20px／热区 ≥72px／只留 SOS 呼吸动效）、暗色达标，
   并用**客观审计**把「好看」变成可复算的数字（26 页 0 违规）。
7. **工程纪律**：v46 把历史遗留的运行时裸 ALTER 全部收回迁移链；对外数字由门禁核对；演示前 9 项自检；6 段兜底录屏。

## 五、已知边界（诚实清单，不藏）

- **LLM 默认按需**：规则优先以保确定性与降本；LLM 用于意图兜底 / 政策生成 / 协商演示，由特性开关控制，可一键关回纯规则。
- **多租户仅预留**：`tenant_id` 字段已加、查询未切（演示级），迁移路径见 `docs/scaling.md`。
- **单机形态**：WebSocket 用内存连接池、限流为进程内实现，多进程/多实例需 Redis（路径已写）。
- **SQLite → PostgreSQL**：迁移路径与前置条件见 `docs/scaling.md`（比赛期不做大重构）。
- **知识图谱不做可视化**：只做「能查得出东西」的链路（按实体反查历史工单/政策），避免评委追问"图谱解决了什么"。
- **Demo 数据非真实成效**：见上文数据说明。
- **`ui_audit` 覆盖 26 个页面/视口**：不是全站逐像素，但覆盖三端主页 + 列表 + 暗色 + 320/390/1366/1440/1920 档。
