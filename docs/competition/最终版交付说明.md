> **比赛**："京彩AI·智汇全球"首都大学生智能体 OPC 创新大赛 · **基层治理赛道**（人文赋能特别奖）
> **版本**：v2.0 定稿（2026-09-14） · 单人参赛（步承泽） · schema v46 · 可运行用例 681
> **形态（先说清楚）**：这是一个**可运行的演示级原型（Demo）**，**不是已上线的生产项目**——演示数据为程序生成的虚构数据，

## 一、5 分钟跑起来

```bash
# 1) 依赖（后端 + 前端）
pip install -r requirements.txt
cd web && npm ci && npm run build && cd ..

# 2) 配置（.env 不进 git；演示姿态可 cp .env.demo.example .env.demo 后填 key）
cp .env.example .env      # 可最小只配 DEEPSEEK_API_KEY（留空则自动降级纯规则，仍可完整演示）
                          # 生产另配 WEB_JWT_SECRET / CRYPTO_KEY / CORS_ORIGINS

# 3) 起主服务（首次启动自动迁移到 schema v46 并灌演示种子，约 15 秒）
python -m uvicorn api_web:app --host 127.0.0.1 --port 8000
```

浏览器打开 `http://127.0.0.1:8000/login`。

| 角色 | 入口 | 账号 |
|---|---|---|
| 居民端（14 页） | `/resident/home` | `demo_resident`（免密） |
| 网格员端（9 页） | `/grid/dashboard` | `demo_grid` / `demo123` |
| 老年关怀端（8 页） | `/elderly/home` | `demo_elderly`（免登录） |
| 治理大屏 | `/screen` | 需网格员身份（指标端点按角色锁定） |

> ⚠️ **数据说明**：演示库为**程序生成**的种子数据（225 工单 / 201 提案 / 6 通知 / 62 条知识）＋ 演示闭环机器人推进，
> **不代表真实治理成效**；生产环境务必关闭 `DEMO_MODE` / `DEMO_AUTO_WORKER`。

**想让人用手机扫码访问（0 成本，评委扫自己的手机）**

```bash
python scripts/serve_public.py     # 起服务（默认只绑 127.0.0.1）+ 公网 HTTPS 隧道 + 刷新扫码页 + 地址进剪贴板
python scripts/probe_public.py     # 对公网入口做 8 项端到端探测
python scripts/serve_public.py --status     # 看当前域名/进程/最近一次探测
python scripts/serve_public.py --stop       # 演示结束立刻关闭公网入口
```

> 方案、6 个已知坑与安全口径见 `docs/演示常开-本机方案.md`。
> **临时隧道无访问控制，拿到链接即可进入，演示完请务必 `--stop`。**
> 校园网 DNS 对新隧道域名可能返回 NXDOMAIN（已内置 DNS 绕行 `scripts/net_probe.py`），手机用 4G/5G 最稳。

**方法学提示（评委常问"你怎么保证质量"）**：本项目把「质量」做成了**可执行的数字**而不是形容词——
UI 用真实浏览器量对比度/热区/字号并卡阈值；检索用 48 条口语金标算 hit@1；数据安全用脚本扫全库；
对外数字用门禁核对代码库；关键路径还做过故障注入验证门禁本身有效。**每一条都能当场跑给你看。**

> **关于「681 项测试」这个数字的口径（主动说明，别等人问）**：
> `681 = 680 通过 + 1 需外部服务默认跳过`。其中 `tests/test_ablation.py` 有 **6 项是给消融报告供数的冒烟项**
> （只跑通、不做断言）；**对外材料真正引用的两个指标另有硬断言测试守住**：
> `test_persona_routing_is_accurate`（断言角色路由准确率 `== 100.0`）与
> `test_tool_discovery_covers_expected`（断言工具无缺失）—— 这两条正是把准确率从 91.67% 拉回 100% 的原因。
> 该口径由 `tests/test_claims_consistency.py` 的白名单门禁守着：**新增任何不做断言的 `test_*` 都会让 CI 变红**。

## 三、架构一页

```
Vue3 + Vite + Naive UI 三端（居民 14 页 / 网格 9 页 / 老年 8 页）
        │  HTTP + WebSocket（JWT 鉴权、安全响应头、SPA 托管）
        ▼
FastAPI 主服务 api_web.py（:8000，130 条路由）  ── 另有 api.py 扣子插件入口（:18800，独立）
        ▼
多智能体编排 agent/orchestrator.py
  ├─ 黑板（agent/blackboard.py）：共享上下文 + 消息队列 + 锁 + 历史 → **真协商，非伪多智能体**
  ├─ 9 个声明式角色：接待员 / 报修调度 / 提案协商 / 政策专员 / 健康顾问
  │                  / 天气守护 / 通知管理 / 网格助手 / 合规审计
  ├─ 16 个工具（自动发现 + 按角色裁剪）
  ├─ Verifier（agent/verifier.py）：幻觉、敏感词、手机号泄露、医疗诊断句式拦截
  └─ Arbiter（agent/arbiter.py）：合规优先 → 安全 → 专业 → 转人工，决策落 agent_logs 留痕
        ▼
属地解析 utils/region.py（**唯一入口，不采 GPS**）
  ├─ 政策：本地优先 + 全国兜底；**属地只改排序，不改"能不能自动回答"**
  └─ 天气：按社区 adcode 取数，居民/老年/Agent 三端口径一致
        ▼
数据与检索
  ├─ SQLite（WAL，schema **v46** 版本化迁移，50 张业务表）：手机号 **AES-256-GCM 加密落库**
  ├─ 知识库混合检索：62 条（61 条已发布，55 条公开政策摘要）× 词法(同义/方言扩展) + 语义向量 RRF
  └─ 轻量知识图谱：89 实体 / 202 关系 / 772 提及
```

**关键目录**：`agent/`（多智能体）、`api_routes/`（14 路由模块）、`data/`（数据层 + 46 个版本化迁移）、
`web/src/views/{resident,grid,elderly}/`（三端）、`scripts/`（自检/评测/审计/录屏/迁移）、`tests/`。

## 四、这一版做了什么（相对早期原型的变化）

1. **架构主线迁移**：Streamlit/LangChain 原型 → **FastAPI + Vue3 三端**（`app.py` 仅存档，非主线）。
2. **多智能体从"单 Agent 反复调用"改为"9 角色 + 黑板真协商"**，并加 **Verifier + Arbiter 双层防线**与全程留痕（353 条 `agent_logs`）。
3. **数据安全收口**：手机号全库加密（v46 补齐提案/两张草稿表/`user_profile` 的遗漏面），**明文计数 0**，
   密钥生产姿态 **fail-closed**（缺失或仍是仓库占位值直接拒绝启动），账号注销级联清密文。
4. **检索从纯词法升级为混合检索**（语义向量 `text-embedding-v3` 1024 维 + RRF），口语金标 hit@1 85.7% → **100%**；
   知识库补到 62 条（55 条可溯源公开政策）。
5. **属地化自适应（本轮新增）**：政策按行政区划本地优先、天气按社区城市、知识库带「适用地区」，
   **三端统一走 `utils/region.py`**，**不采集定位**（网格归属是确定的，不需要也不应该采 GPS）。
6. **可观测**：知识库健康度、关怀量化（情绪/触达率）、LLM 用量记账（`llm_usage` 可逐笔查）、trace_id 全链路、轻量知识图谱。
7. **视觉系统 v2 + 无障碍**：设计令牌、三端差异化（老年端大字 ≥20px／热区 ≥72px／只留 SOS 呼吸动效）、暗色达标，
   并用**客观审计**把「好看」变成可复算的数字（34 个路由页 / 54 个页面视口 0 违规）。
8. **工程纪律**：v46 把历史遗留的运行时裸 ALTER 全部收回迁移链；对外数字由门禁核对；
   静默吞异常门禁（含"假成功必须为 0"）；演示前 9 项自检；7 段兜底录屏（含属地化两社区对比）。

## 五、已知边界（诚实清单，不藏）

| # | 边界 | 影响 | 现状/计划 |
|---|---|---|---|
| 1 | **无真实街道试点、无真实用户数据** | 治理成效**未经验证**，能证明的是"机制有效、可审计" | 试点方案已写清（报修/通知/政策问答/适老 SOS 四项） |
| 2 | **未做非 Chromium 真机测试** | iOS Safari / 微信内置浏览器表现未知；老年端语音在这些环境大概率不可用 | 有降级路径（打字 + 预置短语 + 一键拨号），**待真机验证** |
| 3 | **单进程形态** | 黑板/限流/WebSocket 均在进程内，多 worker 不成立 | 扩容清单见 `docs/scaling.md`（Redis + PG + 会话粘性） |
| 4 | **多租户仅预留** | 3 张主表有 `tenant_id` 字段，查询层未按租户过滤 | 明确声明"预留，未做隔离" |
| 5 | **HTTPS 仅临时隧道** | 正式域名 + 证书 + 访问控制未部署 | `docs/deploy-https.md` 有方案；演示隧道用完即 `--stop` |
| 6 | ~~自由文本 PII 未治理~~ → **已治理（2026-09-24）** | 居民在工单正文/提案/健康咨询里手写手机号、身份证 | `utils/pii.py` 在 **7 处居民可手写写入点**做入库前脱敏（手机号 `138****8000`、身份证保留首 6 末 4）；命中打 warning、**日志不记原文**；`tests/test_pii_scrub.py` 12 用例守住误伤与漏检 |
| 7 | **PWA 只做到"可添加到主屏幕"** | **无 service worker**，不做离网能力，也不宣称 | 刻意取舍：政策/工单缓存过期会误导居民 |
| 8 | **外部系统未对接** | 12345、媒体舆情、真实街道工单系统均为占位/框架 | 已预留接口层，比赛期不接真实系统 |
| 9 | **演示数据是虚构的** | 不代表真实治理成效 | 见上文数据说明 |
| 10 | **密钥派生偏弱** | `SHA-256(CRYPTO_KEY)` 无盐无迭代，无信封加密/轮换 | 计划 HKDF + 每记录 DEK + 轮换演练 |
| 11 | **知识图谱不做可视化** | 只做「能查得出东西」的链路（按实体反查历史工单/政策） | 避免"图谱解决了什么"的追问 |
| 12 | **视觉审计是抽样** | 34 个路由页 / 54 个页面视口，不是逐像素比对 | 覆盖三端主页 + 列表 + 详情 + 暗色 + 5 档分辨率 |
