## 1. 这次观察要回答什么

老年端是"老人一句话诉求 → 智能研判 → 网格员处理 → 反馈"这条闭环的**入口**。
入口如果不成立，后面的研判/校验/协同再漂亮也没用。因此这次观察只回答三个问题：

1. **能不能自己做完**：不靠人教、不靠人扶，能不能把一句诉求提交出去。
2. **做完看不看得懂**：提交后系统"记住了什么"，老人能不能自己复述出来。
3. **愿不愿意再用**：做完之后的主观意愿。

**这次观察不回答**：网格员侧效率、多社区对比、模型准确率（那是 `eval-report` 的事）。
**这次观察不能宣称**：任何"提高了多少"的对比结论——没有对照组。

## 4. 四个任务（按顺序，每位参与者都做）

主试只念**任务原话**，不演示、不指路。参与者卡住时按 §5 的"三级提示"处理，并如实记下级别。

| # | 任务原话（照念） | 观察点 |
|---|---|---|
| **T1** | 「您家里楼道灯坏了，想跟社区说一声。请用这个手机把这个事反映上去。」 | 找不找得到入口；会不会误点其它按钮；能不能自己提交 |
| **T2** | 「刚才您反映的事，系统已经记下来了。请念一下它记的是什么，再说说现在这个事到哪一步了。」 | 确认卡片四个信息块能不能复述；「当前状态」看不看得懂 |
| **T3** | 「您想问一下这个月的养老金什么时候发。请用这个手机问一问。」 | 找不找得到「问一问（小助手）」；会不会误入政策/健康 |
| **T4** | 「要是家里突然有人晕倒，您会按哪个按钮？请指给我看（**先不要真按**）。」 | 能不能找到「紧急求助」；能不能说清什么时候用它 |

> **T4 只指不按**。真触发会发通知、留记录，也会给老人造成心理负担。
> 观察者负责在按下去之前拦住；如果真按了，记进 §7 并按 §8 处理。

**四个任务的边界**（避免把"任务失败"和"系统缺陷"混起来）：

- T1 的"成功"= 诉求提交成功且能在进度页看到这条；**不含**"网格员真的处理了"。
- T2 的"成功"= 能说对 ≥3 个信息块（位置 / 责任范围 / 紧急程度 / 所属社区 / 提交时间 / 当前状态 中任选）。
- T3 的"成功"= 拿到了一段回答（**不判对错**，政策口径由 `eval-report` 评）。
- T4 的"成功"= 指出「紧急求助」并说出一个正确使用场景。

## 5. 三级提示（记录级别，别只记"需要帮忙"）

| 级别 | 主试做什么 | 怎么算 |
|---|---|---|
| **0** | 什么都不做，"您再试试" | 计为**独立完成** |
| **1** | 只重念一遍任务原话 | 计为**口头提示完成** |
| **2** | 指区域（如"您看这一排"），不指具体按钮 | 计为**区域引导完成** |
| **3** | 直接指按钮或替其操作 | 计为**未完成** |

**首次完成率 = 级别 0 的人数 ÷ 参与人数**。用了 1/2/3 级都不算首次完成，
但要在 §6 里单独记清级别分布——"提示一下就会"和"完全做不了"是两回事。

## 8. 安全与伦理

- **T4 只指不按**；真触发「紧急求助」要当场告知参与者这是测试、并按系统流程销掉记录。
- 参与者可随时退出，退出数据一并作废（记进 §7）。
- 全程不录人脸、不录声音；如需录像只录**屏幕**，并单独取得同意。
- 参与者提交的诉求内容是**测试数据**，观察结束后按社区口径清理或标注为测试。
- 遇长者情绪不适立即中止，不做push。
