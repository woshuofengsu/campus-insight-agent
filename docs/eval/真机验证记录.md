## 1. 怎么跑（把真机验证变成 2 分钟的事）

**推荐：走公网 HTTPS 隧道**（一条命令，手机不必和电脑同网，4G 也能开，
而且**语音/播报/PWA 需要安全上下文，非 HTTPS 会被浏览器直接禁掉** —— 用局域网 IP 测语音必然失败）：

```bash
python scripts/serve_public.py          # 起服务 + 隧道，打印 https://xxxx.trycloudflare.com 并生成扫码页
python scripts/serve_public.py --status # 看地址与是否可达
python scripts/serve_public.py --stop   # 停隧道（本机服务继续跑）
```

然后在**真机浏览器**里打开（这个页面里的链接与二维码都指向当前地址）：

```
https://<本轮隧道域名>/device-check.html
```

> **做走查期间电脑不要关、隧道不要停**：免费隧道每次重启域名都会变，二维码会失效。
> ⚠️ **别把真机走查/老人观察指向演示库实例**：演示账号是免密/`demo123`，且库里有 300+ 条脚本生成的工单。
> 给真人用请起 staging 实例（独立库/独立密钥/独立账号，`python scripts/staging_drill.py` 已验证该口径），
> 再让隧道指向它。

局域网方式（无外网时可用，**但语音类项目必然显示"不支持"**）：

```
http://<你的局域网 IP>:8000/device-check.html
```

这一页会现场测出**可客观测量**的部分，并生成一段可粘贴的报告：

| 它测什么 | 为什么要真机 |
|---|---|
| 浏览器识别（微信 / iOS Safari / Android Chrome） | UA 在真机与仿真不同，仿真测不出微信内核 |
| 是否安全上下文（HTTPS）、DPR、触屏点数 | 语音与部分能力在非 HTTPS 下直接被浏览器禁掉 |
| `SpeechRecognition` 是否存在、麦克风权限状态 | 只有真机能给真实权限态 |
| `speechSynthesis` 是否可用、中文语音包数量 | 语音包因系统而异 |
| **无手势直接播报**能否触发 `onstart` | iOS 有"必须用户手势"的历史行为，仿真测不出 |
| 点击后播报是否正常 | 对照上一条，判断"是否需要手势" |
| `tel:` 是否移动端可拉起 | 真机行为 |

> **它不能替代什么**：这页只记录"**这台设备的能力与降级表现**"。
> "**人能不能自己把事办完**"必须真人来点 —— 见 `elderly-user-study-v1.md`。
