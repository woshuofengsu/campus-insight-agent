> 老年人反映问题 → 系统确认 → 网格员接单 → 网格员处理 → 居民查看进度 → 反馈完成

| 环节 | 谁做 | 页面 | 覆盖它的门禁 |

| ② 系统确认（确认卡：六件事 + 技术细节折叠） | 系统 | 同上（提交后卡片） | journey 2 ④d–④h（页面↔接口↔库内三处对账） |

## 三、怎么解冻（**唯一合法路径**）

试点期**原则上不改**。若出现"不改就没法试点"的缺陷（例：老人根本点不到某按钮），按下面走：

1. 写清**为什么非改不可** + 影响面（本文 §五 的变更登记里加一行）；
2. 如果动了结构面（路由/页面/Agent/表/schema）：
   `python scripts/pilot_freeze_check.py --update --force`（脚本会先把"变大了哪些"列出来）；
3. 跑齐门禁：`pytest` · `journey_check` · `grid_gov_check` · `mobile_flow_check` ·
   `demo_flow_check` · `ui_audit` · `mobile_audit` · `preflight` · `ui_style_audit`；
4. **重新冻结**：打新标签（例 `pilot-ui-v2`）并把 `scripts/freeze_check.py` 的 `FREEZE_REF`
   与本文的标签一起改掉——**观察数据只与"同一个标签"内部可比**；
5. 如果观察已经开始，**先记下"第几位老人之后改的"**，后续数据分开统计，不许合并。

> 反面教材（本项目真实发生过）：改注释里的 emoji、删一个 CSS 变量，看着都"无关紧要"，
> 前者被门禁抓到 4 次，后者直接让 4 个页面白字白底（dev-log 六十九）。
> **冻结期改任何东西都要走上面的路径**。

## 六、试点期"隧道入口"守则（**2026-10-06 决策：不搞服务器，直接用隧道**）

用户决定**不买云服务器**，试点/观察的公网入口就用 Cloudflare 免费隧道。
这省掉了 1–3 周的备案等待，但**代价必须写清楚、也必须照做**（否则数据会白采）：

| # | 代价 / 风险 | 必须怎么做 |
|---|---|---|
| 1 | **隧道地址每次重启都会变**（免费版，无自有域名） | **观察期间不要停隧道、不要重启电脑**；一停，老人手里/墙上的二维码全部失效。必须重启时：重跑 `python scripts/serve_public.py`，**重新打印并更换二维码**，并在观察记录里写明"第 N 位之后换过地址" |
| 2 | 电脑必须常开（睡眠/关机即断） | 电源接好、关掉自动睡眠；每天开始观察前跑 `python scripts/serve_public.py --status` 看**服务 ✅ 隧道 ✅ 公网可达 ✅** |
| 3 | 走 Cloudflare 边缘（可能经海外节点） | **真实居民数据会经过第三方 CDN**——TLS 全程加密，但这一点必须在知情同意里讲清；观察期**只放必要信息**（姓名可写"王阿姨"，不写完整门牌与完整手机号） |
| 4 | 公网任何人可访问 `/login` | 真实试点**必须**：`DEMO_MODE=false`（关掉免密演示登录）+ `scripts/bootstrap_admin.py` 建真实账号 + 指向 **staging 独立库**（别把演示库和 300+ 条脚本工单当试点数据） |
| 5 | 家/宿舍网络质量、校园网策略 | 弱网路径已做（超时不谎报成功、有"核对"出口）；真机走查时专门记一条"4G 下打开速度" |
| 6 | 没有访问控制（无 IP 白名单/无口令门） | 试点期把入口当"半公开"看待：可控范围内分发二维码（服务站张贴 / 微信单独发送），**不公开张贴到公网**；发现异常流量立即 `--stop` |

> 上云与备案**不是取消**，只是**推迟**到"试点验证有人愿意用"之后——那时再按
> `docs/deploy/生产部署手册.md` 走一遍（域名 + 备案 + Caddy 自动证书）。
