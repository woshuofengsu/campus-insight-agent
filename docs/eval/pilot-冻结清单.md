## 二、被冻结的**流程**（最小闭环）

> 老年人反映问题 → 系统确认 → 网格员接单 → 网格员处理 → 居民查看进度 → 反馈完成

| 环节 | 谁做 | 页面 | 覆盖它的门禁 |
|---|---|---|---|
| ① 反映问题（说话/打字 → 摘要 → 确认提交） | 老人 | `/elderly/report` | journey 2（缺位置追问→更正→提交）、mobile_flow（语音替代路径） |
| ② 系统确认（确认卡：六件事 + 技术细节折叠） | 系统 | 同上（提交后卡片） | journey 2 ④d–④h（页面↔接口↔库内三处对账） |
| ③ 网格员接单（审核通过 → 派单） | 网格员 | `/grid/work-orders` | journey 1 ⑤⑥、demo_flow |
| ④ 网格员处理（开始处理 → 提交处理结果） | 网格员 | 同上 | journey 1 ⑦ |
| ⑤ 居民查看进度（五步 + 谁做 + 多久 + 是否超时） | 居民/老人 | `/resident/work-orders`、`/elderly/orders` | journey 1 ⑧、mobile_flow |
| ⑥ 反馈完成（满意结单 / 不满意重办） | 居民 | 同上 | journey 1 ⑨⑩ |

问答链路（第二组闭环）：`/elderly/qa`、`/resident/qa` → 结论 + 「查看依据」折叠/暂无法确认 + 人工咨询；
门禁：`rag_eval`（无依据不硬答 8/8）、journey 6（转人工→交接包→领取回复）。

## 三、怎么解冻（**唯一合法路径**）

试点期**原则上不改**。若出现"不改就没法试点"的缺陷（例：老人根本点不到某按钮），按下面走：

1. 写清**为什么非改不可** + 影响面（本文 §五 的变更登记里加一行）；
2. 如果动了结构面（路由/页面/Agent/表/schema）：
   `python scripts/pilot_freeze_check.py --update --force`（脚本会先把"变大了哪些"列出来）；
3. 跑齐门禁：`pytest` · `journey_check` · `grid_gov_check` · `mobile_flow_check` ·
   `demo_flow_check` · `ui_audit` · `mobile_audit` · `preflight` · `ui_style_audit`；
4. **重新冻结**：打新标签（例 `pilot-ui-v2`）并把 `scripts/freeze_check.py` 的 `FREEZE_REF`
   与本文的标签一起改掉——**观察数据只与"同一个标签"内部可比**；
5. 如果观察已经开始，**先记下"第几位老人之后改的"**，后续数据分开统计，不许合并。

> 反面教材（本项目真实发生过）：改注释里的 emoji、删一个 CSS 变量，看着都"无关紧要"，
> 前者被门禁抓到 4 次，后者直接让 4 个页面白字白底（dev-log 六十九）。
> **冻结期改任何东西都要走上面的路径**。
