# 演示常开 · 本机方案（0 成本公网访问）

> 适用范围：比赛评审期 / 答辩演示期，让评委和同学**用自己手机**打开这个系统。
> 决策记录：**不买云服务器**（省 ¥9–40/月），用「自己的电脑当服务器 + Cloudflare 免费隧道」，
> 代价是电脑要开着、地址每次重启会变。本文把这两个代价的**影响和规避办法**写清楚。
> 什么时候该升级到固定域名方案：见 `docs/deploy-https.md`（有域名+证书+访问控制）。

---

## 一、一句话原理

```
手机（任意网络，4G/5G/校园网）
   │  https://xxxx.trycloudflare.com        ← Cloudflare 免费隧道，自动签 HTTPS 证书
   ▼
cloudflared.exe（本机后台进程）  ──►  uvicorn api_web:app  http://127.0.0.1:8000
                                        （Vue3 构建产物 + 130 个接口 + 9 个智能体）
                                            └─ SQLite: data/community_insight.db（50 表 / schema v46）
```

- **不需要**公网 IP、不需要路由器端口映射、不需要域名、不需要备案。
- **不需要**和手机在同一个 Wi-Fi（这点比 `http://10.x.x.x:8000` 强很多）。
- **https 是白送的**，而 https 恰好解锁两个关键功能：老年端**语音播报/麦克风**（Web Speech 需要安全上下文）、
  PWA「添加到主屏幕」（详见 `docs/mobile-deploy.md`）。
- 流量：只走 Cloudflare 边缘，本机只开**一条出站长连接**，无需开放入站端口（校园网防火墙不需要放行）。

## 二、三条命令（全部在项目根目录执行）

```bash
# 1) 一键起：服务 + 公网隧道 + 自动生成扫码页 + 地址自动进剪贴板
python scripts/serve_public.py

# 2) 看状态：服务/隧道是否活着、当前公网地址是什么、公网是否可达
python scripts/serve_public.py --status

# 3) 停隧道（公网立刻失效，本机服务继续跑）
python scripts/serve_public.py --stop
#    连服务一起停：          python scripts/serve_public.py --stop --all
#    只起本机不暴露公网：    python scripts/serve_public.py --no-tunnel
```

`python scripts/serve_public.py` 会按顺序做这几件事（每步都有明确输出，失败会告诉你去看哪个日志）：

1. 检查 8000 端口：**是本服务**就复用；是**别的程序**就报出 PID 并给出 `taskkill` 命令；
2. 起 `uvicorn`（首次约 15 秒，等待 `/api/web/health` 返回身份串 `CommunityInsight Web`，
   **只认服务身份不只看 200**，避免误把别的服务当成本项目）；
3. 起 `cloudflared`，从日志里抓取本轮公网域名，并等到 `Registered tunnel connection` 才算真通；
4. 启动时若本机 DNS 缓存了该新域名的"不存在"（见第五节坑 1），**自动 `ipconfig /flushdns` 重试 3 次**；
5. 生成/刷新扫码页 `.shots/手机访问.html`（二维码 + 三角色进入方式 + 风险提示），
   并打印地址、**自动复制 `https://…/login` 到剪贴板**。
   把 `.shots/手机访问.html` 双击打开，让同学直接扫就行。

演示账号：**居民**点「居民」免密 · **老年**点「老年」免密 · **网格员** `demo_grid` / `demo123`。

两个给人看的页面（都在 `.shots/`，已 gitignore，双击即可打开）：

| 页面 | 用途 |
|---|---|
| `.shots/手机访问.html` | **扫码页**：二维码 + 三角色进入方式 + 风险提示；每次跑一键脚本自动刷新为最新域名 |
| `.shots/mobile/index.html` | **手机端适配画廊**：真机 UA + DPR3 逐页截图（iPhone 390×844 / 安卓 360×800），`python scripts/mobile_gallery.py` 生成，顶部自动带**当前公网 https 地址** |

## 三、让电脑老老实实挂着（已实测本机设置）

用管理员/普通身份跑 `powercfg /q SCHEME_CURRENT SUB_SLEEP` 与本机实测结果：

| 项目 | 当前值 | 含义 |
|---|---|---|
| 在此时间后睡眠（交流电） | `0x00000000` | **从不睡眠** ✅ |
| 在此时间后休眠（交流电） | `0x00000000` | **从不休眠** ✅ |
| 合盖动作（交流电，LIDACTION） | `0x00000000` | **什么都不做** ✅ 合盖继续跑 |
| 在此时间后睡眠（电池） | `0x000000b4` = 180 秒 | ⚠ **拔掉电源会睡**，演示期请插着电 |

结论：**插着电、屏幕可以关掉、盖子可以合上，服务和隧道都不会断**。
若换电脑或设置被改回，一条命令恢复：

```powershell
powercfg /change standby-timeout-ac 0      # 交流电永不睡眠
powercfg /change hibernate-timeout-ac 0    # 交流电永不休眠
powercfg /setacvalueindex SCHEME_CURRENT SUB_BUTTONS LIDACTION 0   # 合盖不动作
powercfg /setactive SCHEME_CURRENT
```

另外两件会"莫名其妙断掉"的事：

- **Windows 更新自动重启** → 所有进程被杀，登录后需要重新跑一次 `serve_public.py`
  （或按第四节设开机自启）。演示前一天建议手动更新完并**暂停更新 7 天**。
- **误关黑窗口/点错** → 用 `--status` 看谁不在，重跑一键脚本即可（已在跑的不会被重复启动）。

## 四、开机（登录）自启

```bash
python scripts/serve_public.py --autostart     # 注册登录自启
python scripts/serve_public.py --no-autostart  # 移除
```

脚本按两条路线自动选择（**本机实测结论**）：

| 路线 | 需要管理员 | 本机实测 | 注册位置 |
|---|---|---|---|
| A. Windows 计划任务 `CommunityInsight-Serve` | **要** | ❌ `ERROR: Access is denied.`（本机无管理员权限） | `schtasks /Query /TN CommunityInsight-Serve` |
| B. 「启动文件夹」隐藏启动脚本 | 不要 | ✅ 已跑通（注册→落地→移除全验） | `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\CommunityInsight-Serve.vbs` |

- **默认不开启**：自启意味着"电脑一登录就自动对外开隧道"，属于安全副作用，要用时再显式打开。
- 自启后公网域名会变：打开 `.shots/手机访问.html`（每次启动自动刷新为最新地址）或跑 `--status` 查看。
- 想彻底不用管，把快捷方式丢进上面那个 Startup 目录效果相同。

## 五、六个已知坑（都踩过，都写进脚本了）

1. **本机报"无法解析主机"，但 nslookup 明明能解析** —— 两层原因，脚本都处理了：
   - ① Windows 对本机刚创建的新域名缓存了 NXDOMAIN → `ipconfig /flushdns` 恢复
     （实测：flush 前 `http=000`，flush 后 `http=200`，耗时 1.47s）；
   - ② **校园网/公司网的解析器直接把新域名判成"不存在"**（上游负缓存或 DNS 拦截，
     flushdns 救不了）。实测对照：校园 DNS(59.64.80.110) 返回 `Non-existent domain`，
     而 `<域名> @8.8.8.8` 立刻给出 `104.16.230.132`。
     脚本已内置兜底：**用 UDP/53 直接问公共 DNS + 本进程改写解析结果**，还能 IP+SNI 直连交叉验证
     （`.shots/logs` 旁边的 `--status` 输出会说明用了哪条路）。
   - ⚠ **对你手机的意义**：如果你手机也连这个校园 WiFi，**很可能同样打不开这个新域名**。
     最稳的是**手机用 4G/5G 流量**打开；或在手机设置里换一个 DNS；或退回局域网方案
     （`python scripts/serve_public.py --lan` + `http://<电脑局域网IP>:8000`，需同一 WiFi 且 http 下没有语音）。
2. **`--status` 说公网不可达** —— 隧道刚建立时边缘路由还在生效，等 5–10 秒重跑 `--status`。
3. **域名每次都变** —— 免费 quick tunnel 的固有行为，没有账号也改不了。
   要固定域名必须"有自己的域名 + Cloudflare 命名隧道"，见 `docs/deploy-https.md`。
4. **端口 8000 被别的程序占了** —— 脚本会指出 PID 并给命令，不会静默失败。
5. **日志在哪** —— `.shots/logs/uvicorn.log`、`.shots/logs/cloudflared.log`（都已 gitignore）。
   出问题先看这两个文件，比截图问我快。
6. **默认只绑本机回环，局域网设备访问不到** —— 这是**刻意的**（复审 F1）：
   cloudflared 隧道是本机出站拨号到 `127.0.0.1:8000`，绑回环隧道照样能用，但校园网/宿舍/公共 WiFi
   里同网段的人就扫不到 `:8000` 了（否则等于对整个局域网免密敞开）。
   实测：`netstat -ano | findstr :8000` 只见 `127.0.0.1:8000 LISTENING`。
   确实需要局域网直连（比如上面坑 1 的退路）再加 `--lan`。

## 六、安全与合规（评委问起来要能答）

- 免费隧道**没有访问控制**：**拿到链接的人都能进**。演示账号在 `DEMO_MODE=true` 下免密。
  所以：**演示结束就 `--stop`**，不要把链接发到公开群；不要把真实居民信息录进去。
- 库里是**虚构种子数据**（`.env` 的 seed 数据：6 条通知、225 条工单、201 条提案，均为演示数据），
  手机号列**已全量加密**（8 张表，`python scripts/audit_phone_encryption.py` 明文计数 0），
  所以即便被外人打开，也**不泄露真实个人信息**。
- HTTPS 由 Cloudflare 提供，手机与电脑之间是加密的；但**演示链路仍是"临时、可被扫到"的**，
  不能当作生产环境的对外服务口径来宣传。答辩口径统一为：「本机演示环境 + 公网隧道」。
- 想对外长期开放（真正给居民用）：换固定域名 + 证书 + 访问控制 + 备案，
  这是一个**独立的部署动作**，不要在本机方案上"凑合当成生产"。

## 七、成本对照（为什么维持现状）

| 方案 | 费用 | 电脑要开 | 地址稳定 | 备注 |
|---|---|---|---|---|
| **本机 + 免费隧道（当前）** | **0 元** | 要 | ❌ 重启会变 | 已跑通、已验证；本文档 |
| 本机 + 域名 + 命名隧道 | 域名 ¥10–30/年 | 要 | ✅ 固定 | 需要域名所有权 |
| 国内云服务器 + 域名 + 备案 | ¥9–30/月（学生机） | 不要 | ✅ | 备案需时间 |
| 香港/境外轻量服务器 | ¥24–40/月 | 不要 | ✅ | 免备案，国内访问质量一般 |
| 免费 PaaS（如 Render 免费档） | 0 元 | 不要 | 半稳定 | 空闲睡眠 30–60s、无持久卷、国内访问不稳 |

结论：**比赛/答辩期间维持本机方案，成本 0**；只有确定要长期对外服务时再买服务器（见 `docs/deploy-https.md`）。
