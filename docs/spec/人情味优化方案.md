# 居民端 / 老年端「人情味」优化施工方案（定稿 v2）

> 目标：让居民端、老年端从"能用、大字、能念"升级到"愿用、暖心、被惦记"。
> 原则：**规则优先、零 LLM 依赖、尽量零 schema 迁移、不破坏现有 499 测试**。
> 适用仓库：campus-insight-agent（FastAPI:8000 + Vue3/NaiveUI 三端 + SQLite v41）。

---

## 0. 先定义清楚：什么叫"有人情味"（验收标尺）

人情味不是加 emoji，是让用户在五个瞬间被照顾到，全部可感知、可验收：

| 感受 | 定义 | 可验收的表现 |
|---|---|---|
| 被看见 | 记得"你是谁、现在什么处境" | 分时段叫出称呼、知道今天降温/该吃药/好久没来 |
| 被理解 | 先处理情绪，再处理事情 | 说"疼/着急/害怕"时先安抚一句，再走流程 |
| 有回音 | 事情进展说"人话"，不是状态码 | "王师傅已接单，下午到，您在家等就好" |
| 被惦记 | 不等指令，主动关心一次 | 办结回访、久未上线提醒网格员问候 |
| 不被指责 | 出错永远不归咎用户、永远有"找人"出口 | "没听清，您慢慢说"，每个空态/错误都能转人工 |

**一条红线**：以上全部用**规则语料**实现，不引入 LLM 生成情感（稳定、可测、零成本、不会说出不合规的话），与项目"规则为骨、LLM 为脑、LLM 默认关"的架构完全一致。

## 2. 总体架构：一个关怀内核，三层落点（不散落、可测试）

```
                 ┌─────────────────────────────────────────┐
                 │  agent/tone.py  （关怀内核，纯函数、零IO） │
                 │  pick() 随机去重 / detect_emotion() 情绪词 │
                 │  empathize() 节点共情 / care_line() 今日关怀│
                 │  human_status() 工单状态人话化             │
                 └───────────────┬─────────────────────────┘
            ┌────────────────────┼───────────────────────┐
   后端编排层 │ receptionist/business_agents 提交·等待·失败·求助  elderly/home 聚合
            │ scheduler tick：办结回访 + 久未活跃
   前端呈现层 │ web/src/utils/warm.js（时段问候/人话映射）  useSpeech 加语速
            │ Home/Medication/Orders/IssueDetail/Report/QA 逐屏
```

- **单一事实源**：所有关怀语料只写在 `agent/tone.py`（后端念的）和 `web/src/utils/warm.js`（前端 toast/标题），禁止再把"暖心话"散落在各 vue/py。
- **会话级去重**：同一会话同一 scene 只共情一次（用 Orchestrator 黑板上的一个 `empathized` 集合），避免"每句都安慰"造成的新机械感。

## 3. 语气设计规范（先立规矩，再写文案）

**人设**：社区里一位耐心、靠谱、语速慢的"社区小助手"；对老人用"您 + 称呼（张阿姨/李大爷）"，对居民用"您"。

**Do**
- 先情绪后事务："听着让人着急，我优先帮您催一下。您的单已经在处理了。"
- 给确定感：说清"谁、大概什么时候、您现在要做什么（通常是什么都不用做，等就好）"。
- 语料 3 句随机轮换，避免复读机。
- 语音单句 ≤ 40 字，数字口语化（"早上 8 点"不念"08:00"），每段都能"再听一遍"。

**Don't**
- 不假亲密：不用"亲/宝/家人们"；不堆砌表情（一段最多 1 个）。
- 不每条都共情（只在 提交/等待/失败/求助 四节点 + 命中情绪词）。
- 不归咎用户：不说"您操作错了/输入不合法"，改"这一步没成功，我们再来一次"。
- 主动语音不打扰：每日主动关怀 ≤ 1 条，**21:00–次日 8:00 不语音播报**（只静默卡片）。
- 关怀文案过 `compliance_auditor` 脱敏，不念完整手机号、不直说敏感病名。

**4.1 新建 `agent/tone.py`（纯函数，可直接单测）**
```python
import random
from datetime import datetime

# 场景语料池（每类 3 句，随机轮换）
LINES = {
    "repair_ok": ["收到啦，您别着急，我这就帮您安排人。",
                  "好的，已经记下了，马上帮您派师傅，您在家等消息就行。",
                  "您放心，单子我接住了，这就走流程。"],
    "wait":       ["正在帮您处理，您稍坐一会儿～", "我盯着进度呢，有进展第一时间告诉您。"],
    "fail":       ["刚刚没太听清，您慢慢再说一遍，不着急。",
                   "这一步没成功，不是您的问题，我们再来一次。"],
    "sos":        ["别慌，我们已经在联系了，您先找个安全的地方坐下。"],
    "done":       ["已经帮您处理好啦，您看看还有没有问题？", "搞定！后续有任何情况随时找我。"],
}
# 情绪词 → 先安抚一句（规则命中即可，不调 LLM）
EMOTION = {
    "疼痛": (["疼", "痛", "摔", "磕", "出血", "扭了"], "您先别乱动，我优先帮您处理。"),
    "着急": (["急", "快点", "来不及", "漏了一地", "冒水"], "听着挺让人着急的，我给您加急。"),
    "害怕": (["怕", "害怕", "一个人", "不敢"], "您别担心，我在呢，这就帮您联系人。"),
    "抱怨": (["怎么还", "又", "投诉", "没人管"], "让您久等了，我这就帮您查清楚。"),
}
HUMAN_STATUS = {  # 工单状态 → 一句人话
    "待审核": "您的上报我们收到了，正在核对",
    "待派单": "已核对通过，正在为您安排负责人",
    "处理中": "师傅已经在处理啦，您在家等就好",
    "待反馈": "处理完了，就等您确认结果",
    "已完成": "这件事已经办结",
    "已驳回": "这条需要再补充点信息，不是不给您办",
}

def pick(scene: str, used: set | None = None) -> str:
    pool = [s for s in LINES.get(scene, []) if not (used and s in used)] or LINES.get(scene, [""])
    s = random.choice(pool)
    if used is not None: used.add(s)
    return s

def detect_emotion(text: str):
    for tag, (words, comfort) in EMOTION.items():
        if any(w in text for w in words): return tag, comfort
    return None, ""

def greeting(hour: int) -> str:
    if hour < 6:  return "夜深了，还没休息呀，注意身体"
    if hour < 11: return "早上好"
    if hour < 13: return "中午好，记得吃饭"
    if hour < 18: return "下午好"
    return "晚上好"

def care_line(*, weather=None, due_meds=0, days_inactive=0) -> str:
    """首页"今日一句关怀"：按 天气 > 用药 > 久未出现 优先级取一条，宁可不弹也不堆。"""
    if weather and weather.get("alert_tags"):
        return "今天天气不太好，尽量少出门，出门一定慢一点"
    if weather and isinstance(weather.get("temp_high"), (int, float)) and weather["temp_high"] >= 35:
        return "今天高温，多喝水、避开正午出门"
    if due_meds: return f"今天有 {due_meds} 次药要吃，我会到点提醒您"
    if days_inactive >= 5: return "好几天没见您啦，一切都好吧？有事随时长按找我"
    return ""

def human_status(status: str) -> str: return HUMAN_STATUS.get(status, status or "")
```

### M3｜用药打卡闭环（需要一次 v42 小迁移，半天，强烈建议，演示高光）

> 现在老人对用药提醒**无法回应**，是"闹钟"不是"关怀"。加"我吃了 / 10 分钟后再提醒"，并给连续鼓励。

**6.1 迁移（严格走 db_core 注册，不裸 ALTER）**：在 `data/db_core.py` 新增
```python
def _m42_medication_intake(conn):
    """v42：用药打卡记录（人情味闭环：我吃了/稍后提醒 + 连续天数）。"""
    conn.executescript("""
    CREATE TABLE IF NOT EXISTS medication_intake_log (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        user_id INTEGER NOT NULL,
        reminder_id INTEGER NOT NULL,
        taken_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
        action TEXT DEFAULT 'taken',          -- taken / snooze
        UNIQUE(user_id, reminder_id, date(taken_at))
    );
    CREATE INDEX IF NOT EXISTS idx_intake_user ON medication_intake_log(user_id, taken_at);
    """)
    conn.commit()
```
并在 `init_db` 的 `post` 列表末尾注册 `(42, "medication_intake", _m42_medication_intake)`；顶部 `SCHEMA` 版本常量同步改 42。

**6.2 数据层 `data/db_elderly_care.py`** 加三个函数：`mark_intake(uid, rid, action)`、`get_intake_streak(uid)`（连续有 taken 的天数）、`get_today_intake(uid)`。

### M4｜主动关怀：办结回访 + 久未活跃（挂现有 scheduler，半天，差异化亮点）

现有 `scheduler.py` 已是 60s 轮询（`api_web.py:90 ensure_scheduler_started`），直接加两个 tick 任务，不引新框架：

**M4 验收**：构造一条昨日完成单，tick 后出现回访通知；构造 5 天不活跃老人，网格员端出现问候提示；夜间不推送。

- 现有文案断言若有精确匹配（如断言"操作过于频繁"），同步更新为新文案。
- 每个 M 完成后：`py -3.12 -m pytest tests/ -q` 全绿 + `py -3.12 -m ruff check .` = 0 + `cd web && npm run build` 通过。

## 8. 排期与"竞赛必须 / 长远"分层

| 批次 | 内容 | 工时 | 层级 |
|---|---|---|---|
| M1 | 关怀内核+问候+今日关怀+语速+全局人话化 | 0.5 天 | **竞赛必须** |
| M2 | 情绪安抚+四节点共情+人话时间轴+兜底人工 | 0.5 天 | **竞赛必须** |
| M3 | 用药打卡闭环（v42） | 0.5 天 | 竞赛强烈建议（高光） |
| M4 | 办结回访+久未活跃 | 0.5 天 | 竞赛加分 / 长远必备 |
| 赛后 | 方言 TTS、服务端 ASR、LLM 个性化共情（仍过 Verifier）、生日/节日（preferences 或 v43） | — | 长远 |

**建议顺序 M1→M2 先合一版（当天就能演示"活了"），M3、M4 各独立提交。**

## 9. 边界：人情味别做过头（反模式清单）

1. 不每句共情、不重复同一句（去重集合兜底）。
2. 不上 LLM 写煽情小作文——政务场景要"稳"，规则语料足够。
3. 主动关怀每日 ≤1 次、夜间静默、可在 preferences 关闭。
4. 语音宁短勿长、可重播；不在关怀语里暴露完整手机号/敏感病情。
5. 不新增多余弹窗；关怀优先用卡片和语音，不打断老人当前操作。

## 10. 现场演示脚本（"独居老人李阿姨"故事线，3 分钟）

1. 早 8 点打开老年端：**"早上好，李阿姨，今天有 1 次药要吃，我会到点提醒您"**（语音播）。
2. 按住说"家里水管漏了一地，急死了"→ 助手先回 **"听着挺让人着急的，我给您加急"**，再完成报修。
3. 切网格员端：看到加急单 + 派单；回老人端工单页：**"师傅已经在处理啦，您在家等就好"**。
4. 到点用药卡弹出，点"✅ 我吃了"→ **"连续 3 天按时吃药，真棒！"**。
5. 演示长按 SOS：第一句是 **"别慌，我们已经在联系了，您先坐下"**，再讲操作。
6. 第二天（造数据）：出现办结回访；网格员端出现"李阿姨 5 天没上线，建议电话问候"。

**答辩一句话立意**："适老化不是把字调大，而是让技术**记得人、体谅人、兜底到人**——我们把'人情味'做成了可测试、可审计、不依赖大模型心情的工程能力。"
