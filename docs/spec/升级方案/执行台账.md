## 0. 执行纪律（本项目既有硬约束，升级期间同样有效）

1. 每批改完必须：`python -m ruff check .` 为 0；`python -m pytest tests/ -q` 全绿（跑测试前**停掉 :8000 服务**）。
2. 改 `web/src` → 必须 `cd web && npm run build`，并重跑 `ui_audit` / `mobile_audit`（两者**需要服务在跑**）。
3. **禁止运行时 ALTER**：加表/加列只走 `data/db_core.py` 的迁移注册表（`_mN_*` + 幂等）。
4. 口径门禁：`check_claims.py` 必须全绿；对外材料的数字只能由 `scripts/sync_test_count.py` 与实测值驱动。
5. 安全类校验 fail-closed；`except` 禁止静默吞异常（有门禁测试）。
6. 每张卡要**留回退点**：能一句话说清"怎么退回上一个可用状态"（git 提交 + 数据备份）。

### 5.2 八条旅程抓到的两个真 bug（2026-09-29，卡12 的"为什么值得做"）

写这条门槛时**当场**抓到两个，都是"文档上说做了、实际用不了"的类型：

1. **老人缺位置时补充后永远提交不了**（`views/elderly/Report.vue` + `api_routes/elderly.py`）
   现象：老人说"楼道灯坏了" → 系统追问楼栋 → 老人填了"19号楼3层楼道" → 点「补充好了，再看一遍」→ **还是那句追问**，
   而且**再也出不来「确认上报」**——两步报修契约在"缺位置"这条路上是**死路**。
   根因：补充值只存在页面 `answer` 里，重查时既没上行（`/report/draft` 只收 `text`），
   又被服务端返回值覆盖；服务端按原话重解析，结论当然还是"缺位置"。
   修法：`/report/draft` 收 `answer_location/answer_scope/answer_urgency`（**服务端照样判合不合用**，
   来源标 `user`）；笼统的补充（"小区"）**说明为什么不收**（`reject_hint`），页面显示并继续追问。
   回归：旅程 2 的 8 项 + `tests/test_elderly_report_api.py`。

2. **连点两下建出两张工单**（`data/db_idempotency.py` + `api_routes/elderly.py`）
   现象：老人在同一帧里连点两下「确认上报」→ **库里两张单、两个工单号**（幂等在并发下失效）。
   根因：原来只有"先查 `recall`、后写 `remember`"两步，两个并发请求**同时查不到** → 各建一张。
   **顺序调用通过完全不等于并发安全**（原来 8 个顺序幂等用例全绿，仍漏掉这个）。
   修法：`begin()` 用 `PRIMARY KEY (scope,key)` 做**原子占位**——只有一个请求能领走，
   另一个"等结果或如实说正在提交中"，**绝不替它再建一张**；`release()` 让"没做成"的编号可重试；
   `state()` 让「查一下」能把"正在提交中"与"没提交过"分开（后者会诱导老人再点一次）。
   回归：`tests/test_report_idempotency.py::test_concurrent_same_token_creates_one_issue`（真双线程）
   + `test_status_distinguishes_in_flight`；**并做了门禁自检**：把 `begin` 换回旧行为，该用例必红（实测 2 张单）。

顺带修掉的第三个（旅程 7 阻塞点）：**第二社区网格员 `demo_grid_cy` 密码为空、登录不上**，
而 `seed_all` 对已存在用户只补手机号、**修不回来**（文档却写着"跑 seed_all 即可"）。
→ seed 现在会**补回缺失的密码**（不动用户自己改过的密码），`demo_preflight` 的账号项也把

| `公积金贷款额度怎么算` | 被《购买北京行政区域内住房申请提取住房公积金》自动回答 | **真失分**：问"贷款额度"答"提取办法"，属相邻业务顶替（张冠李戴） | 需要"**未知业务词检测**"：查询里的具体业务词（贷款额度/补卡）若在**全部已发布条目的标题+关键词里都不存在**，即判"库里没有这件事"→ 转人工。不能只加一个黑名单词 |
| `医保卡丢了去哪补办` | 被《因病致贫重病患者家庭医疗救助》自动回答 | **真失分**，同上（只靠"医保"这个**领域大类词**命中了关键词） | 同上一条；通用做法是把"领域大类词"（医保/社保/公积金/补贴）降级为**不构成主题证据**，但要先证明不会误伤控制组 8 条能答的题 |
| `一个人在家怕摔跤咋办` | 未自动回答（`low_score`） | **真失分但可接受**：库里那条叫《独居老人居家安全与关爱》，问句里一个字都不搭；这是**检索的真实边界**，不是错答 | 加"摔跤/跌倒→居家安全"同义词**能修**，但那正是评测集文件头禁止的「为了表好看去调词表」——**本轮刻意不做**，留作赛后连同人工核对一起改 |

**刻意没做的两件事**（都写在这里，免得下次有人不知道是"想过"）：
① 不为上面两条加"业务词黑名单"（那是拿个例打补丁，不是机制）；
② 不为 1 条口语失分去扩同义词表（评测集头就写着"掉分是结论，不是要调回去的东西"）。
