### 0.1 本轮顺带实测出来的两个真问题（都已修）

1. **`SOS升级` 定时任务从来没跑成过**（安全链路上的静默失效）。
   `scripts/scheduler.py` 里写的是 `get_sos_calls(status="求助中")` —— **没传社区**，
   撞上多租户 fail-closed（`ValueError: 跨用户列表/聚合查询必须显式提供 tenant=`），
   而任务被 `_safe()` 包着 → 只留一条 warning，界面上完全看不出来。
   在**演示库副本**上逐个任务探测确认：16 个任务里就它一个失败。
   修法照 B7（天气联动）的规矩：`utils.tenant.all_tenants()` 按社区逐个判定，
   另外单独统计"无社区归属"的历史行并告警（不静默跳过）。
   同时把任务清单抽成 `scheduled_tasks()` **唯一来源**（`run_all` 与门禁测试共用），
   新增 `tests/test_scheduler_health.py`：① 每个任务在当前 schema 上都要跑得通；
   ② SOS 升级**行为级**验证（11 分钟未响应 → 真的升级并留痕）；③ 按社区隔离。

2. **幂等 fail-open**（评审第一条，我承认是我写错了取舍）。
   原来占位抛异常就返回 `("new", None)` 继续办 —— 而占位失败恰恰最容易发生在
   **库忙/锁冲突**这种并发场景，那正是幂等最该起作用的时刻；此时放行 = 在最需要保护时把保护关掉。
   现在新增 `("unknown", None)` 状态：**拿不到"这件事归我办"的结论就不办**，
   如实回"提交状态暂时无法确认，请点「查一下是否已经提交了」核对，不要重复点上报"；
   人工待办同理（补问/回复会给居民发通知，更不能重复执行）。
   验证：`tests/test_report_idempotency.py` 新增 3 例故障注入（占位抛异常 → 零建单 / `begin` 返回 unknown /
   待办不执行不发通知），并做了**门禁自检**：把 `begin` 换回旧行为，该用例必红（实测：旧行为建了 1 张单）。

## 1. 定位收敛（全部采纳，改的是"讲什么"，不是"删什么"）

**一句话定位**（对内外统一口径）：
> 社区先知是一个**面向老年人的可信社区报事系统**：老人只要把事说出来，系统负责追问与确认，
> 网格员办得下去，居民看得到真实结果。

**四条能力代替"9 个 Agent"作对外表述**（角色数只是事实，不是价值）：
**理解（想办什么）→ 追问（还缺什么）→ 校验（没依据不自动回答）→ 交接（说不清就转真人）**。

- 落点：`docs/competition/答辩问答手册.md` 的答复口径 + 台账/复现指南的定位段落。
- **不做**：不改 PPT（用户明确要求先不动版式）；不在页面上删功能。
- 验收：材料里出现"9 个 Agent"的地方，必须同时给出这四条能力的**对应证据**
  （追问策略测试、拒答评测、人工待办工作台、Verifier/Arbiter 留痕）。

## 2. 功能取舍：**收敛入口，不删代码**（部分采纳）

| 模块 | 处置 | 为什么 |
|---|---|---|
| 老年端报修闭环、进度、SOS、联系家人 | **核心主线，做到极致** | 唯一别人抄不走的产品判断（不确认不落单、来源可解释、结果可核对） |
| 网格员工作台（待审核/待处理/人工交接/超时） | **核心主线** | "办得下去"的证据链 |
| Agent 能力（理解/追问/校验/交接）+ 多租户安全 | **核心支撑** | 机制要能被追问，且要有对照证据 |
| 提案 / 天气 / 健康 / 图谱 / 复杂通知编排 | **降为扩展能力**：首页不突出、演示不展开、PPT 归到"可扩展" | 它们确实不是核心价值，但**删掉会损失已验证的工作量**，且都是可插拔的 |

**明确不采纳**："把提案/健康/天气/图谱删掉或停用"——理由是三条：
① 它们各自有测试与演示数据，删掉是纯损失；② 评审自己也说"不是删除，而是不突出"；
③ 三端共享的数据层与租户机制正是靠它们验证的（例如健康读数跨社区隔离、天气按社区判定）。
**我会做的是**：`/grid/dashboard` 与老年端首页都把"今天要办的事"放第一层，扩展能力收进次级入口。

## 6. 三栏清单（防材料过度承诺，随每批更新）

### A. 已完成（有可复算证据）

  手机 40/40 · 桌面 26/26 · UI 审计 0 HIGH
- 评测口径：两条检索入口分别测、dev/holdout、负收益对照、无证据拒答（8+8）
- 设计令牌同源 + 门禁；定时任务健康门禁

### B. 机制已就位、入口待做（不许说成已完成）

- 证据面板：数据都在返回体里，**页面还没集中展示**
- （2026-09-29 完成）草稿正文服务端化：按 uid 存取的草稿接口 + 前端不再保留正文，共享设备上「改 localStorage 就能看到别人草稿」的路径已消失（mobile_flow_check 有一条守它）

### C. 未验证（缺真实条件）
- 真实老人任务观察（0 位；方案要求 5–8 位）
- iOS Safari / 微信内置浏览器：语音权限、播报、拨号回跳
- 真实模型链路：3 项 deselected + 1 项默认 skip
- 两个社区并行试点的数据隔离与运维
- "100% 命中"的真实泛化能力（样本量不足）
