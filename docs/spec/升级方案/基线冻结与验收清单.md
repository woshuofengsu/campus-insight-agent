# 基线冻结与验收清单（v1，2026-09-29）

> **用途**：任何界面/文案/结构改动**之前**先对一遍这张表。它是"改之前是什么样"的唯一凭据——
> 没有它，改完就说不清"哪些是回归、哪些是新行为"（本项目已经吃过一次：`web/dist` 没重建就审计，
> 得出"修了但没生效"的假结论）。
>
> **纪律**：改任何东西前先问四句（来自外部评审的收敛方案）：
> ① 这块**已有验收证据**吗？② 会不会影响现有**快照/断言**？③ 评委**真看得见**吗？④ 能不能在**比赛周期内**被验证？
> 四句里有一句答不上来，就不要动。
>
> 本文件由 `python scripts/check_claims.py` 的数字口径支撑（第 2、3 节全部可一键复算）。

## 8. 本次冻结时发现的偏差（2026-09-29）

**材料里的结构数字已经漂了好几轮，而且没有任何门禁管它**——这是"数字口径守卫"的一个漏洞：

- 实测发现：`技术实现报告.md`、`演示脚本.md`、`创意说明书-提交版.md`、`最终版交付说明.md`、`README.md`、
  `PRODUCT.md`、`答辩问答手册.md` 里还写着 **schema v51 / HTTP 路由 135 / 业务表 51 /
  54 页视口 / 21 页移动端审计 / 50 个迁移**，而代码实际是 **v52 / 150 / 53 / 58 / 31 / 51**；
- `PRODUCT.md` 还写着"多租户仅预留 `tenant_id`，查询层未隔离"——**B5–B7 早就做完真隔离了**；
- `docs/deploy-keys.md` 的安全处置步骤里引用 `schema v37`（旧账）；
- 处置：**21 + 9 处**逐条改正（历史记录那句改成不带版本号的措辞，不篡改历史），
  并给 `check_claims` **新增 7 类结构数字判据**（schema / 路由 / 角色 / 表 / 迁移 / 视口 / 移动页），
  配一条门禁自检用例（给错数字必须报红、写对不许误报）。

> 这条偏差本身值得记：**"测试数"有人守、"结构数字"没人守**——于是后者静默漂移。
> 评委真去数一遍就是"材料与实际不符"，比少写一个功能更伤。
