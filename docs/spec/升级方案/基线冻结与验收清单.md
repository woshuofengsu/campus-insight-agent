## 8.2 「系统建议 vs 人工最终」的口径纪律（**必须一起写，不许只挑好看的**）

有系统建议 **6** 条 / 窗口期 **306** 单 → **覆盖率约 2%**；这 6 条里 **一致 5 条、人工改过 1 条** → 一致率约 83%。

这组数字**能**证明的：**对照链路已经接上**（提交时记建议 → 人工可改 → 差异可查、可追留痕）。
这组数字**不能**证明的：**分类效果好**。6 条样本的一致率不是准确率——
98% 的工单**根本没有系统建议**（写入侧是 2026-09-29 才补的，历史单为空是预期）。

**对外只能这么说**：

> 当前已建立"系统建议"与"人工最终结果"的对照机制；历史工单大部分没有系统建议，
> 因此**覆盖率仍然有限**，一致率只作参考。

**不许这么说**：~~系统分类准确率 83.3%~~ / ~~自动分类准确率 XX%~~。

四条展示纪律（由 `tests/test_claims_consistency.py` 的三条用例守着）：

1. **覆盖率必须与一致率同时出现**（只报一致率 = 拿一小撮样本冒充全体）；
2. 空建议的工单单独计数（`no_suggestion`），**不算**成"系统建议正确"；
3. 数字必须标"**不用于模型训练/调参**"（本项目没有这条链路）；
4. 演示数据（`scripts/seed_category_demo.py` 造的）要标明"演示数据、不代表真实居民样本"。
