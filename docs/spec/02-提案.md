# 第二部分：提案智能体（最终修正版）

## 一、要完成什么

居民提交提案后，系统生成提案记录并进入负责人审核队列。审核不通过退回修改；审核通过后，居民确认公开或私有。公开提案进入 7 天公示与投票，全体居民可评分，负责人根据平均分排名和实际情况决定是否执行；私有提案不公示、不投票，由负责人手动选择部门转出执行。执行完成后，提案人反馈满意后结束。

核心目标：让居民参与社区治理，提案流程透明公正，执行闭环可追溯。

## 二、谁、什么时候能用

- 启动者：居民本人、家属、负责人（老人可由负责人代报）。
- 启动入口：agent 或网页提交。
- 负责人查看方式：登录后台查看，不实时推送。
- 审核时限：无硬性时限，但建议尽快处理。
- 执行时限：1～2 个月内完成（从审核通过或公示结束决定执行后开始计时）。

## 三、开工前必须拿到什么

必填字段：
- 提案标题（必填，最长 50 字）
- 提案内容（必填，不少于 10 字，不超过 1000 字）
- 提案类别（必填：公共设施/环境卫生/文化活动/安全治理/其他）
- 提案人姓名（必填）
- 联系电话（必填，格式校验）
- 是否公开（必填：公开/私有）

选填字段：
- 所属小区/楼栋（选填，精确到楼栋，不强制房号）
- 附件图片（选填，jpg/png，单张≤5MB，最多 3 张）
- 是否代报（选填，代报人姓名、电话、与提案人关系）
- 是否公开附件（选填，默认不公开。若选择公开，需负责人审核确认不包含个人隐私；公开提案公示期间，附件才会展示给其他居民）

系统自动记录：
- 提交时间
- 审核通过时间
- 公示开始/结束时间（公开提案）
- 提案编号
- 重新执行次数

异常处理：
- 信息不全、格式错误或来源不明：必须追问全部细节后再生成提案。
- 提交时系统崩溃或超时：后台生成草稿，保存 7 天，恢复提交后草稿转为正式提案。
- 居民端提案入口显示"您有未完成的提案草稿"，点击继续填写。
- 附件上传失败：提示"上传失败，请重试"，保留已填文字内容作为草稿。
- 电话格式错误：拦截并提示。

## 四、按什么规矩办

- 提案类别强制选择，不选不能提交。
- 提交时必须选择公开/私有，审核通过后可修改一次，且只能在公示开始前修改。
- 审核通过后，系统通知居民在 7 天内确认公开/私有选择，可修改一次；逾期未确认，系统默认按提交时的选择执行，并留痕，同时自动通知居民"您的提案已按XX公开/私有执行"。
- 公示规则：公开提案公示期 7 天，公示与投票同时进行，全体居民可参与。
- 投票规则：1～5 星评分，一人对一个提案只能评分一次，提案人不能给自己投票；系统以登录账号 ID 判断，一个账号一票。负责人如同时也是居民，可以居民身份投票，同样受一票制限制，投票匿名，且不能查看任何个体投票明细（包括自己的）。
- 投票数据匿名存储：投票记录只保存分数值和投票时间，不保存用户 ID 与分数的关联；用单独的表存储"已投票用户 ID"用于防重复，该表不对任何人可见，仅系统内部使用，不记录分数；系统日志不记录用户 ID 与分数的关联。
- 热度计算：按平均分排名，无人评分排后有评分提案之后，负责人参考实际情况结合票数决定执行。
- 负责人决定执行/不执行时，需填写决定理由，留痕。
- 私有提案：不公示、不投票、不参与排名，直接待执行。
- 审核规则：负责人线上审核，无需电话；不合理情况包括重复提交、类别不符、描述模糊、不属于社区公共事务、违法违规；不通过退回修改重新审核。
- 附件公开审核：附件是否公开在负责人审核提案时一并审核；若提案人选择公开附件且负责人审核确认不含隐私，则公开提案公示期间附件展示；若附件含隐私，附件不公开但不影响提案本身审核通过，审核意见中注明附件处理结果。
- 状态流转（完整）：
```
待审核 → 退回修改（可重新提交，回到待审核）→ 待确认公示/私有 → 公示中/待执行 → 执行中 → 待提案人反馈 → 已完成/重新执行/不予执行/违规下架/已关闭
```
- 公示期内负责人不能提前决定不执行，必须等公示结束。
- 公示开始后，居民不能修改公开/私有属性，也不能修改提案内容。
- 居民在待审核状态可撤回提案：撤回后状态"已撤回"并关闭，可重新打开，回到"待审核"，保留历史记录，居民可修改一次，负责人需重新审核。

### 重新执行规则（重要修正）
- 公开提案不满意重新执行：重新进入公示，公示期缩短为 3 天，重新投票，投票数据清零，防重复表清空，允许之前投过票的居民再次投票，重新执行次数+1。每个提案最多重新执行 2 次。
- 私有提案不满意重新执行：由负责人重新选择部门执行，状态直接回到"执行中"，不公示、不投票，重新执行次数+1。每个提案最多重新执行 2 次。
- 超过 2 次：系统提示负责人"重新执行已超过 2 次，请选择关闭或继续"；负责人选择关闭 → 状态"已关闭"；选择继续 → 再次进入重新执行流程，留痕。

### 补充规则
- 执行完成并通知提案人后，提案人需在 7 天内反馈满意度；逾期未反馈，系统自动标记"已结束"，视为满意，并自动通知提案人。
- 负责人修改提案类别需留痕，修改后不影响已产生的公示数据，但影响后续筛选。
- 若投票功能故障导致公示期内无法投票，故障恢复后公示期顺延故障时长，系统自动计算并通知受影响居民。

## 五、分几步完成

1. 居民/家属/负责人提交提案（强制选类别、公开/私有，填写必填信息）。
2. 系统校验信息完整性和格式。
3. 生成提案，状态"待审核"。
4. 负责人线上审核（含附件公开审核）。
5. 审核不通过 → 退回修改，居民修改后重新提交，回到"待审核"；审核通过 → 状态"待确认公示/私有"。
6. 系统通知居民确认公开或私有，可修改一次；居民确认后：公开 → 状态"公示中"，开始 7 天公示与投票；私有 → 状态"待执行"；逾期未确认，系统默认按提交时选择执行，并通知居民。
7. 公开提案公示结束后，系统自动计算平均分和排名，负责人根据排名和实际情况决定执行或不执行，并填写理由。
8. 公开提案决定执行 → 负责人选择部门转出，状态"执行中"；决定不执行 → 状态"不予执行"，系统通知提案人并显示原因。
9. 私有提案在"待执行"状态，由负责人手动选择部门转出，状态"执行中"。
10. 执行完成，负责人填写执行结果和备注，状态"待提案人反馈"。
11. 提案人反馈满意 → 状态"已完成"；不满意 → 进入重新执行流程（公开：3 天重新公示投票，数据清零；私有：负责人重新选择部门执行，重新执行次数+1）。
12. 重新执行超过 2 次 → 负责人选择关闭或继续，留痕。
13. 提案人 7 天内未反馈 → 系统自动标记"已结束"。

## 六、工具与权限边界

### 居民/家属
- 能：提交提案、查看自己提案进度、修改被退回提案、待审核撤回、待确认阶段修改一次公开/私有、参与公开提案投票（一票制）、查看所有公开提案及排名、对自己提案反馈满意度。
- 不能：修改他人提案、删除提案、查看他人私有提案、查看他人未公示提案、重复投票或修改评分、查看完整留痕、查看他人个人信息、除退回修改和确认阶段外修改已提交内容。

### 负责人
- 能：查看所有提案、审核（含附件公开审核）、修改类别（留痕）、提醒居民确认、查看投票汇总（平均分/评分人数/排名，不查看个体投票明细）、决定执行、选择部门转出、更新状态、填写结果、特殊情况关闭、违规下架、导出（不含个体投票明细）、查看完整留痕、处理重新执行超过 2 次后的关闭或继续决定。
- 查看提案人完整手机号：需二次确认，留痕。
- 负责人可以居民身份投票，同样受一票制限制，投票匿名，投票时不能查看个体明细，后台也不能查看自己的评分明细。
- 不能：删除提案、修改原始内容（类别除外）、代替确认公开/私有、代替投票、代替反馈满意度、跳过待反馈、查看个体投票明细、查看提案人其他隐私。

### 维修人员
- 无系统权限（提案流程中不涉及）。

### AI agent
- 能：接收提案描述、追问缺失或格式错误信息、校验必填项、纠正错别字病句后交居民确认、生成提案。
- 不能：代替选类别/公开私有、代替审核、修改状态、投票、查看隐私。

## 七、标准输出

### 居民提交成功页
- 提交成功提示、提案编号、状态、标题/类别/公开私有/提交时间、告知审核、提示可撤回（仅待审核状态）、详情入口。
- 居民端提案入口显示"您有未完成的提案草稿"，点击继续填写。

### 负责人列表页
- 提案编号、标题、类别、公开/私有、提案人姓名/电话/楼栋（脱敏）、提交时间、状态、操作按钮、筛选搜索、公示倒计时/热度摘要、异常状态原因摘要、重新执行次数（如有）。
- 状态颜色：待审核（黄）、退回修改（红）、待确认公示/私有（蓝）、公示中（蓝）、待执行（蓝）、执行中（绿）、待提案人反馈（橙）、已完成（灰）、重新执行（橙）、不予执行（灰）、违规下架（灰）、已撤回（灰）、已关闭（灰）。
- 公示中的提案显示"剩余X天"；公示结束显示"评分人数：X，平均分：X.X"。
- 不予执行、违规下架状态旁显示原因摘要。
- 导出提案数据：导出字段包含提案编号、标题、类别、公开/私有、提案人姓名（脱敏）、电话（脱敏）、所属小区/楼栋、提交时间、状态、投票人数、平均分、排名、执行部门、执行结果、反馈状态、附件是否公开、重新执行次数；导出文件不含个体投票明细、附件图片、居民其他隐私信息；导出动作留痕。

### 负责人详情页
- 完整字段、附件（仅负责人可见，若提案人选择公开且审核通过，则公示中也可公开）、代报信息、审核记录（含附件公开审核结果）、公示投票数据、执行信息、满意度记录、重新执行记录、完整留痕（默认折叠）。
- 历史留痕默认显示最近 3 条，可展开全部。

### 居民公开提案列表页
- 标题、类别、状态、公示中显示剩余天数和当前平均分/评分人数、执行中显示执行部门、已完成显示执行结果摘要、不予执行/违规下架显示原因摘要、公示结束后显示最终平均分/评分人数/排名。

### 居民公开提案详情页
- 标题、类别、内容全文、提交时间、公示期起止时间、当前平均分/评分人数/排名、投票入口（仅公示中且未投过票时显示）、已投票显示"您已评分：X星"且不可修改、执行部门与结果、附件图片（若提案人同意公开且审核通过，否则不显示）、提案人所属小区/楼栋（仅显示到楼栋，不显示姓名电话）。
- 提案人不能给自己投票，系统提示"不能给自己提案投票"。

### 私有提案反馈页
- 标题、类别、提交时间、执行部门、执行结果和备注、满意度选项（满意/不满意）、不满意需填原因。
- 提示"您的反馈将直接影响提案后续处理，请如实填写"。

## 八、验收标准

1. 提案生成成功：字段完整，附件校验，状态"待审核"。
2. 信息校验有效：缺必填项、电话格式错误、未选公开/私有拦截。
3. 审核通过/退回：审核不通过必须填写意见，退回修改后重新提交，仍由原审核人审核。
4. 撤回与重新打开：待审核状态可撤回留痕；撤回后可重新打开，回到"待审核"，保留历史记录，居民可修改一次。
5. 公开/私有确认与修改：审核通过后 7 天内可修改一次，逾期默认，系统自动通知居民；公示开始后禁止修改。
6. 公示与投票：7 天公示，一票制，提案人不能给自己投；负责人可以居民身份投票，同样受一票制限制，匿名。
7. 投票数据匿名存储：投票记录只保存分数值和时间，不保存用户 ID 与分数的关联；防重复表仅系统内部使用，不记录分数；系统日志不记录投票关联。
8. 热度计算正确：平均分计算正确，无人评分排后。
9. 执行决定与通知：负责人填写决定理由，不执行自动通知提案人并显示原因。
10. 执行完成与反馈：满意度结束/退回，逾期自动结束并通知提案人。
11. 公开提案不满意重新执行：3 天公示投票，数据清零，防重复表清空，重新执行次数+1，最多 2 次。
12. 私有提案不满意重新执行：负责人重新选择部门执行，不公示不投票，重新执行次数+1，最多 2 次。
13. 重新执行超过 2 次：系统提示负责人选择关闭或继续，留痕。
14. 违规下架：强制下架原因留痕。
15. 投票匿名：不显示投票人，导出不含个体投票明细。
16. 附件公开审核：附件是否公开在负责人审核时一并审核，审核意见注明附件处理结果；公开提案且附件公开审核通过，附件在公示中展示；附件含隐私则附件不公开但提案可审核通过，居民端不展示未公开附件。
17. 投票功能故障顺延：故障恢复后公示期顺延故障时长，系统自动计算并通知居民。
18. 全局留痕：完整。
19. 导出功能：字段脱敏，导出留痕，包含"附件是否公开"和"重新执行次数"字段。
20. 查看完整手机号：二次确认留痕。
21. 草稿恢复：居民端提案入口显示未完成草稿，点击继续填写。
22. 负责人投票后不可查看自己的评分明细：后台仅显示汇总。

## 九、停机点

### A 类：系统自动触发，必须留痕，负责人可事后复核
- 提案生成、公示开始与计时、投票数据统计、不执行自动通知、逾期默认公开/私有并通知、逾期未反馈自动结束并通知、投票功能故障顺延自动计算并通知。

### B 类：必须负责人明确批准后才能执行，系统不能自动触发
- 公开提案是否执行（需填写决定理由）
- 私有提案转部门
- 违规下架（需二次确认）
- 特殊情况关闭提案（需二次确认，特殊情况包括：提案人明确放弃、重复提案、违法违规内容）
- 修改提案类别
- 查看完整手机号
- 重新执行超过 2 次后的关闭或继续决定

### 边界确认
- 公示开始后居民不能修改公开/私有。
- 公示期内负责人不能提前决定不执行。
- 公开提案不满意重新执行时公示期 3 天，重新投票，数据清零，防重复表清空，最多 2 次。
- 私有提案不满意重新执行时不公示不投票，负责人重新选择部门执行，最多 2 次。
- 附件是否公开由提案人选择并负责人审核。
- 撤回后可重新打开，回到待审核，可修改一次。
- 投票数据匿名存储，防重复表仅系统内部使用，系统日志不记录投票关联。
- 负责人可以居民身份投票，但不可查看个体明细（包括自己的）。

## 十、异常与留痕

### 异常处理
- 公示开始后修改公开/私有：拒绝并提示"公示已开始，不能修改"。
- 居民给自己提案投票：拒绝并提示"不能给自己提案投票"。
- 反馈时状态不是"待提案人反馈"：提示"当前状态不支持反馈"。
- 投票期间评分未保存：提示"评分失败，请重试"，不记录评分。
- 附件上传失败或超时：提示"上传失败，请重试"，保留草稿。
- 公示期投票功能异常：系统保留已投数据，故障恢复后公示期顺延故障时长，自动通知居民，异常日志记录。
- 提案人逾期未确认公开/私有：系统默认按提交时选择执行，留痕，并自动通知居民。
- 提案人逾期未反馈满意度：系统自动标记"已结束"，视为满意，并自动通知提案人。
- 私有提案不满意重新执行：负责人重新选择部门执行，不公示不投票。
- 重新执行超过 2 次：系统提示负责人选择关闭或继续，留痕。
- 多账号投票风险：第一版暂不强制多账号关联，记录为已知风险，后续版本引入手机号验证或实名认证。

### 留痕规则
- 居民/负责人/系统操作全部留痕，字段含操作人、操作时间、操作类型、操作前值、操作后值、提案编号。
- 负责人可查看完整留痕，居民仅可看自己提案状态变化。
- 投票匿名留痕：只记录"有居民评分"，不记录个体。
- 导出不含个体投票明细。
- 系统异常日志单独保存 7 天。
- 公示记录、强制下架、不予执行、违规下架、重新执行、关闭等必须记录原因、操作人、时间、前后状态。
- 系统日志不记录投票用户 ID 与分数的关联，只记录投票动作。
