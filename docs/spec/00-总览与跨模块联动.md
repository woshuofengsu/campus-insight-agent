# 社区服务智能体 · 最终版定义文档 —— 总览与跨模块联动

> 本文档为用户制定的项目框架与规则（PRD），是开发、验收的唯一基准。
> 共七大模块：报修、提案、天气、疾病预防、通知发布、老年端、政策问答。

## 模块清单

1. 报修智能体（工单闭环：电话核实 → 审核派单 → 处理 → 反馈）
2. 提案智能体（审核 → 公开/私有 → 公示投票 → 执行 → 反馈，含重新执行）
3. 天气功能（实时/预报/极端天气预警/检查任务/缓存降级）
4. 疾病预防（内容发布审核 / 居民健康咨询 / 天气联动提醒）
5. 通知发布（6 类型 / 定时发布 / 紧急通知 / 已读统计）
6. 老年端（极简首页 / 紧急求助 / 语音报修 / 用药提醒 / 联系拨打）
7. 政策问答（知识库审核版本时效 / 自动回答 + 转人工）

# 跨模块联动问题修正报告

## 一、报告概述

本报告总结社区服务智能体七个模块（报修、提案、天气、疾病预防、通知发布、老年端、政策问答）在跨模块联动测试中发现的 11 个问题，以及针对这些问题的修正内容和验证结果。修正完成后，跨模块联动已通过第二轮回归测试，并补充了新增异常例子测试，验证通过。

## 二、问题清单与修正内容

| 编号 | 问题描述 | 涉及模块 | 修正内容 | 验证结果 |
|------|---------|---------|---------|---------|
| 1 | 天气事件边界定义不清晰，联动关闭后"同一天气事件内不再触发"的判定标准缺失 | 天气、疾病预防 | 明确天气事件以预警编号或预警生效时间区间为标识；同一预警编号/区间视为同一事件，解除后再次发布视为新事件 | 通过 |
| 2 | 负责人检查任务结果未校验与天气类型匹配 | 天气 | 填写检查结果时自动带出对应天气类型检查清单，系统校验匹配性，不匹配则拦截并提示 | 通过 |
| 3 | 紧急通知下架后居民端滚动提醒未同步消失 | 通知发布 | 紧急通知下架时，同步从居民端顶部滚动提醒中移除；若仅剩该条，滚动提醒整体消失 | 通过 |
| 4 | 老年端报修草稿恢复入口缺失 | 老年端、报修 | 老年端报修入口增加草稿提示，可继续填写未完成草稿 | 通过 |
| 5 | 老人端紧急求助状态未定义自动刷新机制 | 老年端 | 老人端状态每5秒自动刷新，并在状态变化时主动推送更新 | 通过 |
| 6 | 修改用药提醒审核期间，原提醒到期后新规则是否生效未定义 | 老年端 | 原提醒到期即停止；新规则审核通过后立即生效；审核不通过不再恢复 | 通过 |
| 7 | 修改用药提醒审核期间，暂停/恢复操作对象不清晰 | 老年端 | 暂停/恢复仅影响当前生效的原规则；新规则审核通过前不继承暂停状态 | 通过 |
| 8 | 政策问答语音提问确认超时未定义草稿保留 | 老年端、政策问答 | 确认超时自动取消，但保留转写文本草稿，可重新进入继续提交 | 通过 |
| 9 | 政策通知与知识库版本更新未联动 | 通知发布、政策问答 | 关联知识库更新时，系统提示负责人处理，可选择下架或更新通知 | 通过 |
| 10 | 留痕字段缺少模块来源 | 全局 | 所有留痕增加"模块来源"字段，支持跨模块追溯 | 通过 |
| 11 | 老年端大字版天气数据延迟提示缺失 | 老年端、天气 | 老年端天气页同步显示数据延迟提示，超过30分钟进入缓存降级并语音播报 | 通过 |

## 三、验证情况

1. 修正点回归验证：对上述 11 个修正点逐一回归测试，全部通过。
2. 新增异常例子测试：增加 10 个异常例子测试（天气事件重复预警编号、联动内容强制下架后已展示卡片保留、通知弹窗与滚动提醒同步下架、老年端草稿恢复后再次提交、紧急求助状态自动刷新时网络异常、修改用药提醒审核期间暂停/恢复继承、政策问答草稿删除、负责人忽略政策通知更新提示、跨模块留痕查询、老年端天气数据缓存降级），全部通过。

## 四、结论

跨模块联动测试共发现 11 个问题，已全部完成修正。当前社区服务智能体的跨模块联动功能具备实际开发条件。建议继续关注模块间数据一致性、状态同步及异常恢复场景。
