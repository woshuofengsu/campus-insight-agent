## 2026-09-30 凌晨：老人"说人话"却被判"没听懂/已取消"（实测三处，已修）

**怎么发现的**：用户实测反馈"我保修为啥告诉我无法识别听不懂"。按真实说法跑了一遍老年端小助手接口
（`.shots/_cancel_probe.py`、`.shots/_intent_probe.py`），复现出三个**同一类**问题——
**老人正常说话，系统没接住**：

| 老人说 | 修之前 | 问题性质 |
|---|---|---|
| 「窗户也关不上」（拿到确认卡之后） | "已取消，没有生成工单。" | **静默取消**：老人没说取消，草稿被丢掉，还告诉他取消了 |
| 「我住在五号楼」 | "我没太理解您的意思…" | **补充信息没接住**：这正是用户抱怨的那句 |
| 「我家空调不制冷」「暖气不热」 | 回答今日天气 | **误路由**：故障被当成天气查询 |

**根因**：
1. `RepairDispatchAgent` 的确认分支写的是"不是确认词 → 清空草稿 + 回已取消"——
   把"补充/修正/闲聊"统统当成取消（`agent/roles/business_agents.py`）；
2. 意图识别只看关键词表（`agent/web_agent.py::detect_intent`），"我住在五号楼"没有关键词 → 未知意图兜底；
3. 报修关键词表里没有 空调/暖气/不制冷/不制热，而"热/冷"在天气关键词里，天气又排在后面被先命中。

**修法**（都保守，不动既有语义）：
- 确认阶段改成三分支：**明确取消词**（算了/取消/不要了/先不弄了/不报了/撤了）才取消；
  能抽出**位置或责任范围/紧急程度**这类补充 → 回填草稿并重新出确认卡（并说明"已按您说的更新"）；
  其余一律**重新问一遍**（"还没提交：确认请说「确认提交」，不要了请说「取消」"），**草稿保留**。
- 关键词补齐：同音错字与常见说法（保修/修一下/修一修/闪/打不开/不通/没人清/冻/不响/没反应/异味/积水/松动…）
  与冷热故障（空调/暖气/不制冷/不制热/不热），报修在意图表里排在天气之前，因此不会再被天气截走。

**门禁**：新增 `tests/test_elderly_utterance_coverage.py`——用**真实说法**驱动小助手，
断言"能被理解为报修""确认卡不会被静默取消""明确取消才取消""冷热故障归报修"，
并有自检（把补充信息回填去掉，用例必须红）。
