# 复盘：报修工单在"我的"页面不显示

## 现象

AI 聊天里说了"教三楼灯坏了" → AI 说已上报 → 切到「我的」页面啥也没有。

## 原因（从外到里一共 4 层）

### 第 1 层：缓存没刷新（最终原因）

`ui/cache.py` 里的 `invalidate_issues()` 忘了清 `cached_my_issues` 和 `cached_my_stats`，而且学生聊天页根本没调这个函数。数据库里确实有工单，但页面读的是旧缓存。

改了两处：
- `invalidate_issues()` 补上 my_issues 和 my_stats 的清理
- home.py 每次聊天和快速报修后都调一次

### 第 2 层：地点校验太严

宿舍/教室类报修要求必须有房间号，"宿舍楼2楼"这种不带房间号的就被拦截了。改成只要有地点就放行。

### 第 3 层：安全网没检查工具返回值

之前只要工具被调用了就算成功，不管返回的是成功还是报错。改成先检查返回值，如果是错误就用 fallback 重试。另外安全网的触发条件也有问题——要求 LLM 回复里带"已上报"才触发，DeepSeek 经常不说这几个字。

### 第 4 层：LLM 自己编工单号

DeepSeek 有时候不调用 report_issue 工具，自己编一个工单号返回。安全网兜底。

## 教训

1. **写了数据库就得清缓存**，尤其是"我的"这种个人视图的缓存
2. **工具调了不等于成功了**，得看返回值
3. **别信 LLM**，得有自己的兜底逻辑
4. **校验别太严**，"宿舍楼2楼"也比空着强
