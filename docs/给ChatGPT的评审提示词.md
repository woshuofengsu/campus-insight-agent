# 给 ChatGPT 的评审提示词（复制下面整段给它）

> 用途：让 ChatGPT 对项目做一次**独立的检查与建议**（找问题、挑毛病、给规划），
> 而不是帮你写新功能。与 `docs/给Codex的评审提示词.md` 的区别：
> Codex 那条是**在本机读仓库、能跑命令**的评审；ChatGPT 通常在**网页对话**里，
> 可能读不到你的文件——所以这段提示词写了**两条路**：能读文件就走复算，读不到就明确说"没验证"，
> **不许凭空评价**。那样得到的结论才有意义。
>
> 设计要点（沿用上一份的自律）：
> ① **只读评审**，不许改代码/动库/杀服务；
> ② **不信文档，自己复算**（本项目所有数字都有脚本可核对）；
> ③ **主动列出我自己的短板**，让它去攻，而不是等我自夸；
> ④ 明确要求 **"未验证"必须写出来**，不许拿猜测当结论。

## 附：使用建议（给我自己看的，不用贴给 ChatGPT）

1. **优先走 A 路（能读文件）**：把仓库压成 zip 传给它，或让它读 GitHub 分支；
   让它**跑命令复算**，比让它点评我的描述有用得多。跑不了就要求它列"要什么材料"。
2. 如果它只肯"泛泛点评"（不给 `文件:行号`、不标"未验证"），**直接退货**——那种报告对答辩没有价值。
3. 拿回来的报告按这条处理：**每条结论都先问"证据在哪、能不能我这边复算"**；
   能变成测试的就加测试（本项目所有口号最后都落成 `tests/` 里的门禁），不能复算的就降级成"待验证"。
4. 它的建议**不要直接照抄进材料**：先判断是否与"不许编造/不许宣称没验证的能力"这条底线冲突。
