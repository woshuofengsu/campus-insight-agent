# 《社区治理多智能体平台》全维度评测方法论（可复用）

> 目标：让「质量检测报告」可重复执行——每次大版本改动后，按本文档方法重新检测、
> 更新报告（V4/V5…），用 `scripts/review_score.py` 复算总分并对照历史版本。
> 历次结果：V1 7.03/B → V2 7.62/B+ → V3 8.25/A-。

---

## 一、评测对象与范围

| 项 | 说明 |
|---|---|
| 代码 | agent/（9 角色 + 黑板/仲裁/校验/编排）、api_routes/（路由模块）、data/（数据层）、web/src/（Vue3）、scripts/、utils/ |
| 测试 | 全量 pytest（当前 423 passed）+ scripts/llm_eval.py（20 条评测集）+ 压测（数据层/API/Agent 三层） |
| 文档 | docs/spec/（00-14 + dev-log）、docs/review/（历次检测/升级报告）、docs/deploy-https.md |

## 二、12 维度与权重（固定，不随版本变）

| 维度 | 权重 | 说明 |
|---|---|---|
| A. Agent 架构设计 | 18% | 角色建模/协作机制/编排/上下文/热插拔 |
| B. 业务闭环完整性 | 18% | 7 业务模块闭环/舆情/数据简报/红黑榜 |
| C. Agent 能力质量 | 15% | NLU/幻觉防线/注入防护/评测集/转人工 |
| D. 数据与智能 | 10% | 聚类/趋势/自转率/评测回流/向量图谱 |
| E. 用户体验 | 8% | 异常屏/批量操作/主动提醒/无障碍 |
| F. 工程质量与部署 | 8% | 测试/CI/模块化/链路追踪/部署文档 |
| G. 安全与合规 | 6% | 加密/PIPL/注入/HTTPS/敏感数据迁移 |
| H. 成本与性能 | 5% | LLM 成本/规则优先/压测/模型路由 |
| I. 产品价值与竞争力 | 5% | 治理深度/真实数据/商业模式 |
| J. 演示与表达 | 4% | 执行链可视化/大屏/录屏/异常脚本 |
| K. 团队与执行 | 3% | 交付密度/评审闭环/可持续性 |
| L. 风险扣分 | -10~0 | 单项风险合计（安全/依赖/合规/基建） |

总分 = Σ(维度分 × 权重) + L。等级：≥9.0 S / ≥8.0 A- / ≥7.5 B+ / ≥7.0 B / ≥6.0 C。

## 三、检测步骤（每次复测按此执行）

1. **基线数据收集**：
   - `git log --oneline`（本版本改动范围）
   - `python -m pytest -q`（全量测试数）
   - `python scripts/llm_eval.py`（评测集跑分，CI 已接入）
   - 代码规模统计（api_web.py 行数、api_routes/ 模块与端点数、agent/data/web 文件数）
   - 真实库抽查（schema_version、敏感字段明文情况、自转率/红黑榜 live 数据）
2. **逐维度核查**：对照 12 维度检查清单（见下），记录 ✅/❌ 与依据；变化维度标注相对上一版的分差原因。
3. **问题清单整理**：新发现/未解决/决策保留三类，标 ID、优先级、维度、工作量。
4. **评分**：跑 `python scripts/review_score.py`（输入各维度分，输出总分与等级）。
5. **产出**：更新《项目质量检测报告-VN.md》+《建议升级报告-VN.md》+ 本文档「历次结果」行 + dev-log 补记。

## 四、逐维度检查清单（速查）

- **A**：角色元数据/工具白名单/停机点？黑板消息协议/锁/历史？协商是链式多轮还是单轮？循环防护？状态落库？热插拔？
- **B**：报修（合并/仲裁/超时/满意度）？提案（公示/投票/执行）？天气/健康/通知/老年/政策闭环？舆情/红黑榜/自转率？
- **C**：方言/指代/否定 NLU？Verifier 四规则？注入 6 类？转人工 5 类触发？评测集通过率？
- **D**：聚类/趋势/简报？用量统计？自转率？bad case 回流是否可跑？
- **E**：异常屏 4 态？批量操作？主动提醒？转人工「不用重说」？
- **F**：测试数/CI 步骤/traceId 链路/路由模块化（api_web 行数）/部署文档？
- **G**：加密迁移覆盖哪些表？PIPL 三件套？HTTPS 三档？敏感列有无明文残留？
- **H**：规则零 LLM？用量统计？压测结果？模型路由？
- **I**：治理深度叙事？真实试点数据？商业模式？
- **J**：执行链可视化？大屏指标？录屏/异常脚本？
- **K**：评审问题闭环率？dev-log 可追溯？
- **L**：LLM 依赖/敏感数据残留/测试 flaky/合规演示化 各扣多少？

## 五、评分脚本用法

```bash
python scripts/review_score.py                       # 交互输入 12 维分数 → 总分/等级
python scripts/review_score.py --scores 8.5 9.5 8.5 7.5 8.5 9.5 8.0 8.3 7.8 8.8 7.0 --risk -0.3
python scripts/review_score.py --history             # 显示 V1/V2/V3 历史对照
```
