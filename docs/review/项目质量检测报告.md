## 一、一页纸执行摘要

**总分：7.03 / 10 —— B 级（良好，有明确竞争力，需重点加固）**

**一句话总体评价**：这是一个「数据层与业务闭环远超 Demo 水平、Agent 层尚处规则引擎水平」的参赛项目——7 模块状态机、留痕体系、调度器自动任务、373 项测试和并发压测做得扎实，但「多智能体」名实有差距，真实形态是「单主编排 Agent + 11 工具 + 规则降级 + 定时调度器」。

**三大核心亮点**
1. **业务闭环与留痕体系完整**：7 模块状态机（报修 11 态/提案 14 态）、activity_log 全量留痕、调度器 22 类自动任务（超时升级/预警检测/逾期自动结束），OODA 自转骨架真实存在且被测试覆盖。
2. **工程质量与测试意识远超同类参赛项目**：373 项测试全绿、并发压测 550 请求零失败零锁冲突、双架构（FastAPI+Vue3 主 + Streamlit 备）、dev-log 分阶段记录、权限加固与越权修复有完整批次记录。
3. **三端体验与适老化完成度高**：居民端（Agent 聊天/底部标签栏）、老年端（大字/语音优先/长按求助/60s 语音）、网格员端（深色工作台/AI 助手侧栏）分层清晰，UI/UX 规范已落地。

**三大最紧急问题**
1. **P1-A1-01「多智能体」名实不符**：实际是单 CommunityAgent + 工具调用，无 Agent 间协商/黑板/消息协议；Agent 角色与权限散落在代码中，无结构化定义文件。
2. **P1-C4-01 LLM 幻觉无防线**：一旦配置 DEEPSEEK_API_KEY 启用 LLM 主链路，政策/工单回答可能编造，当前无检索引用强制、无回答校验器接入主链路、无 LLM 输出评测机制。
3. **P1-G1-01 数据安全演示级**：居民手机号等敏感字段 SQLite 明文存储、演示密码弱、无 HTTPS 强制、附件明文本地存储，与《个人信息保护法》要求存在差距。

**一句话改进方向**：把「能用 Demo」推成「敢接真实数据」——补 Agent 角色结构化、LLM 幻觉防线、数据加密与合规三件事，其余按路线图推进。

## 三、逐维度详细检测

### A. 多 Agent 架构设计（6.5/10）

**A1 Agent 角色建模**
- ✅ 有角色人格与降级体系：`agent/prompt.py`（detect_persona）、OfflineAgent/CommunityAgent 双实现、老年端「社区小助手」等。
- ❌ **角色未结构化**：Agent 职责/权限/边界散落在 engine.py、web_agent_service.py、tools/ 各文件，无独立角色配置文件或 system prompt 清单；新增角色需改代码。
- ❌ **无能力清单声明**：每个 Agent 能调哪些工具/访问哪些数据无集中声明；LangChain 侧 `discover_tools()` 全量暴露工具，权限靠外部角色判断，Agent 层自身无工具白名单。
- ⚠️ 协调者：`CommunityAgent`（engine.py）充当主编排，调度逻辑在代码内硬编码 + planner 规则模板，无可视化编排配置。

**A2 协作机制**
- ❌ **无 Agent 间通信协议**：没有消息队列/结构化消息格式/黑板；所谓「多智能体」是单 Agent 顺序调用工具，工具间通过函数返回值传递，无共享全局状态。
- ❌ **无冲突解决机制**：多个结论矛盾时无仲裁层；verifier.py/reflection.py 存在但未挂入主链路（仅反思单次输出）。
- ✅ 任务分发：tools/ 按业务模块划分清晰（报修/提案/查询），router.py 有 VALID_TOOLS 白名单。

**A3 编排与调度**
- ✅ 集中式编排 + 定时调度器双轨：`scripts/scheduler.py run_all()` 挂多模块自动任务，api_web lifespan 启动（此前批次已修复 Web 部署不跑调度器的问题）。
- ❌ 编排硬编码：新增业务流程需改代码；无暂停/恢复/回滚；超时处理靠调度器兜底任务，Agent 调用链无超时熔断。
- ⚠️ 单点：CommunityAgent 是所有 LLM 对话的唯一入口，其性能/可靠性即系统单点（当前离线模式规避）。

**A4 扩展性与可插拔**
- ✅ LLM 底座可换：engine.py 走 `ChatOpenAI`（OpenAI 兼容协议）+ DEEPSEEK 配置，换模型只改配置；无 key 自动降级 OfflineAgent。
- ❌ 无热插拔/无同角色多实例（会话按 uid 内存 dict，多实例会丢状态）；场景迁移（养老/园区）需改 tools+prompt+调度，成本中。

**A5 上下文与记忆管理**
- ✅ 有 MemoryManager（agent/memory.py）+ 短期会话 + 数据库长期记录（agent_dialogs/activity_log）。
- ❌ Web Agent 会话状态存**进程内内存 dict**：重启丢失、多 worker 部署会串/丢会话；无截断策略之外的摘要压缩。
- ⚠️ 注入风险：engine.py 的 LLM 链路无 Prompt 注入防护（系统提示与用户输入无隔离）；Web 规则引擎无此风险（不经过 LLM）。

### B. 业务闭环完整性（8.5/10）——本项目最强维度

**B1 知**
- ✅ 定时巡检：调度器每分钟/定时刷新天气、预警检测、健康联动、政策到期、通知定时发布。
- ❌ 数据源单一：以天气 API + 内部业务数据为主；无政务公开/网络舆情采集源（tools/query_community_pulse 是模拟舆情）。
- ⚠️ 推送精准度：WeatherBanner/紧急通知按角色推送，但无「千人千面」内容个性化。

**B2 报**
- ✅ 全生命周期：报修 11 态状态机 + 超时升级（get_overdue_issues/mark_issue_overdue_notice）+ 满意度闭环 + 居民实时进度（IssueDetail 时间线）+ 自动分类（_llm_classify 关键词降级）+ 紧急插队语义识别。
- ✅ 权限与脱敏：批次 9/14 修复了 action 越权、草稿归属、手机号脱敏。
- ❌ 跨部门争议仲裁：transfer_issue 仅标记「已转出」，无 A/B 部门互推的仲裁流程。
- ❌ 重复上报未合并：同地址同描述不自动去重。

**B3 议**
- ✅ 提案 14 态 + 匿名投票一票制 + 公示期匿名议论（proposal_comments，批次 1）+ 决定执行/满意度反馈/重新执行闭环。
- ✅ 讨论秩序：敏感词拦截、状态限制议论。
- ❌ 无「热议事」自动发现（讨论中高频共识/分歧的语义聚类）。

**B4 督**
- ✅ 指标与看板：Screen.vue 治理大屏（30s 刷新）、统计/高频/阈值、异常日志独立表、待办红标、导出留痕。
- ❌ 数据叙事弱：看板以数字为主，无「环比上升 X% 集中在 Y，建议 Z」的洞察层；无红黑榜；无满意度下钻到具体工单的现成链路。

**B5 OODA 自转**
- ✅ 真实自转骨架：调度器自动执行「观察（刷新）→ 判断（规则/降级）→ 决策（发通知/建任务/告警）→ 行动（落库/通知）」，22 类任务有日志。
- ❌ **假自转风险**：全部为规则/关键词判断，无 LLM 参与的自主决策闭环；人工处理方式不回流学习；自转率无量化统计。

### C. Agent 能力质量（7.0/10）

**C1 NLU**
- ✅ 规则级意图识别（居民 9 类/负责人 5 类/老年 6 类）+ 错别字纠正（先确认）+ 紧急语义 + 情绪安抚 + 多意图取首；有 test_agent.py 13 项与 test_semantics.py 覆盖。
- ❌ 无方言/指代消解（「那个东西」不支持）；否定/模糊表达处理有限。

**C2 任务规划**
- ✅ planner.py 规则模板（复合查询拆步）；Web Agent 追问状态机（报修分类→紧急→确认）。
- ❌ 无断点续跑；规划不可视；失败不自动重规划（降级即终止）。

**C3 工具调用**
- ✅ tools/ 11 工具与数据层一一对应；router.py 白名单；工具失败有日志。
- ❌ 无工具级权限矩阵（谁可调哪个工具由 API 层角色判断，Agent 层无）；无工具调用成本统计。

**C4 回答生成**
- ✅ 离线模板回答基于真实数据库数据（OfflineAgent 注释明示「所有回复基于数据库真实数据」），**无幻觉**——这是当前最大安全点。
- ❌ **LLM 链路无防伪**：若配置 key 启用 CommunityAgent，政策类回答无「引用强制 + 校验器」，幻觉风险真实存在且无评测。
- ⚠️ 政策回答来源：knowledge_base 有依据字段，但 LLM 回答不强制携带引用。

**C5 多轮稳定性**
- ✅ 状态机多轮（追问）稳定；test_agent 覆盖；会话按 uid 隔离不串线。
- ❌ 跨会话记忆仅靠 agent_dialogs 列表，无摘要；内存会话重启丢失。

**C6 异常降级**
- ✅ LLM 无 key 自动降级 OfflineAgent；天气失败走缓存降级并标注时间；提交失败保留草稿；防重复提交。
- ❌ 无 LLM 超时重试/限流排队提示；无输出格式解析容错层（若 LLM 输出非 JSON）。

### D. 数据与智能（6.5/10）

- ✅ 数据治理：40+ 表 schema 迁移至 v30、activity_log/exception_log 分表、留痕字段完整（操作人/时间/前后值/模块）。
- ✅ 智能分析基础：get_frequency_stats（趋势/高频/匹配失败/无帮助）、get_overdue_issues、预警检测规则。
- ❌ 无向量库/语义检索（RAG 为关键词检索）；无知识图谱；无趋势预测；热点=词频非语义聚类。
- ✅ 看板分层：总览（Screen.vue）→ 管理页 → 明细（详情页/留痕）；有导出。

### E. 用户体验（8.0/10）

- ✅ 居民端 3 步内上报（Agent 语音/文字→确认→提交）、底部标签栏、草稿恢复、消息中心。
- ✅ 老年端 WCAG AA（字号≥20/按钮≥60/行距1.8/语音优先/长按求助/10s 超时取消）。
- ✅ Agent 人设与温度（欢迎语/礼貌回复/情绪安抚）。
- ❌ 转人工无上下文同步（Agent 对话不带给人工）；无主动服务提醒（「工单超 24h 帮您催办吗」无触发）。

### F. 工程质量与部署（7.5/10）

- ✅ 373 测试（单元+集成+端到端+消融+语义+派单+Agent）、并发压测 550 零失败、页面冒烟、dev-log 分阶段。
- ✅ 分层清晰（data/ 数据层 → tools/ → agent/ → api_web.py → web/）。
- ❌ api_web.py 1980 行单体，路由/校验/导出/上传全在一文件；无 CI/CD；无统一 lint 配置证据。
- ✅ 部署有 Dockerfile.web（uvicorn 单容器 + healthcheck）；配置经 config.py 环境变量。

### G. 安全与合规（6.0/10）

- ✅ JWT（stdlib HMAC）、手机号/姓名脱敏、详情属主过滤、action 角色校验、紧急通知白名单、导出留痕、敏感词拦截（批次 9/14 大量加固）。
- ❌ 敏感字段 SQLite **明文存储**（无加密）；演示密码弱（demo123）；本地 HTTP 无强制 HTTPS；附件明文本地文件。
- ❌ PIPL/等保未闭环：无隐私政策页面、无数据删除/导出居民自查入口、无算法备案（LLM 接入后）。
- ⚠️ Prompt 注入：LLM 链路无防护（见 A5）。

### H. 成本与性能（7.5/10）

- ✅ 离线模式零 LLM 成本；压测 avg 响应（工单创建 400ms/Agent 聊天 287ms）；SQLite 锁冲突 0。
- ❌ 接 LLM 后无 token 成本预算/缓存/分级模型策略/成本告警。
- ⚠️ 健康咨询创建并发 avg 2.5s（SQLite 写竞争），大数据量导出无分页验证。

### I. 产品价值与竞争力（7.0/10）

- ✅ 真实问题：基层治理「报/议/督」确有痛点；对现状（12345/微信群）有明显增量（闭环+留痕+数据）。
- ✅ 场景壁垒：垂直状态机/留痕/适老深度非通用 Agent 模板能抄。
- ❌ 无真实社区试点数据；商业模式/回款策略未展开；多社区多租户未实现（固定单社区）。

### J. 演示与表达（8.0/10）

- ✅ 素材强：三端 27+ 页、Agent 聊天、治理大屏、语音报修、长按求助、匿名议论——Wow 点足。
- ❌ 无异常路径演示脚本；无录屏兜底；文档存在「AI 味」排比风险（需自查）。

### K. 团队与执行（6.0/10）

- ✅ 单人完成 373 测试 + 双架构 + 全模块，执行密度极高。
- ❌ 无行业/政务经验背书证据；覆盖 7 模块 + 1200+ 行 api_web 单体，长期维护风险；「一人公司」在答辩中会被追问分工与可持续性。

## 五、亮点与最佳实践

1. **留痕先行**：activity_log + exception_log 分表、7 天清理、导出留痕——比多数参赛项目成熟。
2. **降级哲学**：LLM 无 key → OfflineAgent → 规则 → 缓存降级，全链路有兜底，演示永不崩。
3. **权限加固批次化**：越权问题被审查发现后系统化修复（批次 9/14），有完整回归。
4. **适老细节**：长按 3 秒求助、10 秒超时取消、60s 语音、播报重试 3 次——真实站在老人角度。
5. **文档纪律**：dev-log 分阶段 + spec 落盘 10 份，可追溯性强。
