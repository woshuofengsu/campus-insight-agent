一、一页纸执行摘要

一句话总体评价：V2 列出的 3 项 P1 硬伤全部闭环（api_web 拆分、草稿落库、存量加密+HTTPS）， 7 项 P2/P3 问题落地 5 项（真协商/红黑榜/批量操作/traceId/自转率/评测集），代码规模可控 （api_web 227 行骨架 + 14 路由模块 118 端点），423 测试 + 20 条评测集满分—— 「演示级完备」已实质性推向「可上线工程」。

三大核心亮点

① 工程质变

api_web 2400+ 行单体 → 227 行纯装配骨架 + 14 模块；traceId 全链路（请求→业务留痕→Agent 留痕→异常）；423 测试 + CI 五步流水线。

② 能力闭环可度量

真协商（一次输入内天气→健康→通知三 Agent 多轮往返）+ NLU（方言/指代/否定）+ 20 条 golden 评测集满分——「AI 能力」从演示叙事变为可量化证据。

③ 治理深度上台阶

红黑榜（表扬/鞭策双向）+ 满意度下钻到单工单 + 批量派单/关闭 + AI 自转率 62%（真实库实测）——「AI 治理」不是花架子。

三大最紧急问题（已降级）

① P2-G1-03 工单快照 phone 明文

user_profile / emergency_contacts 已加密，但 community_issues 的 reporter_phone / assignee_phone / agent_phone 三列仍明文——G 维度最后一块。

② P2-B1-02 舆情外部源未接

auto_ingest 占位，12345 API / 媒体抓取无真实源。

③ P1-D3-02 LLM 实测缺位

评测集为规则引擎满分；真实 DEEPSEEK key 未接入，LLM 幻觉防线缺实战样本。

一句话改进方向：补工单快照加密（收尾 G 维度）→ 接真实舆情源与 LLM 实测（从演示走向试点）。

三、逐维度检测（V2 问题闭环情况与剩余硬伤）

A. 多 Agent 架构 8.5（+0.5）

  • ✅ A2 真协商落地：orchestrator._drain_negotiations 链式多轮——一次用户输入内天气→健康→通知三 Agent 消息往返（健康确认→天气升级→通知草稿），跳过 receptionist 防轮次误累加；循环防护（单目标 2 轮 + 遍历 5 次）保留。
  • ✅ A1 角色建模结构化（9 声明式角色/工具白名单/停机点）+ A3 编排（执行链/超时重试/锁冲突）+ A5 上下文（会话落库 v31 + 草稿落库 v35 + 转人工包快照）。
  • ❌ A4 无热插拔/同角色多实例；黑板内存不跨 worker 共享（state/draft 均已落库缓解）。
  • ❌ 真协商为规则驱动剧本，非 LLM 自主协商（接 key 后由 prompt 承担，评测集已留接口）。

B. 业务闭环 9.5（+0.5）

  • ✅ 红黑榜 + 满意度下钻（P2-B4-01）：db_board.py 红榜（满意工单/高效网格员/完成提案）vs 黑榜（不满意/SLA 超时/低效网格员），GET /agent/board + /agent/satisfaction-drilldown 下钻到单工单。
  • ✅ AI 自转率量化（P3-B5-01）：get_self_resolution_stats 按 agent_logs+handoffs 聚合，真实库实测 62%（AI 58 / 转人工 26）；大屏「AI 自转率」卡。
  • ✅ 报修（重复合并/跨部门仲裁/超时升级/满意度闭环）+ 舆情（分级/一键转工单/简报）。

C. Agent 能力 8.5（+1.0）
