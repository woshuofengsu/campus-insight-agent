# 竞品对标升级方案（V4，借鉴 + 反借鉴）

> **对标对象**：`AI-Customer-Service-Companion`（智能客服陪练系统 · 银行客服培训，React19+AntD6+FastAPI+SQLAlchemy+MySQL+**ChromaDB**）
> **对标日期**：2026-08 · **我方基线**：514 passed / schema v42 / ruff 0 / 16 路由模块
> **方案原则**：只借「技术短板」与「工程亮点」，**不借平台依赖与降级设计**（见第四章）
> **可证伪**：每项含现状证据、验收命令、回退开关；无证据的条目不入方案

---

## 一、基线校准：我们已有 vs 对手已有（防重复建设）

先纠正一个常见误判——**我们不是「没有 RAG」**，而是「有词法 RAG，缺语义向量」：

| 能力 | 我方现状（已核实） | 对手 | 差距判定 |
|---|---|---|---|
| 检索 | `agent/rag.py`：n-gram TF-IDF 稀疏向量 + 余弦 + `kb_embeddings` SQLite 缓存 + LIKE 降级 | ChromaDB 语义向量 | ⚠️ **词法 vs 语义**（同义词召回弱） |
| RAG 生成 | `agent/policy_rag.py`（`POLICY_LLM_RAG` 开关，弱命中才生成） | 有 | 平 |
| 多智能体 | 9 角色 + 黑板消息队列 + 真协商 + `llm_negotiator.py` | 5 agents（偏 pipeline） | ✅ 我们强 |
| 双层防线 | `verifier.py`（防幻觉/引用强制）+ `arbiter.py`（仲裁留痕） | 无 | ✅ 我们强 |
| 测试 | **514 passed** | **0**（无 tests/ 无 pytest） | ✅ 压倒性 |
| CI / 容器 | ci.yml（pytest+ruff+eval+build+smoke）/ Dockerfile / nginx / compose | 无 | ✅ 压倒性 |
| 鉴权 | JWT 中间件全覆盖 + secure-by-default（无密钥拒启） | **自认后台零鉴权** | ✅ 压倒性 |
| 敏感数据 | 全表手机号 AES-256-GCM（376 条已迁移）+ PIPL 注销级联 | 占位密钥 + CORS `*` | ✅ 压倒性 |
| 知识图谱 | 无 | 有 | ❌ 对手有 |
| 领域语料 | 演示 seed 数据 | 《银行客服 RAG 语料 100 问》 | ❌ 对手强 |
| 分层结构 | `data/db_*.py` 部分 800–1240 行 | agents/services/api/models/core 标准分层 | ⚠️ 对手规范（我们已决策 D12 答辩后动） |
| 人格化演练 | `tone.py` 情绪识别 + 安抚（**无演练闭环**） | 客户人格 + 烦躁值 + 错题变种 + 能力画像 | ⚠️ 对手有培训闭环 |

**结论**：真正的缺口只有 **3 个**——语义向量检索、领域真实语料、知识图谱；其余是「对手没有的」或「我们已决策不动的」。

## 二、借鉴升级清单

### U1 混合语义检索（P0 · 3 天）——补齐唯一技术短板

- **借鉴来源**：对手 ChromaDB 语义向量召回。
- **现状证据**：`agent/rag.py:239 rag_search()` 仅字符 n-gram TF-IDF；同义查询（「医保报销」vs「医疗费用结算」）召回弱。
- **方案**：
  1. 新增 `utils/embedding.py`：Provider 抽象（`bailian` 百炼 text-embedding-v3 / `zhipu` / `none`），统一 `embed(texts) -> list[list[float]]`。
  2. `agent/rag.py` 新增 `search_hybrid()`：**Dense（语义）+ Sparse（现有词法）双路召回 → RRF(k=60) 融合**；`get_rag_context()` 切到 hybrid。
  3. 向量缓存复用/扩展 `kb_embeddings`（加 `dim`、`vector BLOB` 列）；仅知识库变更时重建。
  4. **回退开关** `EMBEDDING_PROVIDER`（默认 `none` → 行为与今日完全一致，零风险）。
- **验收**：
  - `tests/test_rag_hybrid.py`：20 条同义 query golden，有 provider 时 top3 命中率 ≥ 80%；`none` 时纯词法不报错且 ≥ 60%。
  - `scripts/rag_eval.py` 输出命中率报告并接入 CI（与 `llm_eval.py` 同模式）。
  - 现有 514 测试全绿；`ruff check .` = 0。
- **风险/回退**：无 key 或 API 失败 → 自动降级词法（已设计）；预算：20 条查询嵌入成本 < ¥0.01。

### U2 真实政策语料库（P0 · 3 天）——从「演示数据」到「可溯源语料」

- **借鉴来源**：对手《银行客服 RAG 知识库语料 100 问》+ 5 个真实业务工作流。
- **现状证据**：`data/seed.py` 知识库为演示条目，答辩易被问「数据哪来的」。
- **方案**：
  1. 收录 **30–50 条公开发布的北京/海淀政策原文**（老旧小区综合整治、既有多层住宅增设电梯、城乡居民医保报销、养老服务补贴、接诉即办条例、垃圾分类等）。
  2. 落地为 `data/kb_corpus/*.jsonl`：`{title, category, source_url, publish_date, effective_date, expire_date, body, keywords}`。
  3. `scripts/import_kb_corpus.py`：幂等导入（按 `title+source_url` 去重），可 `--dry-run`。
  4. 前端政策详情展示**来源与生效期**（RAG 引用可溯源）。
- **合规红线**：只收录**公开发布**的政策文本 + 标注来源 URL；**不收录**个人信息、内部文件、未公开材料。
- **验收**：导入后 `SELECT COUNT(*) FROM knowledge >= 30`；`rag_eval.py` 覆盖 ≥10 条真实政策 query；引用展示含来源。
- **风险/回退**：语料整理耗时 → 先做 15 条高价值（医保/加梯/养老/物业）保底。

### U3 知识库健康度可观测（P0 · 1.5 天）——把 RAG 变成「可量化」

- **借鉴来源**：对手管理后台数据大屏（多指标 Tab）。
- **现状证据**：`agent_logs.routed` 已带 rag 标记，但无聚合指标。
- **方案**：
  1. `data/db_kb_metrics.py`：`get_kb_health(days)` → 命中率、零命中问题 top10、平均召回条数、引用率。
  2. 端点 `GET /api/web/agent/kb-health`（grid 专属，复用 `_require_role`）。
  3. `web/src/views/Screen.vue` 加「知识库健康度」卡（与现有「AI 自转率」并列）。
- **验收**：`tests/test_kb_metrics.py`（造数断言各口径 + 权限）；大屏可见；`npm run build` 通过。
- **价值**：把「我们有 RAG」升级为「我们的 RAG 命中率 X%、零命中问题清单如下」——**可证伪的技术叙事**。

### U4 情绪关怀量化（P1 · 1.5 天）——对标「人格化演练」的低成本替代

- **借鉴来源**：对手客户人格 + 烦躁值机制（用于培训）。
- **现状证据**：`agent/tone.py` 已有 `detect_emotion`/`care_line`，`_finish` 有安抚与 `empathized` 去重，但**无量化**。
- **方案**：复用 `agent_logs` 留痕聚合——情绪识别次数、安抚后转人工率、情绪→闭环率；端点 `GET /api/web/agent/care-metrics` + 大屏卡。
- **明确不做**：不新建「网格员演练/陪练」模块（工作量大、偏离基层治理主线、易被质疑「培训系统不是治理」）。
- **验收**：测试 + 大屏可见。

### U5 一键演示与自检（P1 · 1 天）——对齐对手 `start_prod.sh` 的演示工程

- **借鉴来源**：对手 `start_dev.bat`/`start_prod.sh` + 部署说明书。
- **现状证据**：已有 `deploy.sh`/Dockerfile/nginx，但缺「答辩前 10 分钟自检」。
- **方案**：
  1. `scripts/demo_preflight.py`：串行检查 ①514 测试全绿 ②`ruff check .`=0 ③`web/dist` 产物存在且新于源码 ④DB schema 版本匹配 ⑤`.env` 关键项（有无 key 走哪套姿态）⑥8000 端口占用 ⑦三个演示账号可登录；**任一失败给明确修复指令**。
  2. `scripts/demo_start.ps1`：起 uvicorn + 打开浏览器 + 打印演示账号。
  3. 更新 `docs/review/演示保障清单.md`。
- **验收**：preflight 在干净环境 0 退出；故意改坏一项能报错定位。

### U6 轻量知识图谱（P2 · 4 天，视时间）——只做「能查」的图谱

- **借鉴来源**：对手知识图谱。
- **方案（仅当 U1–U3 完成且时间充裕）**：SQLite 三表 `kg_entity`/`kg_relation`/`kg_mention`，不做可视化花架子；落地 2 个**真实查询**：①「3 号楼电梯」→ 关联历史工单/维保/同楼栋诉求 ②政策 → 适用人群/办理事项 → 关联社区事项。
- **验收**：实体抽取单测 + 关联查询端点 + 至少 1 个前端消费点。
- **止损**：若只能做「图漂亮但查不出东西」，**直接砍掉**（答辩被问「图谱解决了什么」会扣分）。

### U7 数据层分层演进（P2 · 0.5 天文档 + 答辩后实施）

- **借鉴来源**：对手 `agents/services/api/models/core` 标准分层。
- **现状证据**：`AGENTS.md` 已记录 D12——`data/db_policy/proposal/elderly_care/health_content/weather/notice` 各 800–1240 行，**比赛期不做大重构**。
- **本案动作**：仅在 `docs/scaling.md` 写清演进路径（read/write 拆分 + `data/_*_logic.py` 纯计算抽离 + 单测），**比赛期零代码改动**。

## 四、明确不借鉴（反模式清单）

| 不借 | 理由（可证伪） |
|---|---|
| **Coze/扣子平台依赖**（对手用 coze_client/coze_workflow_client） | 我们已自研编排（`orchestrator.py` + 黑板 + 真协商）；引入平台=架构倒退 + 单点依赖 + 演示受网络/额度制约 |
| **MySQL 迁移** | SQLite 已优化（WAL + `busy_timeout=5000` + `synchronous=NORMAL` + v40 索引）；演示场景 MySQL 零收益，只增加部署失败面 |
| **零鉴权/占位密钥**（对手 `SECURITY-TODO.md` 自认） | 我们已 JWT 全覆盖 + secure-by-default + 全表加密 + 登录限流；这是对手最致命短板，反向即我们的加分项 |
| **React 重写前端** | Vue3+NaiveUI 三端已成型（`web/`），重写=纯风险无收益 |
| **「先跑通再补测试」** | 对手 0 测试 / 1 commit；我们 514 测试是**答辩主武器**，不可回退 |
| **纯展示型知识图谱** | 无查询价值的图谱在答辩会被追问「解决什么问题」；U6 已设止损条件 |
| **向量库重型依赖（ChromaDB/Milvus）** | 我们零依赖哲学是特色；U1 用 API embedding + SQLite 缓存即可达到同等召回，且无装包/部署风险 |

## 七、答辩叙事升级（把新能力翻译成加分话术）

1. **「会查、不会编、越界能拦」三件套**：混合检索（查得准）→ Verifier 引用强制（不编）→ Arbiter 仲裁（越界拦）。**对手只有「查」，我们有「查+验+拦」全链**。
2. **降级即设计**：无 embedding key 自动回落词法检索、无 LLM key 回落规则引擎——「不依赖单一外部服务」是工程成熟度，不是缺陷。
3. **知识库可溯源**：30+ 条北京/海淀真实政策原文 + 来源 URL + 生效期展示；「我们的知识不是编的」。
4. **RAG 可量化**：命中率 X%、零命中问题 top10 清单、引用率——**可证伪的技术指标**（对手无任何量化）。
5. **人文赋能不只靠 LLM**：情绪识别 → 共情话术 → 安抚成功率量化；关怀内核（`tone.py`）是规则优先的零成本温度。
6. **工程质量即战力**：514 测试 / ruff 0 / CI 五步 / 演示前自检——**「我们敢让评委现场跑测试」**（对手 0 测试不敢）。

## 八、一句话总结

对手给我们的最大启示不是「上向量库」，而是**「把 AI 能力做实、可量化、可溯源」**；我们要借的是这份「技术可信度」，同时守住他们缺失的**工程纪律与安全底线**——补完 U1–U3 后，我们将同时拥有「真语义 RAG + 真防线 + 真测试 + 真合规」，形成无法被技术先进性单点击穿的综合优势。
