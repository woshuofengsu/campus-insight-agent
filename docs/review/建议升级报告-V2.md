# 《社区治理多智能体平台》建议升级报告（V2，对应 V2 检测报告 7.62/B+）

## 一、P1 级问题详细方案（3 项 + 2 项能力项）

### P1-F2-01 api_web 单体重构（路由拆分）
- **证据**：api_web.py 2400+ 行，路由/校验/导出/上传/Agent 端点全在一文件；V1 已列 P2-04，本轮只完成服务层抽取。
- **影响**：改动互相干扰、测试成本随功能增长不可控；答辩「工程质量」项会被追问。
- **方案**：按 `api_router/` 包拆分——`auth.py`(登录/改密/me/注销) / `issues.py` / `proposals.py` / `notices.py` / `weather.py` / `health.py` / `policy.py` / `elderly.py` / `agent.py` / `export.py` / `system.py`；每文件 <300 行；`main.py` 仅 app 装配 + include_router。用现有 401 测试做回归护栏，每拆一模块跑一次全量。
- **验证**：api_web.py 减至 <200 行；401 测试全绿；冒烟通过。
- **工作量**：大（1 月+）。**依赖**：无。

### P1-A5-02 黑板草稿落库
- **证据**：`orchestrator._state_key` 落库 v31，但 `work_order_draft/proposal_draft` 键存黑板内存；重启后 `_resume_target` 恢复 step 但 draft=None（补空 dict 兜底），草稿内容丢失。
- **影响**：用户填写一半的报修/提案重启即丢，与「崩溃/超时保留草稿」spec 冲突。
- **方案**：草稿并入会话落库——`save_session` 时把 `user:{uid}:{draft}` 键合并进 state_json；`run()` 恢复时从 state 回填 draft 键。
- **验证**：重启后追问流程的已填字段完整恢复；新增测试覆盖。
- **工作量**：中。**依赖**：无。

### P1-G1-02 存量加密迁移 + HTTPS
- **证据**：Crypto 工具就绪（v3.0），但存量库 phone 等仍明文；无生产证书。
- **方案**：写一次性迁移脚本 `scripts/migrate_encrypt.py`（读存量 phone → Crypto 加密写回密文字段，`phone_enc` 新列）；读写层封装 `mask/decrypt`；Nginx + Let's Encrypt 部署文档 + Dockerfile 挂证书说明。
- **验证**：迁移后 SELECT phone 无明文；导出/展示仍脱敏。
- **工作量**：中。**依赖**：P1-F2-01 可选。

### P1-C1-01 NLU 增强（方言/指代/否定）
- **方案**：在 `agent/web_agent.py` 加轻量规则：①指代消解（「那个/上次的」→ 取会话最近实体，黑板 user_context 存最近实体）；②否定处理（「不是A是B」→ 拆分重识别）；③方言词表（北京/上海常用口语映射）。接 LLM 后由 prompt 承担，规则为离线兜底。
- **验证**：新增 5 条语义测试（test_semantics 扩展）。
- **工作量**：大。**依赖**：无。

### P1-D3-01 LLM 评测集与自优化
- **方案**：建 `tests/llm_eval/` 20 条 golden（政策/报修/健康/注入/引用），OfflineAgent 与 LLM 双跑对比；bad case 从 agent_logs（status=拦截/转人工）抽取 → 人工标注 → 回归。
- **验证**：CI 中跑评测集；幻觉率 <5%。
- **工作量**：中。**依赖**：P1-C1-01 可选。

## 二、P2 级方案（摘要）
- **P2-A2-02 真协商**：可选升级——给 1-2 个场景（天气联动健康）接 LLM 自主协商（prompt 驱动 Agent 互发消息），其余保持声明式；工作量中。
- **P2-I3-01 多租户**：`community_id` 列级隔离（从 community 字段演进）+ 租户配置表；大规模改造，列入产品化阶段。
- **P2-B1-02 舆情外部源**：`auto_ingest` 接 12345 CSV 导入（先做文件导入，API 申请后接）——先落地「文件导入」即可演示。
- **P2-F4-01 链路追踪**：FastAPI middleware 生成 request_id，注入 agent_logs/activity_log；日志 JSON 化。
- **P2-E2-01 批量操作**：工单列表加批量派单/批量关闭（checkbox + 批量端点）。
- **P2-B4-01 红黑榜/下钻**：满意度按工单聚合 + 下钻明细；部门排名看板。
- **P2-H1-02 分级模型**：简单意图走规则，复杂走小模型，仅政策/协商走大模型（接 key 后）。

## 三、P3 级（长期）
- 自转率统计（调度器任务成功率看板）、录屏/演示脚本、商业模式（政府购买/SaaS 定价）。

## 四、四阶段路线图
1. **紧急冲刺（1 周）**：无 P0；补演示录屏 + 异常路径脚本；草稿落库（P1-A5-02，小改动高价值）。
2. **能力加固（1-2 月）**：api_web 拆分（P1-F2-01）+ 存量加密 + NLU 增强 + 评测集；真实数据试点。
3. **产品化（3-6 月）**：多租户 + 批量操作 + 链路追踪 + 舆情文件导入 + 红黑榜。
4. **规模化（6 月+）**：真协商升级 + 外部 API + 商业验证 + 数据飞轮。
