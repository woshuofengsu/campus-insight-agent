# 《社区治理多智能体平台》建议升级报告（V3，对应 V3 检测报告 8.25/A-）

> 与《项目质量检测报告-V3》配套。V2 提出的 15 项问题中 13 项已解决或降级；
> 本报告聚焦 V3 剩余 8 项（含 2 项新发现）的落地方案，按答辩价值排序。

## 一、P1 级（2 项：1 新发现 + 1 能力延续）

### P1-D3-02 LLM 实测缺位（新发现，D 维度）
- **证据**：评测集 20 条规则引擎满分，但 .env 未配真实 DEEPSEEK key——LLM 幻觉防线（Verifier 引用强制/输出检测/审计）无真实对抗样本；答辩若被问「LLM 到底跑过没有」缺乏实证。
- **方案**：接 key 后 `scripts/llm_eval.py` 双跑（OfflineAgent vs LLM）——脚本已按 provider 可扩展，仅需加 LLM 实现；bad case（LLM 答错/引用缺失）从 agent_logs 抽取 → 人工标注 → 回流 golden 或补 Verifier 规则。
- **验证**：评测集 LLM 通过率 ≥ 80%；幻觉率（无引用/编造）< 5%。
- **工作量**：中。**依赖**：真实 key + 评测集已有。

### P2-G1-03 工单快照 phone 明文（新发现，G 维度）
- **证据**：v36 迁移覆盖 user_profile/emergency_contacts，但 `community_issues.reporter_phone / assignee_phone / agent_phone` 三列仍明文（真实库实测 13800138000）；展示层已脱敏，存量列未加密。
- **方案**：沿用 `scripts/migrate_phone_encryption.py` 模式——issues 表加 phone_enc 三列 + 迁移（明文置空/密文保留）+ `_issue_view` 解密读取 + rollback；与 v36 同脚本扩展（表名参数化）。
- **验证**：迁移后 SELECT issues.* 无明文；工单列表/详情/导出仍脱敏显示。
- **工作量**：中（复用模式，半日）。**依赖**：无。

## 二、P2 级（4 项）

- **P2-B1-02 舆情外部源**：先落地「文件导入」即可演示（CSV：12345 工单/媒体文章 → auto_ingest 解析入库 → 分级）；API 申请后接真实源。工作量：中。
- **P2-I3-01 多租户**：已决策产品化阶段——community_id 列级隔离 + 租户配置表；当前 community 字段按社区过滤满足演示。工作量：大。
- **P2-H1-02 分级模型路由**：接 LLM 后——简单意图（报修/天气/通知）走规则；复杂（政策引用/协商）走小模型；仅跨部门冲突走大模型。工作量：小。
- **P2-A4-01 热插拔/多实例**：黑板状态已落库（v31/v35），多 worker 可共享 DB 恢复；热插拔角色注册表 + 实例池。工作量：大，产品化阶段。
