## 三、本次核验发现并修掉的 2 个真问题

### 问题 1：`meta.js` 改了但前端没重建（dist 落后于源码）

- **怎么发现的**：`demo_preflight --fast` 第 3 项红字报错"源码比产物新：web\src\config\meta.js"。
- **后果**：登录页会显示旧数字，且 `ui_audit`/`mobile_audit` 测的是旧包（正是复审 F4 那类假结论的来源）。
- **修复**：`cd web && npm run build` → 复跑 preflight **9/9**、ui_audit **0 HIGH**、mobile_audit **全通过**。
- **说明**：这不是"新 BUG"，而是**门禁按设计生效**——它把"忘记构建"拦在了提交之前。

### 问题 2：LLM 成本口径出现两个不同数字

- **怎么发现的**：逐句核对材料时发现 README 与交付说明写「**20 次调用 ¥0.0053**」，而技术报告/问答手册/创意说明书/产品文档写「**30 次调用 ¥0.0069**」。
- **根因**：两个数字分别来自「一次评测批（20 题）」与「当时库内累计（30 次）」，**来源不同却并列使用**，
  且两个数都会随使用继续变化 → 评审若并排看，会认为材料自相矛盾。
- **修复**：
  1. 统一为**库内记账快照 + 稳定口径**：`llm_usage` 逐笔记账，本次快照 **57 次 / ¥0.0139**，
     并统一强调**单次均价 ¥0.0002**（不随调用次数漂移的那个数）；
  2. 新增 `scripts/llm_cost.py`（含 `--json`），让这个数字**任何人事后都能一条命令复核**，
     并在文档里指向它；
  3. 7 份材料（创意说明书/技术报告/交付说明/问答手册/五维自查/README/PRODUCT）全部同步，残留检查为 0。
