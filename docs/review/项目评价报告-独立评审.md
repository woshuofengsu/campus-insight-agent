## 1. 总体评价与评分

### 1.1 一段话定性

这是一个**工程纪律罕见地好、但业务真实性与适老可用性尚未被证明**的基层治理多智能体演示系统：它把"可验证性"做成了方法论（10 轮外部复审全部有回执、门禁脚本族可现场复算、迁移版本化、手机号真加密），在三端适老化和多智能体可解释编排上有真实设计投入；但它**没有一天真实街道运行、没有一条真实居民数据、没有一个真实老年用户测过**，核心卖点（语音助老、多智能体自主协商）在真机与真实场景下大概率打折，而"多智能体"实质是**声明式规则编排 + 黑板留痕**，LLM 自主协商默认关闭——按展示口径讲它是"可解释的多角色协作平台"完全站得住，但若按"LLM 自主协商的多智能体"讲，会被评委当场问穿。

**一句话：工程质量配得上 9 分，业务落地只值 5 分；差距不在代码，在"有没有人真的用过"。**

### 1.2 两个评分

| 维度 | 分数 | 说明 |
|---|---|---|
| **① 竞赛完成度（互联网+视角）** | **9.2 / 10** | 功能闭环完整、三端齐全、有可复算的质量证据链、有 10 轮外部复审闭环、有独特的"工程可验证性"叙事；扣分在**无真实场景验证**与**多智能体定性有被问穿风险** |
| **② 生产就绪度（真实落地视角）** | **5.5 / 10** | 工程规范远超学生水准（迁移/加密/审计/门禁），但作为**承担政务责任的系统**：密钥管理 fail-open、单进程内存态不可横向扩展、无租户隔离、无等保/密评/备案、无备份恢复演练、无试点数据、无成本人力测算 |

### 1.3 分差原因（拆开看就明白，不是矛盾）

| 子维度 | 竞赛视角 | 生产视角 | 差异来源 |
|---|---|---|---|
| 工程规范（迁移/测试/静态检查） | 9.5 | 8.5 | 生产还缺 SLO、告警、灰度 |
| 安全基线（加密/鉴权/响应头） | 8.5 | 6.5 | 密钥 fail-open、无等保/密评、HTTPS 未真实部署 |
| 可扩展性（横向、并发） | 7.0 | 4.0 | SQLite + 黑板/限流/WS 全在进程内，多 worker 直接不成立 |
| 合规（PIPL/数据分级） | 7.5 | 4.0 | 有加密与脱敏，无单独同意/分类分级/删除权全流程 |
| 业务验证（真实用户/成效） | 4.0 | 2.0 | 无试点、无真实数据、无前后对比 |
| 商业可持续性 | 5.0 | 1.5 | 只有潜在路径，无成本/人力/运营测算 |

> **为什么外部评审给"生产就绪 7.6–7.8"、我给 5.5**：他们量的是"**工程成熟度**"（这个我给 8.5），我量的是"**能不能承担政务责任上线**"（这个只能给 5 分）。两者不矛盾，但**不要把工程成熟度当生产就绪度去讲**——评委里只要有一个做过政务信息化的，这一条会被当场拆开。

## 2. 核心优势（只列 5 条，且每条都有证据）

### 2.1 "可复算的质量主张"——这是本项目最稀缺的资产

**为什么是真优势**：绝大多数学生项目对"质量好"只能给形容词；这个项目把质量变成了**可执行的数字**：`pytest` 586 项、`ui_audit` 全站 34 个路由页/54 个页面视口 × 9 类检查、`mobile_audit` 21 页真机口径、`demo_preflight` 9 项、`demo_acceptance` 11 项真实 HTTP E2E、手机号加密明文残留审计、RAG 金标评测、数字一致性门禁（`check_claims`）。
**证据**：这些脚本都真实存在且我刚实跑过（54 页 0 违规、21 页 0 违规、9/9、11/11、0 warnings）。更关键的是**门禁会咬自己人**——本轮我往文档里写了一句被禁的措辞，门禁立刻带行号报红。这种"门禁不是摆设"的证据，比任何 PPT 都有说服力。

### 2.2 数据安全的"最后一公里"做得比多数商用系统还认真

**为什么是真优势**：不只加密，而是**fail-closed**（`cryptography` 缺失时 `encrypt()` 直接抛错而不是明文落库）、密文带算法版本前缀（`g1$`）、旧算法保留解密兼容、有单独的重加密轮换脚本、有覆盖 8 张表的明文残留审计、留痕日志做手机号脱敏。
**证据**：`utils/crypto.py:96-102`（缺库即拒绝加密）+ `scripts/audit_phone_encryption.py`（8 表明文 0，我实跑过）。

### 2.3 适老化是"真做了工程"而不只是放大字号

**为什么是真优势**：粗触屏 ≥44px 热区、输入框 16px 防 iOS 聚焦放大、`100dvh` 带 `100vh` 回退、安全区、底栏遮挡用 `elementFromPoint` 真测、适老字号 ≤20px 下限被审计卡住、横屏专用引导层、reduced-motion 全站可关。
**证据**：`mobile_audit` 21 页 0 违规（含 320/390/844 与横竖屏），且审计在**种了真实演示数据之后**还抓到过 6 处真问题（暗色对比度等），说明审计有效而非空跑。

### 2.4 迁移与"禁止运行时裸 ALTER"的纪律

**为什么是真优势**：46 个版本化迁移、50 张表、全新建库与存量升级走同一条路径、历史遗留的运行时补列被收回迁移链、迁移函数幂等。这是"以后能演进"的硬前提，学生项目里极少见。

### 2.5 外部复审闭环（10 轮报告 + 逐轮处理回执）

**为什么是真优势**：`docs/review/` 里有 10 轮外部评审报告与**逐条处理回执**，包含"未修复项与理由"。这证明了**接受批评并落到代码**的能力——答辩时这是"我们如何迭代"的最强素材，远比"我们功能很多"更能打动评委。

### P3（打磨级，但评委可能顺手一问）

## 4. 十个维度逐项诊断

### ① 技术架构合理性

**【现状】** 分层清晰：`api_web.py`（装配/中间件/安全头/WS/SPA）→ `api_routes/`（14 个业务路由）→ `agent/`（9 角色 + 黑板 + 编排 + 双层防线）→ `data/`（按域拆分的纯 sqlite3 访问层）→ `web/`（Vue3 三端）。上有 46 版迁移与统一 schema 注册。

**【问题】**
- **三入口冗余**：FastAPI 主线 + Streamlit 备线 + 扣子插件。对一个比赛项目，备线与插件带来的疑问（"到底哪个是真的"）大于价值。
- **`data/db_policy.py` 等文件单文件 800–1240 行**（材料自认 D12），是下一个 `api_web.py` 式的大文件债。
- **多智能体是否过度设计**：9 角色里通知/天气偏薄；但黑板协议+优先级队列+留痕**不是**过度设计——它是这个项目唯一不可替代的叙事资产。**真正过度的是"广度"**：知识图谱、舆情源框架、多租户预留、三条后端入口，都属于"加了但没形成闭环"。
- **并发前提缺失**：全内存态没有显式声明。

**【建议】** ① 冻结新功能；② 把 Streamlit 与扣子插件在文档中降级为"历史/独立"，默认路径只留 FastAPI；③ `db_policy/proposal/...` 按 read/write 拆分（纯计算抽 `_*_logic.py` + 单测）；④ 启动守卫声明单进程前提。

### ② LLM 接入真实性与有效性

**【现状】** DeepSeek 用于意图识别/追问补全/政策回答生成/协商演示；**规则优先、LLM 兜底**；LLM 编排与协商**默认关闭**控成本；政策回答强制引用 + Verifier/Auditor 校验 + 答不准转人工；Prompt 注入五层防护；`db_llm_usage` 记账（20 次调用 ¥0.0053 量级）。

**【问题】**
- **"真 AI"证明不足**：默认关闭意味着**生产路径其实是规则**；若演示环境不开，评委看到的是 if-else。
- **缺"LLM 到底带来多少提升"的量化**：有 `llm_eval` 20 题满分，但缺"同题规则 vs LLM"对照。
- **混合策略本身是合理的**（基层政务要稳定、便宜、可解释），但**需要证据支撑**而不是理念支撑。
- 无分级模型路由（简单任务也走同一模型）。

**【建议】** ① 现场开 LLM 协商做**一条**端到端演示，并展示 `db_llm_usage` 的 token/费用；② 出一张"同题对照表"（规则命中 / LLM 兜底 / 最终输出质量与成本），把"哪里必须用 LLM（开放式诉求意图、政策生成、跨角色联动），哪里该留规则（状态机、权限、风控、脱敏）"讲成设计原则；③ 把 `route_grade()` 的命中率与成本画到大屏上。

### ③ 数据安全与合规

**【现状】** 手机号真 AES-256-GCM（fail-closed）、版本前缀、8 表明文 0、脱敏与留痕规则；JWT secure-by-default；最小公开路径；两级角色权限；安全响应头（CSP/HSTS/X-Frame/nosniff）；traceId 全链路；SQL 标识符白名单 + 值参数化；上传 5MB 双校验。

**【问题】**（按严重度）
1. **`CRYPTO_KEY` fail-open + `.env.example` 未列密钥**（P1-1）→ 最要命且最容易修。
2. **密钥派生弱**（无 KDF/盐）、**无信封加密**（单密钥泄露 = 全量泄露）。
3. **演示姿态默认开**（`DEMO_MODE`/`DEMO_AUTO_WORKER` 默认 true）→ 忘关即带免密登录 + 机器人自动推进工单上线。
4. **PIPL 全流程缺口**：有加密与脱敏，但**单独同意、数据分类分级、最小必要留痕、删除权/撤回权的端到端验证**未见证据（材料未给）。
5. **HTTPS 未真实部署**（仅文档 + 临时隧道）。
6. **自由文本里的 PII 无治理**：居民在工单/提案正文里手写他人手机号、身份证号时，加密列不覆盖——这条评委一问就中。

**【建议】** ① 密钥 fail-closed + 补 `.env.example` + 加 preflight 检查（**今天就能做**）；② HKDF/Argon2 派生 + 轮换演练；③ 生产姿态断言：`DEMO_MODE=false` 时禁止免密演示账号与 auto worker，并加测试；④ 写一页《PIPL 对照表》：告知/同意/最小必要/删除/撤回 逐项"已做/未做/怎么验"；⑤ 自由文本 PII 加"正则 + 提示 + 入库前脱敏"（至少覆盖手机号/身份证）。

### ④ 多智能体协作真实性

**【现状】** 黑板（锁/版本/历史 500 上限）、消息协议（task_request/task_response/notify/error/handoff）、事件 + 定时触发、优先级队列；真实联动两条（天气⇄健康、报修→通知升级）；Verifier→Arbiter 双层防线 + 人工兜底 + 留痕；转人工生成"人工处理包"。

**【问题】**
- **本质是"声明式/规则编排的协作"，不是自主协商**——材料自己说了，我同意。这不丢人，**含糊其辞才丢人**。
- **Arbiter 是否有"真改变结果"的实例**：材料未提供 【待补充：一条 Arbiter 拦截并改写输出的 `agent_logs` 记录】。若拿不出，评委有理由怀疑它是摆设。
- **黑板数据竞争只在单进程成立**：多 worker = 多黑板；"带锁"是进程内锁，跨进程无效。
- **Verifier 在规则链路上接近空转**（规则输出天然来自库、无幻觉）——别把它说成"防幻觉"，要说"**LLM 链路强制防线 + 全输出统一挂链**"。

**【建议】** ① 答辩定性改口径（见 P1-2）；② 补一条"协商改变结果"的端到端测试断言 + 现场日志对比；③ 在 `docs/scaling.md` 写明多进程下黑板/限流的替换方案；④ 明确 Verifier 的**双重职责**：LLM 链路的幻觉防线 + 全链路的合规挂链点。

### ⑤ 适老化与用户体验

**【现状】** 老年端大字高对比、语音、长按 SOS、用药提醒、最近联系人、防呆、横屏引导；真机口径适配（16px 防放大、dvh、安全区、底栏遮挡检测）；21 页移动审计 0 问题；54 页视觉审计 0 违规 0 控制台报错。

**【问题】**
- **审计是"数值达标"，不是"老人可用"**：字号/热区/对比度达标 ≠ 老人能找到按钮。**没有一位真实老年用户测过** 【待补充：≥5 位 60+ 用户的可用性测试】。
- **语音可用性依赖浏览器**（见 P1-4），无方言/噪音/语速鲁棒性验证。
- 老年端"功能数量"其实偏多（8 页），对老人是认知负担；适老的第一原则是**少**。

**【建议】** ① 做一次 5 人可用性测试（任务：报修、看通知、找联系人），记录完成率/求助次数/耗时，这比再多审计都值钱；② 语音补降级通道或换云 ASR；③ 老年端考虑把 8 页收敛到 5 页（首页/SOS/报修/用药/听通知），其余从属。

### ⑥ 产品价值与场景匹配

**【现状】** 报修状态机、提案公示投票执行反馈、通知分级、政策知识库版本+审核分离、健康咨询与急症转 120、天气联动、网格工作台/红黑榜/满意度下钻；均为演示数据。

**【问题】**
- **痛点选得对**（接诉即办、适老、政策问答是真实痛点），但**价值主张未验证**。
- **为展示而做的部分**：知识图谱（能反查，但不改变任何业务决策）、大屏（好看，非一线必需）、舆情源框架（未对接）。
- **离商用距离**：至少还有"真实流程对接（12345/街道系统）、多租户、等保/密评、运维、数据迁移、培训"六道门。

**【建议】** ① 明确"最小可用闭环"= 报修 + 通知 + 政策问答 + 适老 SOS，其余为增强；② 若做试点，优先验证"一次派单成功率"和"重复投诉率"这两个网格员真正关心的指标；③ 把知识图谱的使用场景收缩成一句话（"按实体反查历史处置，辅助派单"），别当卖点讲。

### ⑦ 工程完整度与可维护性

**【现状】** 测试 586 项、ruff 0、门禁脚本族、10 轮复审回执、文档齐全；`api_web.py` 已从 2000+ 行拆出 14 个路由模块。

**【问题】**
- 测试金字塔偏倒（单元多、集成/e2e 少）。
- 大文件债转移到了 `data/`（800–1240 行/文件）。
- **bus factor = 1**：单人项目，虽文档好，但缺"新人 30 分钟跑起来"的一页速览与一键脚本索引（部分已有：`demo_preflight`/`serve_public`）。
- 门禁脚本越加越多，有"工具比产品花哨"的风险——**但这在本项目里是战略选择**（可复算性是核心卖点），不算过度设计，只是要控制增速。

**【建议】** ① 补集成/E2E 层；② 拆 `data/` 大文件；③ 写《新人上手 30 分钟》；④ **冻结门禁数量**，把精力转向真实用户验证。

### ⑧ 竞赛竞争力

**【现状】** 功能闭环 + 三端 + 多智能体 + 适老 + 可复算门禁 + 10 轮复审闭环；单人完成。

**【判断】** 能走多远：**省赛/校赛稳，国赛有机会但取决于叙事与真机演示**。三个决定性变量：① 多智能体定性是否诚实且能现场证明；② 是否有一次真实使用（哪怕很小）；③ 真机上老年端语音与三端流程是否顺畅。

**评委最可能质疑的三件事**：多智能体是不是花架子、ORAG 100% 是不是自证、没有真实数据凭什么说有用。
**最该展示的三件事**：门禁当场复算（`pytest`/`ui_audit`/`check_claims` 现场跑）、一条真实协商+仲裁改写结果的留痕、真机扫码走完居民报修→网格派单→老年听到通知。

### ⑨ 商业可持续性

**【现状】** 潜在路径：政府购买服务、街道 SaaS、运维订阅；**无成本/人力/运营测算**。

**【问题】** 政务采购要求：等保二级+（多数地区）、密评、数据不出域/信创适配、供应商资质、驻场运维能力。**单人学生团队不具备投标资格**——这是硬约束，不是努力能解决的。

**【建议】** ① 别在比赛里讲"要卖给政府"，讲"**可作为高校/园区后勤、社区物业、街道试点的技术底座**"；② 做一页粗算：单街道（假设 5000 户）→ 存储/带宽/LLM 成本/运维人力（【待补充：目标定价】）；③ 明确"我方定位 = 技术方案提供方，不是运营方"。

### ⑩ 答辩准备

**【现状】** 有 5 问答辩库（第九轮报告新增面）+ 录屏素材 6 段。

**【问题】** 题库偏"技术解释"，缺"价值质疑"与"伦理/合规追问"；缺"翻车兜底话术"。

**【建议】** ① 用第 6 节的 20 问当压力测试，逐条练；② 准备**三条底线话术**：默认关闭的能力必须主动说、未对接的必须主动说、没试点的必须主动说；③ 每个"没有"都要配一个"为什么这样取舍 + 什么时候会有"。

## 7. 最终结论与行动主张

**值不值得继续做：值得，但必须换挡。**

方向是对的：接诉即办 + 适老 + 政策问答是真实痛点，且这个项目的工程底子（加密、迁移、门禁、复审闭环）在学生项目里属于前 5%，继续投入不会浪费。**真正的问题不是代码，而是"从未被人真正使用过"**——这会让所有优势停留在自证层面。

**明确的行动主张（不要和稀泥）：**

1. **立即冻结功能开发。** 现在每加一个功能，都是在给"没有验证"的仓库上加重量。答辩前只做 P1-1（密钥 fail-closed）、答辩口径改写、真机三环境测试、演示脚本彩排。
2. **两周内必须有一次真实使用，哪怕极小。** 一个社区、一个学校后勤、一支物业队伍，30 单就够。产出的"平均受理时长 / 一次派单成功率 / 回访满意度"三个前后对比，价值超过再写 5000 行代码。做不到，就在所有材料首页写清"成效未验证"——**诚实本身就是差异化**。
3. **生产化只做三件事，其余全部延后**：① 密钥体系 fail-closed + KDF（安全底线）；② 单进程前提显式声明 + 扩容清单（诚实边界）；③ 备份恢复演练（数据底线）。Redis/PG/等保/信创都属于"有客户之后"的事。
4. **答辩叙事从"我们做了多少"改为"我们证明了什么"**：能现场复算的门禁、能被追问的三层防线、能诚实说出的四条边界（无试点 / 无多租户 / 无离线 / 无信创）。**一个敢于在台上说"这四条我们没做，理由与时间表如下"的团队，比一个声称全都做了的团队可信十倍。**
5. **别做"通用政务平台"的梦。** 你的现实定位是"可在高校/园区/社区物业落地试点的基层治理技术底座"，商业模式讲"技术方案提供方"，不讲"政府供应商"——后者需要资质，不是努力问题。

**最后一句**：这个项目最打动人的地方不是 9 个 Agent，而是**它把自己放在了可以被验证的位置上**——在普遍靠 PPT 说话的学生竞赛里，这是真正的差异化。别用没验证过的野心，把这个优势稀释掉。
