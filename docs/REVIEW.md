# 项目评审记录（四轮锐评存档）

> 社区先知 CommunityInsight Agent — 多视角锐评存档（2026-08-14）。
> 视角：AICG 大师（技术/架构）· 居民（体验）· 网格员（效率与权责）。

## 第一轮锐评（换皮完成后，2026-08-13）

### 大师视角
1. **AI 含量约 40%**：prompt 509 行，一半是穷举触发词规则；"智能"实为规则驱动的工具调用器。
2. **迁移裸奔**：init_db 无版本号、try/except 吞异常，中间态无法诊断。
3. **死代码**：db_core.resolve_author 无调用者；data/models.py 整模块死代码；测试 _login_user_profile 死 fixture；test_teacher.db / streamlit_errors.log 垃圾文件。
4. **测试膨胀**：test_ablation 返回 dict 冒充单测；大量"不崩"断言而非"正确"断言。
5. **安全**：切换账号一键越权；API 无鉴权；ngrok 公网裸奔。
6. **中间层冗余**：database.py 99 行纯 re-export。

### 居民视角
1. 39 条工单全是 seed，闭环是假的（没人处理）。
2. 匿名上报后自己找不到自己的工单。
3. 切换账号让双角色隔离现场崩塌。
4. 游戏化激励（钻石/黄金守卫者）不适合老人。
5. 注册字段语义错位（楼栋存进 school）。

### 网格员视角
1. "我的待办"按姓名匹配 assignee，同名串单。
2. 主动派单 = 派了个寂寞（无通知）。
3. SLA 预警只展示不升级。
4. 满意度被居民单方面拿捏。
5. issues_mgmt 是 session_state 地狱。
6. 邮件发送静默失败。

## 第二轮锐评（优化 + 老年关怀版完成后，2026-08-14 上午）

### 大师视角（新雷）
1. **Streamlit Cloud 数据一次性**：文件系统临时，DB 重启即失——上云后"接诉即办/老年关怀"变空壳；这是演示与产品的本质差距。
2. **技术债形态变了**：从"没有迁移"变成"每加功能就加迁移补丁"（v1~v10 全是事后补丁）。
3. **依赖没锁版本**：requirements 全 `>=`，CI 是纸老虎。

### Agent 竞争力（重点）
1. **评测是自证**：15 个场景覆盖关键词表本身 → 100% 命中是拟合不是泛化；offline 不测 LLM 兜底。
2. **三层智能本质是规则**：路由=关键词+LLM 替补、校验=正则+DB 查重、规划=模板+LLM 步骤——AI 含量 40%→50%，无质变。

### 产品视角
1. **21 页面膨胀**：居民 9 + 网格员 6 + 老年 6，功能堆叠大于产品一致性；真实居民常用页面 ≤3 个。
2. **「办」字悬空**：真实上报后无人处理、SLA 超时无人负责；自动派单派给不存在的网格员。
3. **老年语音是半成品**：voice_input 识别结果在 iframe 内，不能自动回填输入框，对目标用户交互断裂。

### 后续若继续，只做三件事
1. 数据持久化决策（上云换 Postgres/Supabase，或诚实声明演示数据会重置）。
2. 评测去自证（加 10 个未见过的说法，跑 LLM 版评测拿真实泛化数字）。
3. 把"办"演完（模拟网格员自动处理，让闭环真的转）。

## 第三轮锐评（完整审查优化后，2026-08-14 下午）

### 大师视角（本轮新发现）
1. **CI 是半吊子**：`.github/workflows/test.yml` 名称还是"309 Tests"（过时）；pytest 路径**不含** `test_semantics.py` / `test_elderly.py` / `test_ablation.py` —— 新增的语义测试、老年测试、消融测试全不在 CI 保护内。CI 只跑"老测试"，新功能无回归防线。
2. **本地全量测试 = 花钱 + 外部依赖**：`tests/test_deepseek_compat.py` 的 2 个测试真实调用 DeepSeek API（OpenAI client.create）。「328 passed」里有真实 API 调用——clone 项目无 key / 断网，pytest 直接挂。宣称的"全绿"是脆弱且烧钱的。
3. **依赖不锁版本**：`requirements.txt` 全 `>=`，无 lockfile；CI 每次 pip 装最新版，LangChain/Streamlit 大版本一升就翻车。
4. **评测自证（复确认）**：15 场景 100% 命中 = 关键词表覆盖了自建场景；offline 不测 LLM 兜底，泛化能力未被证明。
5. **配置键双份**：`COMMUNITY_*` + `CAMPUS_*` fallback——兼容正确，但长期双份键名是负担，需设定旧键弃用点。
6. **dist/ 旧安装包残留**：`CampusInsight_校园先知_一键安装包.zip` 物理存在（名字已过时），gitignore 但磁盘在，外发会带旧版。

### 确认安全（本轮核查通过）
- Dockerfile + .dockerignore：`.env` / `*.db` / `dist/` 均排除，镜像不含密钥 ✅
- make_installer.py：排除 `.env` / `.db` / `.log` ✅
- git：`.env` / `*.db` 未跟踪；无密钥泄漏 ✅
- ui/cache.py 失效函数已含 cached_my_issues / cached_my_stats（旧 bug 已修）✅

### 居民视角
1. 「办」字悬空依旧：真实上报后无真人处理，SLA 无人负责（自动派单派给不存在的多部门网格员）。
2. 老年语音半成品：iframe 识别结果不能自动回填输入框，对张大爷交互断裂。
3. 21 页面膨胀：真实居民常用 ≤3 页。
4. 上云后数据一次性：线上上报/评价/打卡重启即失，居民看到的是"会重置的演示数据"。

### 网格员视角
1. 只有一个 demo_grid，多人协作（同名/多部门/派单分发）从未被真实数据验证。
2. SOS 广播给所有 grid——demo 单网格员无感，真实多网格员会轰炸。
3. assignee_id 有了，但"哪个部门该派谁"的映射从未被第二个网格员验证。

### Agent 竞争力（更深一层的判断）
1. 关键决策权仍在关键词表，LLM 只是 miss 时的替补；且替补层无评测覆盖。
2. planner 是"建议步骤注入提示词"，不是真正的 Plan-and-Execute 执行循环——LLM 可以不执行建议。
3. 事实校验只查 `#编号` 存在性，不校验数字正确性（"解决率 80%"这类数值不核对）。
4. workers.py 是"聚合既有规则"，不是真正的多 Agent 协作（无独立决策/通信）。
→ 结论：AI 含量从 40% → 50%，仍是**工程智能**，未发生质变。

### 若继续，只做三件事
1. 把 CI 补齐：pytest 路径纳入全部 test_*.py，锁依赖版本，mock 掉 test_deepseek_compat 的真实 API 调用。
2. 评测去自证：加 10 个关键词表外的新说法，有 key 时跑 LLM 版评测，拿真实泛化命中率（哪怕 70%）。
3. 数据持久化决策：上云换 Postgres/Supabase，或明说"演示数据会重置"。

## 第四轮锐评（Agent 内核 + 工程收尾 + UI 折腾后，2026-08-14 晚）

### 一、最该被骂的：这一轮在「看得见的改进」上栽了跟头
- 三轮 UI 折腾：①技术达标（字号/对比度/token）→ 用户「没看出来」；②加品牌色竖条 → 用户「好丑」；③用户选 B 方向（现代浅色）仍在调。
- **教训（也是项目的隐喻）**：技术指标（WCAG AA、design token）≠ 用户感受。项目一路在做「功能丰富、工程规范」，但真实用户要的是「好看、好用」——「达标」和「被感知」是两回事。这一课比任何功能都值钱。

### 二、Agent 内核：这轮真正的硬货（值得肯定）
- 决策权交还 LLM（语义路由 LLM 优先）、反思层 LLM 核查、角色工具裁剪、Plan-and-Execute 真循环、评测去自证（8 个关键词表外场景泛化 100%）。
- **泼冷水**：8 个泛化场景样本太小，100% 可能是小样本幸运；且 LLM 兜底层仍未被大规模评测覆盖。要拿去答辩，至少扩到 30+ 场景。

### 三、工程：扎实（看不见但重要）
- CI 修复（全量测试、无 key 也绿、38s）、依赖锁版、API 测试隔离、dist 清理、评测报告落盘。这些是「经得起抽查」的底子。

### 四、但「演示 vs 产品」的本质差距还在
- **数据一次性**：Streamlit Cloud 上云后 DB 重启即失，只是「声明了」，没解决。
- **闭环是演的**：演示机器人让工单自动办结，但真实运营没有真人网格员接单。
- **21 页面堆叠**：三角色 21 页，真实用户常用 ≤3 页。
- **多网格员是假的**：demo_grid2 有了，但仍是 seed 数据，真实运营的派单/协作从未被验证。

### 五、新隐患（本轮暴露）
- **自定义组件上云**：老年语音用了 `declare_component`（`ui/static/voice_input/`），Streamlit Cloud 打包时静态文件是否随行、是否可用，未验证——这是上云的新风险点。
- **UI 未定稿**：B 方向仍在调，说明设计语言还没定，比赛前要冻结。
- **评测样本小**：泛化 100% 是 8 个场景，需扩样本。

### 六、如果我是评委
- **技术分高**：Agent 内核（LLM 主决策 + 反思 + 评测）、工程（CI/迁移框架/日志/权限）、多角色（居民/网格员/老年）——这是头部作品的技术纵深。
- **但「演示感」太重**：数据是 seed 的、闭环是机器人演的、UI 还在改。评委现场把玩 5 分钟，会发现「看起来完整，摸起来是演示」。
- **一句话**：你的项目已经从「会翻车的演示」变成「经得起技术抽查的演示」；但离「真的治理产品」，还差「数据是真的、闭环是真人接的、UI 是定稿的」三件事。

### 若继续，只做三件事
1. **冻结 UI**：B 方向调 2 轮定稿，别再改——比赛前 UI 反复 = 评委眼中的「没想清楚」。
2. **扩评测**：泛化场景 8 → 30+，把 LLM 兜底层的真实命中率测出来，答辩才有底气。
3. **诚实答辩**：把「演示数据会重置」「闭环为演示流程」写进答辩稿，主动承认比被评委戳穿强。
